앞 절에서 에이전트를 “루프를 돌며 도구를 쓰는 실행 단위”로 보았다면, 그 중심에는 항상 **채팅 모델(chat model)** 이 있습니다. 이 절에서는 LangChain v1에서 표준화된 채팅 모델 인터페이스가 어떤 역할을 하는지, 그리고 왜 에이전트 설계의 출발점이 되는지를 살펴봅니다.

소프트웨어 관점에서 큰 변곡점은 세 가지로 널리 이야기됩니다: 인터넷, 스마트폰, 그리고 LLM.
인터넷이 세상을 연결하고, 스마트폰이 개인을 연결했다면, **LLM은 지능을 연결한 시대**를 열었습니다.  

채팅 모델은 이런 변화를 대표하는 기술입니다. 단순한 텍스트 생성기를 넘어, 사람의 언어를 이해하고 대화 속에서 판단하며, 필요한 경우 외부 도구나 데이터를 호출해 스스로 문제를 해결합니다.  
[[TIP("요점")]]
오늘날의 AI 에이전트가 “생각하고, 말하고, 실행”할 수 있는 이유가 바로 여기에 있습니다.
[[/TIP]]
LangChain은 이러한 채팅 모델을 표준화된 인터페이스로 다룰 수 있게 해 줍니다. 덕분에 우리는 복잡한 모델 구조나 공급자별 차이에 구애받지 않고, 가장 적합한 모델을 선택·교체하며 자신만의 에이전트를 만들 수 있습니다.
> ### LangChain v1 변화 요약
> - **공급자-무관 표준화**: 모델과 에이전트 모두 `공급자:모델명` 규칙 사용
>   - **모델**: `init_chat_model("openai:gpt-4o")`, `init_chat_model("anthropic:claude-3-5-sonnet-latest")`
>   - **에이전트**: `create_agent(model="anthropic:claude-sonnet-4-5", tools=[...])`
> - **공통 호출 인터페이스**: `invoke` / `stream` / `batch`로 통일 (반환형 표준화: `AIMessage`, `AIMessageChunk`)
> - **ENV 키는 그대로**: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY` 등 기존 공급자 키 사용
> - **옵션 추가**: 필요 시 `LC_OUTPUT_VERSION=v1`로 **표준 콘텐츠 블록**을 `content`에 직렬화 (멀티모달 직렬화 스위치, 옵트인)

## 채팅 모델이 뭐야?
채팅 모델은
 **메시지들의 리스트를 입력받아 단일 `AIMessage`를 출력**하는 표준 인터페이스입니다.  
문자열 인/아웃 LLM과 달리 **역할(role)·콘텐츠 블록(텍스트/이미지/오디오 등)·메타데이터**를 가진 메시지 단위를 사용하고, `invoke` / `stream` / `batch`에 더해 `bind_tools`(툴 호출), `with_structured_output`(구조화 출력) 등을 **지원 모델에서** 공통적으로 제공합니다.

### 언제/왜 채팅 모델을 쓰나
- **대화 맥락 유지**: 다중 턴 기록을 표준 메시지로 주고받아 일관성을 유지합니다.
- **도구 호출·구조화 출력·멀티모달**: 모델에 도구를 “바인딩”하거나, JSON 등 스키마 준수 출력, 이미지/오디오 등 멀티모달 입력을 **지원 모델에서** 취급할 수 있습니다.

## 호출 메서드
작업 목적(단일 응답, 실시간 스트리밍, 병렬 처리)에 따라 적절한 메서드를 선택합니다.

- `invoke(messages_or_text)`: 한 번의 요청에 대해 **완성된 `AIMessage`**를 반환합니다.  
- `stream(...)` / `astream(...)`: **토큰 단위 `AIMessageChunk`**를 스트리밍합니다(각각 동기/비동기).  
- `batch([...])`: 여러 입력을 한 번에 묶어 처리하며 **`List[AIMessage]`**를 반환합니다.

```python
from langchain.chat_models import init_chat_model

model = init_chat_model("openai:gpt-4.0")

# 문자열 또는 메시지 리스트 모두 가능
resp = model.invoke("한 줄 요약으로 설명해줘")
print(resp.content)  # AIMessage의 본문 텍스트

# 스트리밍 출력 (동기)
for chunk in model.stream("스트리밍으로 보여줘"):
    print(chunk.content, end="")
```
>스트리밍은 실시간 로그나 UI 표시와 함께 사용할 때 특히 유용합니다.  
LangChain의 체인/그래프(LCEL/LangGraph)와 결합하면 **`astream_events()`**로 중간 단계(툴콜/토큰/상태 전환 등)까지 **이벤트 단위**로 받을 수 있습니다.

### 1) 입력과 출력

- **입력(Input):**  
  메시지들의 리스트(`SystemMessage`, `HumanMessage`, 필요 시 `AIMessage`)  
  혹은 단순 문자열(`str`)을 사용할 수 있습니다.  

- **출력(Output):**  
  `AIMessage` 객체로 반환되며,  
  본문 텍스트(`content`)뿐 아니라 **툴 호출 정보(`tool_calls`)**와 **메타데이터**를 포함할 수 있습니다.  

> 🔑 **핵심:**  
> 단순 문자열이 아닌 “메시지 시퀀스(Message Sequence)”를 표준 입력으로 사용하면  
> **멀티턴 대화, 멀티모달 입력, 툴 호출**까지 일관된 구조로 다룰 수 있습니다.


### 2) 최소 예제 (문자열 입력)

```python
from langchain.chat_models import init_chat_model

# 공급자:모델명 형태로 초기화
model = init_chat_model("openai:gpt-4.0")

# 단일 문자열 입력
resp = model.invoke("LangChain을 한 문장으로 요약해줘.")
print(resp.content)  # AIMessage의 본문 텍스트
```
> 💡 **`init_chat_model()`은 모델 초기화를 표준화한 통합 함수입니다.**  
> 이 함수를 사용하면 OpenAI, Anthropic, Gemini 등 서로 다른 공급자의 모델을  **동일한 코드 인터페이스로 손쉽게 교체하고 실험**할 수 있습니다.  
> 즉, 특정 SDK나 API 호출 방식에 종속되지 않고 LangChain의 표준 방식으로 일관된 초기화가 가능합니다.

### 3) 메시지 리스트 입력 예제

```python
from langchain.chat_models import init_chat_model
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

# 1) 모델 초기화
llm = init_chat_model("openai:gpt-4o")

# 2) 메시지 시퀀스 구성(권장)
messages = [
    SystemMessage(content="당신은 간결하고 정확한 기술 작가입니다."),
    HumanMessage(content="채팅 모델의 핵심 개념을 2~3줄로 요약해줘.")
]

# 3) 호출 및 결과
ai_msg = llm.invoke(messages)
print(ai_msg.content)
```
>왜 메시지 리스트”인가?
>-   **역할(Role)** 을 구분해 맥락을 명확히 유지(시스템 지침/사용자 질의/모델 응답).
>-   이후 **다중 턴, 툴 호출, 멀티모달 입력**으로 자연스럽게 확장 가능.
```python
# (선택) 직전 응답을 포함한 연속 대화 예시
followup = [
    *messages,
    AIMessage(content=ai_msg.content),           # 직전 모델 응답을 맥락에 포함
    HumanMessage(content="한 문장으로 더 압축해줘.")
]
print(llm.invoke(followup).content)
```

### 4) 표준 호출 메서드

채팅 모델은 `invoke`, `stream`, `batch` 세 가지 주요 호출 방식을 지원합니다.  
각 방식은 목적과 반환형이 다르므로, 상황에 맞게 선택할 수 있습니다.

| 메서드 | 설명 | 반환형 |
|:--|:--|:--|
| `invoke()` | 단일 입력에 대해 완성된 응답을 한 번에 반환 | `AIMessage` |
| `stream()` / `astream()` | 토큰 단위로 실시간 스트리밍(각각 동기 / 비동기) | `AIMessageChunk` |
| `batch()` / `abatch()` | 여러 입력을 묶어 병렬 처리 | `List[AIMessage]` |

---

```python
from langchain.chat_models import init_chat_model

llm = init_chat_model("openai:gpt-4o")

# 1) invoke — 단일 호출
resp = llm.invoke("LangChain의 핵심 개념을 3줄로 요약해줘.")
print(resp.content)

# 2) stream — 동기 스트리밍
for chunk in llm.stream("스트리밍으로 한 줄씩 보여줘."):
    print(chunk.content, end="")

# 3) batch — 여러 요청을 한 번에
questions = [
    "LLM이란?",
    "에이전트와 모델의 차이는?",
    "구조화 출력의 장점은?"
]
answers = llm.batch(questions)

for a in answers:
    print(a.content)
```

### 5) 메시지 포맷 두 가지(객체 vs 딕셔너리)

LangChain은 **메시지를 두 가지 방식**으로 표현할 수 있습니다.  
프로젝트 안에서는 한 가지 방식으로 **통일**해서 쓰는 것을 권장합니다.

**객체형(권장)**  
- `SystemMessage`, `HumanMessage`, `AIMessage`, `ToolMessage` 등 클래스를 직접 사용  
- - 타입이 분명해서 IDE 자동완성, 리팩터링, 테스트에 유리
```python
# 1) 객체형(권장)
from langchain_core.messages import SystemMessage, HumanMessage

messages_obj = [
    SystemMessage(content="한국어로 간결하게 답해주세요."),
    HumanMessage(content="채팅 모델과 에이전트의 차이를 한 문장으로 설명해줘.")
]
```
**딕셔너리형(호환)**  
- OpenAI 등 외부 API에서 흔히 쓰는 `{"role": "...", "content": "..."}` 형태  
 - - 외부 JSON과 바로 주고받을 때 편리
```python
# 2) 딕셔너리형(호환)
messages_dict = [
    {"role": "system", "content": "한국어로 간결하게 답해주세요."},
    {"role": "user", "content": "채팅 모델과 에이전트의 차이를 한 문장으로 설명해줘."}
]
```
> 💡 **언제 어떤 걸 쓰나?**  
> - **객체형**: LangChain 안에서만 돌 때, 그래프·체인·툴 호출까지 사용할 때  
> - **딕셔너리형**: 외부 API에서 온 메시지를 그대로 넘길 때, 프론트엔드 ↔ 백엔드 간 JSON만 주고받을 때  
>
> ⚠️ **주의**  
> 서로 다른 포맷을 섞으면 디버깅이 어려워집니다.  
> 한 프로젝트(또는 한 노트북)에서는 **객체형으로 통일**하는 것을 추천합니다.

### 6) 운영 파라미터 & 실무 팁

채팅 모델은 여러 **운영 파라미터(Operational Parameters)** 를 통해 출력 품질, 속도, 비용, 안정성을 조정할 수 있습니다.  
아래는 가장 자주 사용하는 주요 인자들입니다.

| 파라미터 | 설명 | 예시 값 |
|:--|:--|:--|
| `temperature` | 출력 다양성(창의성) 제어 | 0.0 ~ 1.0 (낮을수록 일관된 답변) |
| `max_tokens` | 한 응답의 최대 토큰 수 | 256, 512 등 |
| `timeout` | 응답 대기 시간(초) | 10 ~ 60 |
| `max_retries` | 실패 시 자동 재시도 횟수 | 기본 2 |
| `api_key` | (선택) 코드 내에서 직접 키 지정 | `"sk-..."` |

---

```python
from langchain.chat_models import init_chat_model

# 주요 파라미터 설정 예시
llm = init_chat_model(
    "openai:gpt-4o",
    temperature=0.2,   # 낮을수록 더 일관적이고 덜 창의적
    max_tokens=256,    # 최대 출력 길이
    timeout=15,        # 요청 제한 시간(초)
    max_retries=2      # 실패 시 재시도 횟수
)

resp = llm.invoke("운영 파라미터 설정의 의미를 간단히 설명해줘.")
print(resp.content)
```
>**운영 팁**
>-   **낮은 `temperature` + 적절한 `max_tokens`** 설정으로 비용과 변동성을 줄일 수 있습니다. 
>-   `timeout`과 `max_retries`를 함께 설정하면 **네트워크 불안정 시 자동 복구**에 유리합니다.
>-   대량 요청 시에는 **`batch()`** 또는 **비동기 호출(`abatch`)** 을 사용해 처리 효율을 높이세요.
>-   LangSmith를 활성화(`LANGCHAIN_TRACING_V2=true`)하면 실행 로그와 토큰 사용량을 손쉽게 모니터링할 수 있습니다.

### 7) 환경 변수(ENV) 설정 요약

LangChain v1에서는 **환경변수 구조가 단순화**되고,  
모델 초기화와 에이전트 구동 시 **공급자별 키만 설정하면 작동**하도록 통합되었습니다.  
아래는 주요 ENV 변수와 변경 요약입니다.

---

#### ✅ 7.1) 공급자(API Key) 설정 (기존 방식 유지)

| 공급자 | 환경 변수 | 예시 |
|:--|:--|:--|
| OpenAI | `OPENAI_API_KEY` | `sk-xxxx` |
| Anthropic | `ANTHROPIC_API_KEY` | `sk-ant-xxxx` |
| Google (Gemini) | `GOOGLE_API_KEY` | `AIza...` |
| Azure OpenAI | `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_VERSION` |  |
| AWS Bedrock | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION` |  |

> 💡 `init_chat_model("공급자:모델명")`은 공급자를 자동 추론하므로,  
> 모델명만 바꾸어도 **코드를 수정하지 않고 교체 실험이 가능**합니다.

```bash
# 예시
export OPENAI_API_KEY="sk-xxxx"
export ANTHROPIC_API_KEY="sk-ant-xxxx"
export GOOGLE_API_KEY="AIza..."
```
#### ⚙️ 7.2) 멀티모달 직렬화 스위치 (v1 신설)

멀티모달 표준 콘텐츠 블록을 `content` 필드에 포함하고 싶을 경우,  
아래 옵션으로 **직렬화 모드(v1)** 를 활성화할 수 있습니다.
```bash
export LC_OUTPUT_VERSION="v1"
```
>-   기본값은 `v0`이며, 공급자별 원본 포맷 그대로 유지됩니다.
>-   `v1`을 설정하면 LangChain 표준 콘텐츠 블록 구조로 변환되어  멀티모달 입력(이미지·오디오 등)을 일관되게 처리할 수 있습니다.

#### 📊 7.3) LangSmith 트레이싱 (권장)
LangChain 실행을 시각적으로 추적하고 토큰 사용량을 모니터링할 수 있습니다.)을 일관되게 처리할 수 있습니다.
```bash
export LANGCHAIN_TRACING_V2=true
export LANGCHAIN_API_KEY="lsv2-xxxx"
# 선택 옵션
export LANGCHAIN_PROJECT="my-project"
export LANGCHAIN_ENDPOINT="https://api.smith.langchain.com"
```
>LangSmith를 켜두면 `invoke`, `stream`, `batch` 호출마다  
**요청·응답·토큰 사용량·실행시간**이 자동으로 기록됩니다.
#### 🧭 7.4) v0 → v1 환경 변화 핵심 요약

| 항목 | v0 | v1 |
|:--|:--|:--|
| **API Key 구조** | 공급자별로 동일 | 변경 없음 |
| **모델 초기화** | 공급자별 클래스 필요 | `init_chat_model("공급자:모델명")` 한 줄로 통합 |
| **콘텐츠 직렬화** | 공급자 포맷 유지 | `LC_OUTPUT_VERSION=v1`로 표준 블록 직렬화 (옵트인) |
| **LangSmith 트레이싱** | 수동 설정 필요 | `LANGCHAIN_TRACING_V2` / `LANGCHAIN_API_KEY`로 간단히 활성화 |

> ✅ **정리**
> - 공급자별 API Key는 그대로 유지  
> - `LC_OUTPUT_VERSION=v1` 옵션으로 **멀티모달 콘텐츠 표준화** 가능  
> - LangSmith 트레이싱으로 **실행 히스토리와 토큰 사용량** 추적  
> - 코드 수정 없이 모델 교체 실험이 가능한 `init_chat_model` 구조로 단순화

---

### 8) v0 → v1 마이그레이션 정리

LangChain v1에서는 기존 코드를 거의 그대로 유지하면서도 호출 방식과 초기화 로직이 **표준화**되었습니다.  
아래 표와 예시를 통해 v0과 v1의 차이를 한눈에 비교할 수 있습니다.

---

#### 📋 주요 코드 변화 비교

| 구분 | v0 (이전 방식) | v1 (현재 권장 방식) |
|:--|:--|:--|
| **모델 초기화** | `from langchain.chat_models import ChatOpenAI`<br>`model = ChatOpenAI(model="gpt-4")` | `from langchain.chat_models import init_chat_model`<br>`model = init_chat_model("openai:gpt-4o")` |
| **호출 메서드** | `model.predict("질문")` | `model.invoke("질문")` |
| **스트리밍** | 공급자별로 다름 (예: OpenAI 전용 코드 필요) | `model.stream("입력")` (공통화) |
| **에이전트 생성** | `initialize_agent(tools, llm, agent="zero-shot-react-description")` | `create_agent(model="공급자:모델명", tools=[...])` |
| **출력 구조** | 단순 문자열 중심 | `AIMessage` / `AIMessageChunk` 객체 (메타데이터 포함) |
| **ENV 설정** | 공급자별로 별도 가이드 필요 | 동일 (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY` 등) |
| **콘텐츠 직렬화** | 없음 | `LC_OUTPUT_VERSION=v1` 설정으로 표준 콘텐츠 블록 직렬화 |

---

#### 💡 실제 변환 예시
**v0 (이전 방식)**
```python
# ✅ v0 방식
from langchain.chat_models import ChatOpenAI

model = ChatOpenAI(model="gpt-4", temperature=0.7)
response = model.predict("LangChain의 핵심 개념을 설명해줘.")
print(response)
```
**v1 (현재 권장 방식)**
```python
# ✅ v1 방식
from langchain.chat_models import init_chat_model

model = init_chat_model("openai:gpt-4o", temperature=0.7)
response = model.invoke("LangChain의 핵심 개념을 설명해줘.")
print(response.content)
```

### 🧩 마이그레이션 시 주의할 점

> - `ChatOpenAI`, `ChatAnthropic` 등 공급자별 클래스를 직접 임포트하는 대신  
>   **`init_chat_model("공급자:모델명")`** 형태로 교체합니다.  
> - 기존의 `.predict()`는 `.invoke()`로 변경하세요.  
> - 스트리밍(`.stream`)은 이제 **공통 API**로 제공되므로 별도 코드가 필요 없습니다.  
> - v1에서는 모든 호출이 **`AIMessage` 객체**를 반환하므로,  
>   **`response.content`** 로 본문 텍스트를 꺼내야 합니다.  
> - `LC_OUTPUT_VERSION=v1` 옵션을 설정하면 **멀티모달 콘텐츠 직렬화도 표준화**됩니다.

---

### ✅ 요약

| 항목 | 이전(v0) | 현재(v1) |
|:--|:--|:--|
| **모델/에이전트 초기화** | 공급자별 코드 | `init_chat_model` / `create_agent` 표준화 |
| **메서드** | `.predict()` | `.invoke()` |
| **결과** | 문자열 | `AIMessage` 객체 |
| **스트리밍** | 공급자별 구현 필요 | `stream()` 공통 메서드 |
| **환경변수** | 공급자별로 다름 | 동일, 구조 단순화 |
| **신규 옵션** | 없음 | `LC_OUTPUT_VERSION=v1` (직렬화 스위치) |

---

> 💬 **한줄 정리**  
> LangChain v1은 “공급자별로 제각각이던 코드”를 모두  **`init_chat_model`**, **`create_agent`**, **`invoke / stream / batch`** 인터페이스로  **통합 표준화**했습니다. 덕분에 모델 교체, 실험, 배포가 한결 단순해졌습니다.
