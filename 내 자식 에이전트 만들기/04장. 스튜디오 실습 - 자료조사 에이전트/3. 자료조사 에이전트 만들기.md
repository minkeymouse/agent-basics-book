이번 섹션에서는 1장부터 3장까지 배운 모든 내용을 활용하여 실제로 작동하는 자료조사 에이전트를 만들어보겠습니다. 사용자가 "요즘 가장 주목받는 영화 다섯개를 찾아서 보고서로 정리해줘"라고 요청하면, 에이전트가 웹에서 정보를 검색하고, 그 결과를 바탕으로 보고서를 작성한 다음 PDF 파일로 만들어주는 에이전트입니다.

이 에이전트는 두 가지 방법으로 실행할 수 있습니다. 하나는 LangGraph Studio를 사용하는 방법이고, 다른 하나는 Python 스크립트로 직접 실행하는 방법입니다. 처음에는 Studio를 사용하는 것을 권장합니다. Studio를 사용하면 그래프 구조를 시각적으로 확인할 수 있고, Human-in-the-Loop 처리도 브라우저에서 쉽게 할 수 있기 때문입니다.

자료조사 에이전트가 어떻게 동작하는지 먼저 살펴보겠습니다. 사용자가 자료조사 주제를 자연어로 요청하면, 에이전트는 Tavily Search라는 웹 검색 툴을 사용하여 관련 정보를 찾습니다. 검색 결과를 바탕으로 체계적인 보고서를 작성하고, 마지막으로 PDF 파일을 생성합니다. 이때 PDF 생성 전에 3장에서 배운 Human-in-the-Loop을 통해 사용자 승인을 받습니다. 이렇게 하면 사용자가 보고서 내용을 확인하고 수정하거나 거절할 수 있어 안전합니다.

먼저 프로젝트 구조를 확인해봅시다. 1번 섹션에서 만든 프로젝트 루트에 `graphs` 폴더와 `langgraph.json` 파일이 있어야 합니다. `graphs` 폴더 안에 `research_agent.py` 파일을 만들고, 여기에 에이전트 코드를 작성합니다. 이 파일의 `agent` 변수가 `langgraph.json`에서 참조되므로 파일 끝에 `agent` 변수를 그대로 두어야 합니다.

이제 필요한 라이브러리들을 임포트합니다. `graphs/research_agent.py` 파일을 생성하고 다음과 같이 작성합니다:

```python
# graphs/research_agent.py
import os
from dotenv import load_dotenv

from langchain.tools import tool
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langchain_community.tools.tavily_search import TavilySearchResults
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from reportlab.lib.pagesizes import A4
from reportlab.platypus import SimpleDocTemplate, Paragraph, Spacer
from reportlab.lib.styles import getSampleStyleSheet
from reportlab.lib.units import inch

# 환경 변수 로드
load_dotenv()
```

`langchain.tools.tool`은 2장에서 배운 커스텀 툴을 만들기 위한 데코레이터입니다. `create_agent`는 1장부터 3장까지 계속 사용해온 에이전트 생성 함수입니다. `TavilySearchResults`는 실시간 웹 검색을 제공하는 툴이고, `HumanInTheLoopMiddleware`는 3장에서 배운 사용자 승인을 위한 미들웨어입니다. `InMemorySaver`는 체크포인터인데, HITL을 사용하려면 반드시 필요합니다. 마지막으로 `reportlab`은 PDF 파일을 생성하기 위한 라이브러리입니다.

이제 툴을 정의해봅시다. 먼저 Tavily 검색 툴부터 시작합니다. Tavily Search는 LangChain에서 제공하는 툴을 그대로 사용하면 됩니다. Tavily는 실시간 웹 검색 API로, 최신 정보를 검색하는 데 유용합니다:

```python
# Tavily 검색 툴 생성
tavily_search = TavilySearchResults(
    max_results=5,              # 최대 검색 결과 개수
    include_raw_content=True     # 원문 내용 포함 여부
)
```

`max_results=5`는 최대 5개의 검색 결과를 가져온다는 의미입니다. 더 많은 결과가 필요하면 값을 늘릴 수 있습니다. `include_raw_content=True`는 검색 결과의 원문 내용도 포함한다는 의미인데, 이렇게 하면 에이전트가 더 상세한 정보를 활용할 수 있습니다.

Tavily를 사용하려면 API 키가 필요합니다. Tavily 웹사이트에서 무료로 발급받을 수 있으며, `.env` 파일에 `TAVILY_API_KEY=your_tavily_api_key_here` 형식으로 설정합니다. 나중에 HITL 설정을 할 때 툴 이름이 필요하므로, `TavilySearchResults`의 툴 이름은 일반적으로 `tavily_search_results_json`입니다.

이제 PDF 보고서를 생성하는 커스텀 툴을 만들어봅시다. 이는 2장에서 배운 `@tool` 데코레이터를 활용합니다:

```python
@tool
def generate_pdf_report(
    title: str,
    content: str,
    output_path: str = "report.pdf"
) -> str:
    """보고서 내용을 PDF 파일로 생성합니다.
    
    이 툴은 검색 결과를 바탕으로 작성된 보고서를 PDF 형식으로 변환합니다.
    제목과 본문을 포함하여 체계적인 보고서를 생성합니다.
    
    Args:
        title: 보고서 제목
        content: 보고서 본문 내용 (문단은 \\n\\n으로 구분)
        output_path: 생성할 PDF 파일 경로 (기본값: "report.pdf")
    
    Returns:
        생성된 PDF 파일 경로를 포함한 성공 메시지
    """
    try:
        # PDF 문서 생성
        doc = SimpleDocTemplate(output_path, pagesize=A4)
        styles = getSampleStyleSheet()
        story = []
        
        # 제목 추가
        story.append(Paragraph(title, styles['Heading1']))
        story.append(Spacer(1, 0.2*inch))
        
        # 본문 내용을 문단별로 분리하여 추가
        paragraphs = content.split('\n\n')
        for para in paragraphs:
            if para.strip():
                story.append(Paragraph(para.strip(), styles['Normal']))
                story.append(Spacer(1, 0.1*inch))
        
        # PDF 생성
        doc.build(story)
        
        return f"PDF 보고서가 성공적으로 생성되었습니다: {output_path}"
    except Exception as e:
        return f"PDF 생성 중 오류가 발생했습니다: {str(e)}"
```

`@tool` 데코레이터는 Python 함수를 LangGraph 툴로 변환합니다. 함수의 docstring은 툴 설명으로 사용되며, LLM이 언제 이 툴을 사용할지 판단하는 데 중요한 역할을 합니다. 구체적이고 명확하게 작성하는 것이 좋습니다. 타입 힌트는 툴의 입력 스키마를 자동으로 생성하므로 필수입니다. `output_path`에 기본값이 있어 선택적 인자로 사용할 수 있고, `try-except`로 오류를 처리하여 에이전트가 실패 원인을 이해할 수 있도록 합니다.

`@tool` 데코레이터로 만든 툴은 함수 이름을 그대로 사용합니다. 즉, `generate_pdf_report` 함수의 툴 이름은 `generate_pdf_report`입니다. PDF 생성을 위해 `reportlab` 라이브러리를 사용하며, `requirements.txt`에 이미 포함되어 있습니다.

이제 HITL 미들웨어를 설정하기 전에 툴의 정확한 이름을 확인해야 합니다. 툴 이름이 정확하지 않으면 HITL이 작동하지 않습니다:

```python
# 툴 목록 생성
tools = [tavily_search, generate_pdf_report]

# 툴 이름 확인 (디버깅용)
print("사용할 툴 목록:")
for tool in tools:
    print(f"  - {tool.name}")
```

이 코드를 실행하면 `TavilySearchResults`의 툴 이름은 `tavily_search_results_json`이고, `@tool` 데코레이터로 만든 툴 이름은 `generate_pdf_report`임을 확인할 수 있습니다.

이제 확인한 툴 이름을 사용하여 HITL 미들웨어를 설정합니다:

```python
# 모델 초기화
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 시스템 프롬프트 정의
system_prompt = """당신은 전문 자료조사 에이전트입니다.

사용자의 요청을 받으면:
1. Tavily 검색 툴을 사용하여 관련 정보를 검색합니다
2. 검색 결과를 바탕으로 체계적인 보고서를 작성합니다
3. 최종적으로 PDF 보고서를 생성합니다

중요한 원칙:
- 검색 결과를 바탕으로 정확한 정보만 제공합니다
- 출처를 명시하여 신뢰성을 보장합니다
- 사용자가 요청한 형식에 맞춰 보고서를 작성합니다
- 보고서는 명확하고 구조화된 형식으로 작성합니다
"""

# Human-in-the-Loop 미들웨어 설정
hitl_middleware = HumanInTheLoopMiddleware(
    interrupt_on={
        # PDF 생성은 승인 필요
        # True를 사용하면 모든 결정 타입(approve, edit, reject)이 허용됩니다
        "generate_pdf_report": True,
        # Tavily 검색은 자동 승인 (False로 설정)
        "tavily_search_results_json": False
    },
    description_prefix="보고서 생성 전 승인이 필요합니다"
)
```

`interrupt_on`은 어떤 툴 호출 시 승인을 받을지 설정하는 딕셔너리입니다. 툴 이름을 키로 사용하고, `True`를 사용하면 모든 결정 타입(`approve`, `edit`, `reject`)이 허용됩니다. 이는 docs-langchain에서 권장하는 간단한 방법입니다. 세부 설정을 원하면 `{"allowed_decisions": ["approve", "edit", "reject"]}` 형식으로 지정할 수도 있습니다. 예를들어 `edit`을 제외하고 `["approve", "reject"]`만 허용할 수도 있습니다. `False`로 설정하면 해당 툴은 자동으로 승인되어 중단되지 않습니다. `description_prefix`는 중단 메시지 앞에 붙는 설명으로, 사용자가 어떤 작업이 승인 대기 중인지 쉽게 이해할 수 있도록 도와줍니다.

이제 체크포인터를 설정하고 에이전트를 생성합니다:

```python
# 체크포인터 설정 (HITL을 사용하려면 필수)
checkpointer = InMemorySaver()

# 에이전트 생성
agent = create_agent(
    model=model,
    tools=tools,
    system_prompt=system_prompt,
    middleware=[hitl_middleware],
    checkpointer=checkpointer
)
```

Studio에서 사용하려면 파일 끝에 `agent` 변수를 그대로 두어야 합니다. 이 변수가 `langgraph.json`에서 참조됩니다.

이제 Studio에서 에이전트를 테스트해봅시다. 코드 작성이 완료되었으므로 프로젝트 루트 디렉토리에서 `langgraph dev` 명령어를 실행합니다. 터미널에 "LangGraph Dev Server is running at http://localhost:2024"와 "Studio is available at https://smith.langchain.com" 메시지가 표시됩니다.

브라우저에서 LangSmith Studio에 접속하고, 로컬 서버(`http://localhost:2024`)에 연결합니다. 그래프 목록에서 `research_agent`를 선택하고, 채팅 인터페이스에서 "요즘 가장 주목받는 영화 다섯개를 찾아서 보고서로 정리해줘"와 같은 메시지를 입력합니다. 에이전트의 실행 과정을 시각적으로 확인할 수 있고, PDF 생성 전에 HITL이 작동하면 Studio에서 승인, 수정, 거절을 선택할 수 있습니다.

Studio 대신 Python 스크립트로 직접 실행하려면 다음과 같이 작성합니다:

```python
from langgraph.types import Command

# 스레드 ID 설정 (체크포인터를 사용하므로 필요)
config = {"configurable": {"thread_id": "research_001"}}

# 사용자 요청
user_query = "요즘 가장 주목받는 영화 다섯개를 찾아서 보고서로 정리해줘"

# 에이전트 실행
result = agent.invoke(
    {"messages": [{"role": "user", "content": user_query}]},
    config=config
)

# 중단 여부 확인
if "__interrupt__" in result:
    print("⚠️ 에이전트 실행이 중단되었습니다. 승인이 필요합니다.")
    interrupts = result["__interrupt__"]
    
    print("승인이 필요한 작업:")
    for interrupt in interrupts:
        interrupt_data = interrupt.value
        for action_request in interrupt_data.get("action_requests", []):
            print(f"툴: {action_request['name']}")
            tool_args = action_request.get('args', {}) or action_request.get('arguments', {})
            print(f"인자: {tool_args}")
            print(f"설명: {action_request['description']}")
    
    # 사용자 승인 처리
    decision = input("승인하시겠습니까? (approve/edit/reject): ")
    
    if decision == "approve":
        # 승인하여 계속 진행
        result = agent.invoke(
            Command(resume={"decisions": [{"type": "approve"}]}),
            config=config
        )
    elif decision == "edit":
        # 수정하여 진행 (예시: 제목 변경)
        if action_requests:
            action_request = action_requests[0]
            new_title = input("새로운 보고서 제목을 입력하세요: ")
            original_args = action_request.get('args', {}) or action_request.get('arguments', {})
            result = agent.invoke(
                Command(
                    resume={
                        "decisions": [{
                            "type": "edit",
                            "edited_action": {
                                "name": "generate_pdf_report",
                                "args": {**original_args, "title": new_title}
                            }
                        }]
                    }
                ),
                config=config
            )
    elif decision == "reject":
        # 거절하고 종료
        reason = input("거절 이유를 입력하세요: ")
        result = agent.invoke(
            Command(
                resume={
                    "decisions": [{
                        "type": "reject",
                        "message": reason
                    }]
                }
            ),
            config=config
        )
else:
    # 정상 완료
    print("에이전트 응답:")
    print(result["messages"][-1].content)
```

`__interrupt__`는 HITL 미들웨어가 중단시킨 작업 목록입니다. 이 키가 결과에 있으면 에이전트 실행이 중단된 것입니다. `Command`는 중단된 작업을 승인, 수정, 거절하는 객체입니다. `resume` 파라미터에 결정을 전달하고, `decisions` 리스트에 각 중단된 작업에 대한 결정을 순서대로 제공해야 합니다. 여러 툴이 중단되면 각각에 대한 결정을 순서대로 제공해야 합니다.

에이전트의 실행 과정을 실시간으로 확인하기 위해 스트리밍을 사용할 수도 있습니다. 이는 3장에서 배운 내용입니다:

```python
# 스트리밍으로 실행 과정 확인
for chunk in agent.stream(
    {"messages": [{"role": "user", "content": user_query}]},
    config=config,
    stream_mode="updates"
):
    for step, data in chunk.items():
        print(f"\n[Step: {step}]")
        
        # 메시지 확인
        if "messages" in data:
            last_msg = data["messages"][-1]
            if hasattr(last_msg, "tool_calls") and last_msg.tool_calls:
                print(f"툴 호출: {last_msg.tool_calls[0]['name']}")
                print(f"인자: {last_msg.tool_calls[0]['args']}")
            elif hasattr(last_msg, "content"):
                print(f"응답: {last_msg.content[:200]}...")
```

`stream_mode="updates"`는 각 단계에서 변경된 부분만 확인합니다. 전체 상태가 아닌 변경사항만 보여주므로 더 효율적입니다. 툴 호출 과정을 실시간으로 추적할 수 있어 에이전트의 사고 과정을 이해하는 데 도움이 됩니다. `step`은 실행 단계를 나타냅니다. `model`은 모델 호출 단계, `tools`는 툴 실행 단계를 의미합니다.

실제로 에이전트를 실행하는 전체 흐름을 정리하면 다음과 같습니다. HITL을 사용하므로 중단 처리가 필요합니다:

```python
from langgraph.types import Command

def run_research_agent(query: str):
    """자료조사 에이전트를 실행하는 함수"""
    
    config = {"configurable": {"thread_id": f"research_{hash(query) % 10000}"}}
    
    print("🔍 자료조사 시작...")
    result = agent.invoke(
        {"messages": [{"role": "user", "content": query}]},
        config=config
    )
    
    # HITL 처리
    while "__interrupt__" in result:
        interrupts = result["__interrupt__"]
        
        print("\n⏸️  에이전트 실행이 중단되었습니다.")
        print("승인이 필요한 작업:")
        
        # 중단된 작업 정보 표시 및 저장
        action_requests = []
        for interrupt in interrupts:
            interrupt_data = interrupt.value
            for action_request in interrupt_data.get("action_requests", []):
                action_requests.append(action_request)
                print(f"\n툴: {action_request['name']}")
                tool_args = action_request.get('args', {}) or action_request.get('arguments', {})
                print(f"인자: {tool_args}")
                print(f"설명: {action_request['description']}")
        
        # 사용자 결정 받기
        print("\n선택하세요:")
        print("1. approve - 승인하고 계속 진행")
        print("2. edit - 수정하고 진행")
        print("3. reject - 거절하고 종료")
        
        choice = input("선택 (1/2/3): ").strip()
        
        if choice == "1":
            result = agent.invoke(
                Command(resume={"decisions": [{"type": "approve"}]}),
                config=config
            )
        elif choice == "2":
            if action_requests:
                action_request = action_requests[0]
                new_title = input("새로운 보고서 제목을 입력하세요: ")
                original_args = action_request.get('args', {}) or action_request.get('arguments', {})
                result = agent.invoke(
                    Command(
                        resume={
                            "decisions": [{
                                "type": "edit",
                                "edited_action": {
                                    "name": "generate_pdf_report",
                                    "args": {
                                        **original_args,
                                        "title": new_title
                                    }
                                }
                            }]
                        }
                    ),
                    config=config
                )
        elif choice == "3":
            reason = input("거절 이유를 입력하세요: ")
            result = agent.invoke(
                Command(
                    resume={
                        "decisions": [{
                            "type": "reject",
                            "message": reason
                        }]
                    }
                ),
                config=config
            )
            break
        else:
            print("잘못된 선택입니다. 다시 시도하세요.")
            continue
    
    # 최종 결과 확인
    if "__interrupt__" not in result:
        print("\n✅ 자료조사 완료!")
        final_message = result["messages"][-1]
        print(f"최종 응답: {final_message.content}")
        
        if os.path.exists("report.pdf"):
            print("\n📄 PDF 보고서가 생성되었습니다: report.pdf")

# 실행 예시
if __name__ == "__main__":
    run_research_agent("요즘 가장 주목받는 영화 다섯개를 찾아서 보고서로 정리해줘")
```

이 함수는 사용자 쿼리로 에이전트를 시작하고, `__interrupt__` 키가 있으면 HITL이 작동한 것입니다. 사용자가 승인, 수정, 거절 중 선택하고, `Command` 객체로 중단된 실행을 재개합니다. 여러 툴이 중단되면 반복 처리하고, 최종 결과를 확인합니다.

실제 사용 시 발생할 수 있는 문제와 해결 방법도 알아봅시다. Tavily API 키가 없으면 검색이 실패하므로, 코드 시작 부분에 에러 처리를 추가할 수 있습니다:

```python
    print("Tavily 웹사이트(https://tavily.com)에서 API 키를 발급받아 .env 파일에 설정하세요.")
```

HITL 설정 시 툴 이름이 정확하지 않으면 중단이 작동하지 않습니다. 에이전트 생성 전에 툴 이름을 확인하는 것이 좋습니다:

```python
# 에이전트 생성 전에 툴 이름 확인

for tool in tools:
```

PDF 생성 중 오류가 발생할 수 있습니다. 툴 내부에서 이미 처리하고 있지만, 실행 후 파일 존재 여부를 확인할 수 있습니다:

```python
    print("✅ PDF 파일이 성공적으로 생성되었습니다.")
else:
    print("⚠️ PDF 파일 생성에 실패했습니다.")
```

Studio가 로컬 서버에 연결되지 않는 경우, `langgraph dev`가 정상적으로 실행되었는지 확인하고, 기본 포트는 2024입니다. 다른 포트를 사용하는 경우 Studio에서 포트를 변경해야 합니다. Studio에서 그래프를 찾을 수 없는 경우, `langgraph.json`의 `graphs` 설정이 올바른지 확인하고, Python 파일에서 `agent` 변수가 올바르게 정의되었는지 확인합니다.

이제 모든 단계를 통합한 완성된 코드입니다. `graphs/research_agent.py` 파일에 저장합니다:

```python
# graphs/research_agent.py
# Studio에서 실행하기 위한 파일
import os
from dotenv import load_dotenv
from langchain.tools import tool
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langchain_community.tools.tavily_search import TavilySearchResults
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from reportlab.lib.pagesizes import A4
from reportlab.platypus import SimpleDocTemplate, Paragraph, Spacer
from reportlab.lib.styles import getSampleStyleSheet
from reportlab.lib.units import inch

# 환경 변수 로드
load_dotenv()

# API 키 확인
if not os.getenv("TAVILY_API_KEY"):
    print("⚠️ TAVILY_API_KEY가 설정되지 않았습니다.")
    print("Tavily 웹사이트(https://tavily.com)에서 API 키를 발급받아 .env 파일에 설정하세요.")

# PDF 생성 툴
@tool
def generate_pdf_report(
    title: str,
    content: str,
    output_path: str = "report.pdf"
) -> str:
    """보고서 내용을 PDF 파일로 생성합니다.
    
    이 툴은 검색 결과를 바탕으로 작성된 보고서를 PDF 형식으로 변환합니다.
    제목과 본문을 포함하여 체계적인 보고서를 생성합니다.
    
    Args:
        title: 보고서 제목
        content: 보고서 본문 내용 (문단은 \\n\\n으로 구분)
        output_path: 생성할 PDF 파일 경로 (기본값: "report.pdf")
    
    Returns:
        생성된 PDF 파일 경로를 포함한 성공 메시지
    """
    try:
        doc = SimpleDocTemplate(output_path, pagesize=A4)
        styles = getSampleStyleSheet()
        story = []
        
        story.append(Paragraph(title, styles['Heading1']))
        story.append(Spacer(1, 0.2*inch))
        
        paragraphs = content.split('\n\n')
        for para in paragraphs:
            if para.strip():
                story.append(Paragraph(para.strip(), styles['Normal']))
                story.append(Spacer(1, 0.1*inch))
        
        doc.build(story)
        return f"PDF 보고서가 성공적으로 생성되었습니다: {output_path}"
    except Exception as e:
        return f"PDF 생성 중 오류가 발생했습니다: {str(e)}"

# 모델 초기화
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# Tavily 검색 툴
tavily_search = TavilySearchResults(
    max_results=5,
    include_raw_content=True
)

# 툴 목록
tools = [tavily_search, generate_pdf_report]

# 시스템 프롬프트
system_prompt = """당신은 전문 자료조사 에이전트입니다.

사용자의 요청을 받으면:
1. Tavily 검색 툴을 사용하여 관련 정보를 검색합니다
2. 검색 결과를 바탕으로 체계적인 보고서를 작성합니다
3. 최종적으로 PDF 보고서를 생성합니다

중요한 원칙:
- 검색 결과를 바탕으로 정확한 정보만 제공합니다
- 출처를 명시하여 신뢰성을 보장합니다
- 사용자가 요청한 형식에 맞춰 보고서를 작성합니다
"""

# Human-in-the-Loop 미들웨어
hitl_middleware = HumanInTheLoopMiddleware(
    interrupt_on={
        # PDF 생성은 승인 필요 (True를 사용하면 모든 결정 타입 허용)
        "generate_pdf_report": True,
        # Tavily 검색은 자동 승인 (False로 설정)
        "tavily_search_results_json": False
    },
    description_prefix="보고서 생성 전 승인이 필요합니다"
)

# 체크포인터
checkpointer = InMemorySaver()

# 에이전트 생성
agent = create_agent(
    model=model,
    tools=tools,
    system_prompt=system_prompt,
    middleware=[hitl_middleware],
    checkpointer=checkpointer
)

# Studio에서 사용하기 위해 agent 변수로 export
# langgraph.json에서 "./graphs/research_agent.py:agent"로 참조됩니다
# 이 변수를 그대로 두면 Studio가 자동으로 인식합니다
```

Studio에서 실행하려면 파일 끝에 `agent` 변수를 그대로 두어야 합니다. Studio는 이 변수를 자동으로 인식하여 `langgraph.json`의 설정과 연결합니다. 파일을 저장한 후 `langgraph dev`를 실행하면 Studio에서 에이전트를 테스트할 수 있습니다.

이번에 만든 자료조사 에이전트는 1장부터 3장까지 배운 모든 개념을 활용합니다. 1장에서는 `create_agent`를 통한 에이전트 구성과 여러 툴을 하나의 에이전트에 통합하는 방법을 배웠습니다. 2장에서는 `@tool` 데코레이터를 활용한 커스텀 툴 생성, 타입 힌트와 docstring을 통한 자동 스키마 생성, `InMemorySaver`를 통한 대화 세션 관리를 배웠습니다. 3장에서는 `HumanInTheLoopMiddleware`를 통한 사용자 승인, `stream_mode="updates"`를 통한 실행 과정 추적, 위험한 작업에 대한 사용자 승인을 배웠습니다.

이제 1장부터 3장까지 배운 모든 내용을 활용하여 실제로 작동하는 자료조사 에이전트를 만들었습니다. Studio를 통해 시각적으로 테스트해보고, 다양한 주제로 에이전트를 실행해보세요. 필요에 따라 툴을 추가하거나 시스템 프롬프트를 개선하여 더 나은 결과를 얻을 수 있습니다.
