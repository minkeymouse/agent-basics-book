“기술은 복잡하지만, 사용은 단순해야 한다.”
— Steve Jobs

LangChain/LangGraph v1은 이 말에 꽤 잘 어울립니다. 내부적으로는 에이전트·툴·메모리·체크포인트·그래프 런타임이 복잡하게 연결되어 있지만, 사용하는 사람 입장에서는 **한두 개의 표준 함수와 일관된 인터페이스**만 알면 대부분의 에이전트를 만들 수 있도록 설계되었습니다.

## LangChain v1 한눈에 보기

v1에서 LangChain은 “에이전트 중심”으로 크게 정리되었습니다. 공식 문서에서는 세 가지 축을 특히 강조합니다.  
([LangChain v1 개요 문서](https://docs.langchain.com/oss/python/langchain/overview), [v1 릴리스 노트](https://docs.langchain.com/oss/python/releases/langchain-v1))

- `create_agent` : 기존 `create_react_agent`를 대체하는 **표준 에이전트 생성 함수**
- `init_chat_model` : 공급자에 관계없이 동일한 방식으로 채팅 모델을 초기화하는 함수
- 표준 콘텐츠 블록(content blocks) : 텍스트·이미지·오디오 등 멀티모달 입력을 하나의 `content` 구조로 통합

이 세 가지 덕분에, 모델 교체나 구조화 출력, 툴 호출 같은 기능을 **공급자에 덜 의존하면서** 구현할 수 있습니다.

## LangGraph v1 한눈에 보기

LangGraph v1은 “그래프 런타임의 안정성”에 초점을 맞춘 릴리스입니다.  
([LangGraph v1 개요 문서](https://docs.langchain.com/oss/python/langgraph/overview), [v1 릴리스 노트](https://docs.langchain.com/oss/python/releases/langgraph-v1))

- 그래프의 기본 개념(상태, 노드, 엣지, 실행 모델)은 v0와 크게 달라지지 않았습니다.
- 대신 **타입 안정성, 체크포인터/메모리, 스트리밍, human-in-the-loop(HITL)** 같은 운영 기능이 정식으로 자리를 잡았습니다.
- LangChain v1의 `create_agent`는 내부적으로 LangGraph 위에서 돌아가므로, “빠른 프로토타입 → 세밀한 그래프 설계”로 자연스럽게 내려갈 수 있습니다.

즉, **LangChain은 에이전트를 조립하는 프레임워크**, **LangGraph는 그 에이전트를 오래·안전하게 돌리는 런타임**이라고 이해하면 됩니다.

## 이 장에서 다루는 v1 관점

0장의 목적은 LangChain/LangGraph v1 전체를 깊게 파는 것이 아니라,

- “왜 v1이 나왔는지”
- “앞으로 예제에서 보게 될 코드의 기본 축이 무엇인지”

를 감만 잡는 데에 있습니다. 뒤 장에서 나오는 코드들은 대부분 다음과 같은 패턴을 따르게 됩니다.

- 모델 초기화: `init_chat_model("공급자:모델명")`
- 에이전트 생성: `create_agent(model=..., tools=[...], ...)`
- 그래프 구성: `StateGraph`에 노드·엣지를 정의하고 `compile(checkpointer=...)`로 실행 준비

이 흐름을 머릿속에 두고 이하 장을 읽으면, 세부 문법보다 **“전체 구조가 어떻게 생겼는지”** 먼저 눈에 들어올 것입니다.

## LangGraph Studio 한눈에 보기

Studio는 코드로 작성한 그래프를 화면에 펼쳐 보여주는 동반자 같은 도구입니다. 실행 흐름이 어디로 흘러가는지, 어떤 노드에서 어떤 상태가 만들어지는지, 언제 분기되고 다시 합쳐지는지를 눈으로 따라갈 수 있습니다. 멀티턴 대화를 직접 입력해 보며 결과를 확인할 수 있고, 중요한 지점에서 실행을 잠시 멈춰 상태를 들여다보는 브레이크포인트, 단계별로 변화가 전달되는 모습을 실시간으로 확인하는 스트리밍까지, 에이전트 개발에 필요한 기능이 자연스럽게 녹아 있습니다.

## 설치 확인

앞서 `00-02. 개발 환경 설정`에서 `langgraph-studio`를 설치했다면 추가 설정 없이 바로 사용할 수 있습니다. 가상환경이 활성화된 상태인지만 확인해 주세요.

## 실행 방법

프로젝트 루트에서 다음 명령을 실행하면 Studio가 켜집니다. 잠시 후 브라우저가 자동으로 열리며 인터페이스가 표시됩니다.

```bash
langgraph dev
```

만약 자동으로 열리지 않는다면 주소창에 `http://localhost:8000`을 직접 입력해 접속합니다. 기본적으로 현재 폴더의 `langgraph.json`을 읽어 그래프를 로드하며, 해당 파일이 없다면 빈 상태에서 시작합니다.

## 주요 화면과 기능

화면의 중심에는 그래프 뷰가 자리합니다. 노드와 엣지가 시각적으로 배치되어 있고, 실행이 진행되면 현재 위치가 강조되어 어디서 무엇이 일어나는지 쉽게 파악할 수 있습니다. 오른쪽에는 상태 패널이 있어 메시지와 키-값 상태를 시점별로 살펴볼 수 있습니다. 아래쪽 실행 로그는 각 노드의 결과와 오류를 시간순으로 보여 주어, 예상치 못한 동작의 원인을 빠르게 좁히는 데 도움을 줍니다. 입력 패널에서는 사용자 메시지나 테스트 데이터를 넣고 같은 흐름을 여러 번 재실행하며 비교해 볼 수 있습니다.

## 기본 사용 흐름

일반적으로는 Studio를 실행한 뒤 좌측에서 그래프나 스레드를 선택하고, 입력 패널에 프롬프트를 적어 실행합니다. 그러면 그래프 뷰가 활성화되며 경로를 따라 노드가 차례로 실행되고, 각 단계에서 상태가 어떻게 변하는지 상태 패널에서 확인할 수 있습니다. 실행 로그를 함께 보면서 기대와 다른 부분이 나타나는지 점검하면 디버깅이 훨씬 수월해집니다.

## 디버깅 기능 요약

실행 과정을 세밀하게 관찰하려면 스트리밍 모드를 적절히 고르는 것이 중요합니다. 최종 상태만 빠르게 확인하고 싶다면 values, 단계별 상태 갱신을 보고 싶다면 updates, 메시지 중심으로 살피려면 messages, 내부 동작까지 자세히 살피려면 debug가 알맞습니다. 특정 노드 전후로 실행을 멈추는 브레이크포인트를 활용하면, 해당 시점의 상태를 확인하고 필요할 경우 값을 수정해 다른 경로로 이어가 볼 수도 있습니다. 이를 통해 원인을 가설로 세우고 즉시 검증하는 ‘짧은 피드백 루프’를 만들 수 있습니다.

## 자주 겪는 이슈와 해결

가끔 Studio가 뜨지 않는 경우가 있습니다. 대부분 가상환경이 비활성화되어 있거나 `langgraph-studio` 설치가 누락된 경우이니, 먼저 이 두 가지를 확인하세요. 그래프가 비어 보인다면 `langgraph.json`의 경로나 형식이 올바른지 점검합니다. API 호출 오류가 난다면 `.env`에 입력한 `OPENAI_API_KEY` 값과 철자를 다시 확인해 보세요. 실행이 오래 걸리거나 중간에 멈추는 증상이 있다면 스트리밍 모드를 `debug`로 전환해 어느 노드에서 지연이 발생하는지부터 찾아내는 것이 좋습니다.
