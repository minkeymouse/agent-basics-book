지금까지 우리는 하나의 에이전트를 만들고, 기억을 주고, 도구를 쥐여주며
‘혼자서 생각하고 행동하는’ 법을 배웠습니다. <br>
하지만 어느 순간, 우리의 에이전트는 세상에서 혼자 감당하기엔 버거운 문제들을 만나게 됩니다.

> “나 혼자서는 너무 많은 걸 알아야 해요.” <br>
> “이건 제가 아니라 수학에 강한 친구가 해야 할 것 같아요.” <br>
> “사람마다 말을 다르게 하니, 제 기억이 너무 복잡해져요…” <br>

이 시점에서 우리는 하나의 에이전트가 아닌, **여러 명의 에이전트가 협력하는 세상**을 마주하게 됩니다. <br>
바로, **멀티에이전트 시스템(Multi-agent System)** 입니다.

### 👭 멀티에이전트가 무엇일까요?

멀티에이전트 시스템은 복잡한 문제를 작게 나눠,
**전문성을 가진 여러 에이전트들이 협력해 해결하는 구조**입니다.

즉,

> “한 명의 천재 대신, 여러 명의 전문가가 팀으로 일하는 방식”이죠.

LangChain에서는 이 구조를 다양한 형태로 구현할 수 있습니다. <br>
예를 들어 다음과 같은 상황에서 멀티에이전트가 유용합니다:

* 단일 에이전트가 너무 많은 도구를 가지고 있어 선택을 잘못하는 경우
* 메모리(컨텍스트)가 커져 한 에이전트가 모든 정보를 추적하기 어려운 경우
* 작업이 명확히 분업 가능한 경우 (예: 기획자, 연구자, 계산전문가)

## 🧠 멀티에이전트 패턴 이해하기

멀티에이전트의 핵심은 **“누가 말하고, 누가 듣고, 누가 실행할까”**입니다. <br>
LangChain에서는 주로 다음 두 가지 패턴으로 이를 조합합니다:

| 패턴 | 설명 | 제어 흐름 | 예시 |
|------|------|------|------|
| 🕹️ Tool Calling | 한 감독 에이전트(Supervisor) 가 다른 하위 에이전트를 도구처럼 호출 | 중앙집중형 | 이메일 요약기 + 일정 분석기 |
| 🔁 Handoff | 현재 에이전트가 다음 담당자에게 대화 주도권을 넘김 | 분산형 | 도메인별 상담, 전문가 교체형 대화 |

이 두 구조는 서로 배타적이지 않습니다.
실무에서는 **하이브리드 형태** (감독 에이전트가 필요할 때 sub-agent를 도구로 호출하고,
필요 시에는 사용자 대화를 넘기는 형태) 를 자주 사용합니다.

## ⚙️ 환경 설정 준비

멀티에이전트를 실험하려면 LangChain과 OpenAI 도구 세트를 준비해야 합니다. <br>
기존의 단일 에이전트와 동일한 환경 위에, 단지 **여러 명의 에이전트**를 추가할 뿐입니다.

```python
pip install langchain langchain-openai
```

그리고 모델 환경 변수도 설정해줍니다.

```python
export OPENAI_API_KEY="YOUR_API_KEY"
```

또는 Python 코드 상단에 직접 지정할 수도 있습니다.

```python
import os
os.environ["OPENAI_API_KEY"] = "YOUR_API_KEY"
```

## 이번 장의 구성

이 장에서는 이제 막 세상으로 나온 에이전트가
**“혼자서 일하던 시절”을 지나 “협력하는 사회적 존재”로 성장하는 과정**을 따라갑니다.

| 단계 | 소제목 | 핵심 개념 |
|------|------|------|
| 🧑‍🤝‍🧑 1단계 | 에이전트가 친구를 만나기 (Parallel Collaboration) | 여러 에이전트가 동시에 일을 나누는 구조 |
| 🧩 2단계 | 역할을 나눠 일하기 (Subgraph Collaboration) | 각 에이전트가 자신만의 역할과 워크플로를 갖는 구조 |
| 🧠 3단계 | 모인 생각을 하나로 정리하기 (Map & Reduce Reasoning) | 여러 결과를 하나의 통합된 답으로 모으는 구조 |
