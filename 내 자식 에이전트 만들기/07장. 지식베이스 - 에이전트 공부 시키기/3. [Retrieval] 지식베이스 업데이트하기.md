지식베이스는 한 번 저장하고 끝이 아닙니다. 사용자의 정보가 변경되거나, 새로운 정보가 추가되거나, 기존 정보를 수정해야 할 때가 있습니다. 효과적인 업데이트 전략이 지식베이스를 유용하게 만드는 핵심입니다.

실제로 지식베이스는 살아있는 시스템입니다. 사용자의 선호도는 시간이 지나면서 변할 수 있고, 새로운 경험이 쌓이면서 정보가 추가되거나 수정될 수 있습니다. 예를들어 사용자가 처음에는 "비빔밥을 좋아함"이라고 했지만, 나중에 "비빔밥과 불고기를 좋아함"으로 변경되었다면, 지식베이스도 이에 맞게 업데이트되어야 합니다.

또한 정보의 정확성을 유지하는 것도 중요합니다. 오래된 정보나 잘못된 정보가 지식베이스에 남아있다면, 에이전트가 부정확한 응답을 할 수 있습니다. 따라서 지식베이스를 정기적으로 검토하고 업데이트하는 것이 필요합니다.

이번 섹션에서는 LangGraph Store에서 저장된 정보를 업데이트하고 관리하는 다양한 방법을 배워봅시다. 기본적인 업데이트부터 메모리 컬렉션을 활용한 동적 관리까지 학습합니다. 1~2절에서 살펴본 Store·Retrieval 개념 위에, 여기서는 “어떤 정보를 프로필로 묶고, 어떤 정보를 컬렉션으로 나눌지”라는 **메모리 스키마 설계** 관점까지 함께 다뤄 봅니다.

지식베이스는 살아있는 시스템입니다. 사용자의 선호도가 바뀌고, 새로운 정보가 계속 추가되며, 오래된 정보는 갱신되어야 합니다. 마치 인간의 기억이 시간이 지나면서 변화하고 업데이트되는 것처럼, 에이전트의 지식베이스도 지속적으로 관리되어야 합니다.

예를들어 사용자가 처음에는 "독서를 좋아함"이라고 했지만, 나중에 "독서와 영화감상을 좋아함"으로 변경되었다고 가정해봅시다. 만약 지식베이스가 업데이트되지 않는다면, 에이전트는 여전히 사용자가 독서만 좋아한다고 생각하고, 영화에 대한 추천을 하지 않을 수 있습니다. 이는 사용자 경험을 저해할 수 있습니다.

또한 정보의 정확성을 유지하는 것도 중요합니다. 사용자가 실수로 잘못된 정보를 제공했거나, 나중에 정보를 수정하고 싶을 수 있습니다. 예를들어 사용자가 처음에는 "치와와를 좋아함"이라고 했지만, 나중에 "실제로는 골든 리트리버를 좋아함"으로 정정했다면, 지식베이스를 업데이트해야 합니다.

다음과 같은 상황에서 지식베이스를 업데이트해야 합니다. 사용자의 선호도나 관심사가 변경되었을 때, 사용자가 새로운 정보를 제공했을 때, 잘못된 정보를 수정하거나 더 이상 유효하지 않은 정보를 삭제할 때, 시간이 지나면서 변경된 정보를 반영할 때입니다.

지식베이스를 업데이트하는 방법은 여러 가지가 있으며, 각각 장단점이 있습니다. 전체 교체는 기존 데이터를 완전히 새로운 데이터로 교체하는 방법으로 구현이 간단하지만, 일부 필드만 업데이트하려고 할 때 나머지 필드가 손실될 수 있어 작은 객체나 단순한 구조에 적합합니다. 부분 업데이트는 변경된 부분만 수정하는 방법으로 기존 값을 가져와서 병합한 후 저장합니다. 자동 업데이트는 LLM을 활용하여 대화에서 자동으로 정보를 추출하고 업데이트하는 방법으로, `with_structured_output`을 사용하여 구조화된 정보를 추출하고 Store에 저장합니다. 사용자 개입 없이 지식베이스를 관리할 수 있지만, 잘못된 정보가 저장될 위험이 있습니다.

지식베이스를 업데이트하는 가장 기본적인 방법부터 알아봅시다. 기본 업데이트 방법은 구현이 간단하지만 주의해서 사용해야 합니다. 특히 데이터 손실을 방지하기 위해 신중하게 접근해야 합니다.

가장 간단한 업데이트 방법은 같은 `namespace`와 `key`로 새로운 값을 저장하는 것입니다. 이는 기존 값을 완전히 새로운 값으로 교체하는 방식입니다. 

왜 이 방법이 간단한가요? `put` 메서드는 같은 키로 데이터를 저장하면 기존 데이터를 덮어씁니다. 따라서 별도의 업데이트 메서드가 필요 없이, 그냥 `put` 메서드를 다시 호출하기만 하면 됩니다.

하지만 주의해야 할 점이 있습니다. 이 방법은 전체 객체를 교체하는 방식이므로, 일부 필드만 업데이트하려고 할 때 나머지 필드도 함께 제공해야 합니다. 만약 일부 필드를 누락하면, 그 필드의 값이 사라질 수 있습니다.

예를들어 사용자 정보에 이름, 나이, 취미가 있는데, 나이만 업데이트하려고 한다면, `{"age": 26}`만 저장하면 이름과 취미가 사라집니다. 올바른 방법은 `{"name": "홍길동", "age": 26, "hobby": "독서"}`처럼 모든 필드를 포함해야 합니다. 다음 예제를 보면, 나이와 취미만 업데이트하려고 하지만, 이름도 함께 제공해야 합니다. 만약 이름을 제공하지 않으면, 이름 필드가 사라질 수 있습니다.

실제 시나리오를 가정해보겠습니다. 온라인 쇼핑몰의 고객 프로필 관리 시스템을 만든다고 생각해봅시다. 고객이 처음 가입할 때 기본 정보를 저장하고, 나중에 정보가 변경되면 업데이트해야 합니다.

단계별로 살펴보겠습니다.

```python
from langgraph.store.memory import InMemoryStore

# Store 생성
store = InMemoryStore()

# 고객 프로필 네임스페이스 설정
customer_id = "customer_12345"
namespace = (customer_id, "profile")
```

먼저 Store와 네임스페이스를 설정합니다. 실제 애플리케이션에서는 고객 ID나 사용자 ID를 사용합니다. 여기서는 `(customer_id, "profile")` 형태로 네임스페이스를 정의했습니다. 이렇게 하면 고객별로 프로필 정보를 독립적으로 관리할 수 있습니다.

```python
# 초기 정보 저장 (고객 가입 시)
store.put(namespace, "customer_profile", {
    "name": "김철수",
    "age": 28,
    "email": "kim@example.com",
    "phone": "010-1234-5678",
    "preferences": {
        "hobby": "독서",
        "favorite_category": "도서",
        "shipping_preference": "일반 배송"
    },
    "created_at": "2024-01-01T10:00:00",
    "last_updated": "2024-01-01T10:00:00"
})

print("✅ 초기 고객 프로필이 저장되었습니다.")
```

초기 고객 정보를 저장합니다. 실제 애플리케이션에서는 고객이 가입할 때 이 정보를 수집합니다. 여기서는 이름, 나이, 이메일, 전화번호, 선호도 정보 등을 저장했습니다. 저장된 정보는 이름이 김철수, 나이가 28, 이메일이 kim@example.com, 전화번호가 010-1234-5678, 선호도가 독서, 도서 카테고리, 일반 배송입니다.

```python
# 정보 업데이트 (고객이 정보를 변경한 경우)
# 예: 고객이 취미에 "영화감상"을 추가하고, 배송 선호도를 변경함
store.put(namespace, "customer_profile", {
    "name": "김철수",  # 이름도 함께 제공해야 함
    "age": 28,  # 나이는 변경 없음
    "email": "kim@example.com",  # 이메일도 함께 제공해야 함
    "phone": "010-1234-5678",  # 전화번호도 함께 제공해야 함
    "preferences": {
        "hobby": "독서, 영화감상",  # 취미에 영화감상 추가
        "favorite_category": "도서",
        "shipping_preference": "빠른 배송"  # 배송 선호도 변경
    },
    "created_at": "2024-01-01T10:00:00",  # 생성 시간 유지
    "last_updated": "2024-01-15T14:30:00"  # 업데이트 시간 변경
})

print("✅ 고객 프로필이 업데이트되었습니다.")
```

같은 키 `"customer_profile"`를 사용하여 정보를 업데이트합니다. 주의할 점은 전체 객체를 제공해야 한다는 것입니다. 변경 사항을 살펴보면, 취미는 "독서"에서 "독서, 영화감상"으로 영화감상이 추가되었고, 배송 선호도는 "일반 배송"에서 "빠른 배송"으로 변경되었으며, 업데이트 시간은 "2024-01-01T10:00:00"에서 "2024-01-15T14:30:00"으로 변경되었습니다.

하지만 이름, 나이, 이메일, 전화번호도 함께 제공해야 합니다. 만약 이 필드들을 생략하면 해당 필드가 사라질 수 있습니다. 예를들어 이름을 생략하면 이름 필드가 `None`이 되거나 사라질 수 있어서, 나중에 "고객님의 이름이 무엇인가요?"라고 물었을 때 답변할 수 없게 됩니다.

```python
# 업데이트된 정보 확인
updated_info = store.get(namespace, "customer_profile")
if updated_info:
    print("\n업데이트된 고객 프로필:")
    print(f"이름: {updated_info.value['name']}")
    print(f"나이: {updated_info.value['age']}")
    print(f"취미: {updated_info.value['preferences']['hobby']}")
    print(f"배송 선호도: {updated_info.value['preferences']['shipping_preference']}")
    print(f"마지막 업데이트: {updated_info.value['last_updated']}")
    print(f"\n전체 프로필 데이터:")
    print(updated_info.value)
```

업데이트된 정보를 확인합니다. `get` 메서드를 사용하여 저장된 정보를 가져옵니다.

실행하면 다음과 같은 결과가 나옵니다:

```
✅ 초기 고객 프로필이 저장되었습니다.
✅ 고객 프로필이 업데이트되었습니다.

업데이트된 고객 프로필:
이름: 김철수
나이: 28
취미: 독서, 영화감상
배송 선호도: 빠른 배송
마지막 업데이트: 2024-01-15T14:30:00

전체 프로필 데이터:
{'name': '김철수', 'age': 28, 'email': 'kim@example.com', 'phone': '010-1234-5678', 'preferences': {'hobby': '독서, 영화감상', 'favorite_category': '도서', 'shipping_preference': '빠른 배송'}, 'created_at': '2024-01-01T10:00:00', 'last_updated': '2024-01-15T14:30:00'}
```

이렇게 업데이트된 정보를 활용하면, 에이전트가 "고객님께서 영화감상을 좋아하신다고 하셨으니, 영화 관련 도서를 추천해드릴게요"와 같이 개인화된 서비스를 제공할 수 있습니다.

이 방법은 작은 객체나 단순한 구조에 적합합니다. 일부 필드만 업데이트해야 할 때는 기존 값을 가져와서 병합한 후 저장하는 것이 좋습니다.

업데이트된 항목의 메타데이터를 확인하여 변경 시점을 추적할 수 있습니다. `get` 메서드로 항목을 가져와서 `created_at`과 `updated_at` 속성을 확인하면 됩니다.

더 이상 필요하지 않은 메모리는 삭제할 수 있습니다. `delete` 메서드를 사용하여 특정 네임스페이스와 키로 메모리를 삭제합니다.

```python
# 메모리 삭제
store.delete(namespace, "user_info")

# 삭제 확인
deleted_item = store.get(namespace, "user_info")
if deleted_item is None:
    print("✅ 메모리가 성공적으로 삭제되었습니다.")
```

`delete` 메서드는 네임스페이스와 키를 인자로 받아서 해당 메모리를 영구적으로 삭제합니다. 삭제된 메모리는 복구할 수 없으므로 주의해서 사용해야 합니다. 메모리 컬렉션을 사용하는 경우, 특정 메모리만 선택적으로 삭제할 수 있어 유연하게 관리할 수 있습니다. 예를들어 사용자가 더 이상 유효하지 않은 선호도를 삭제하거나, 잘못 저장된 정보를 제거할 때 유용합니다.

기본 업데이트의 한계를 살펴보면, 전체 객체를 교체하므로 일부 필드만 수정해도 나머지가 사라질 수 있고, 작은 변경에도 전체 객체를 다시 저장해야 하며, 여러 업데이트가 동시에 발생하면 충돌 가능성이 있습니다. 같은 키로 덮어쓰기를 할 때는 항상 전체 데이터 구조를 포함해야 합니다. 일부 필드만 업데이트하려면 기존 값을 먼저 가져와서 병합해야 합니다.

메모리 컬렉션은 여러 개의 개별 문서로 지속적으로 업데이트되고 확장되는 메모리 관리 방법입니다. 각 메모리는 독립적으로 추가, 수정, 삭제할 수 있어 유연한 업데이트가 가능합니다.

컬렉션의 특징을 살펴보면, 각 메모리가 개별 문서로 저장되고, 새로운 정보가 들어올 때마다 새로운 메모리를 추가하거나 기존 메모리를 업데이트하며, 특정 메모리만 선택적으로 업데이트하거나 삭제할 수 있고, 각 메모리가 좁은 범위로 정의되어 정보 손실이 적습니다.

메모리 컬렉션의 장점은 각 메모리를 독립적으로 처리할 수 있고, 필요에 따라 메모리를 추가하거나 삭제할 수 있으며, 특정 메모리만 수정할 수 있고, 개별 메모리를 검색하고 필터링할 수 있다는 것입니다.

프로파일과 컬렉션을 비교하면, 프로파일은 단일 JSON 문서로 전체 문서를 교체하는 방식이며 복잡도가 낮지만 프로파일이 커질수록 정보 손실 위험이 높고 검색이 단순합니다. 작은 규모의 정보에 적합합니다. 컬렉션은 여러 개별 문서로 개별 문서를 추가, 수정, 삭제하는 방식이며 복잡도가 높지만 각 메모리가 독립적이어서 정보 손실 위험이 낮고 필터링이나 벡터 검색이 필요합니다. 많은 개별 메모리 관리에 적합합니다.

언제 프로파일을 사용하고, 언제 컬렉션을 사용할까요? 프로파일은 사용자 기본 정보(이름, 나이, 이메일 등)처럼 작고 명확하게 정의된 정보에 적합하고, 컬렉션은 대화 기록, 선호도 목록, 할 일 목록처럼 개수가 많고 지속적으로 추가되는 정보에 적합합니다.

메모리 컬렉션을 사용하려면 먼저 스키마를 정의합니다.

```python
from pydantic import BaseModel, Field

class Memory(BaseModel):
    """개별 메모리를 나타내는 스키마"""
    content: str = Field(description="메모리의 주요 내용. 예: '사용자가 치와와를 좋아함'")

class MemoryCollection(BaseModel):
    """메모리 컬렉션을 나타내는 스키마"""
    memories: list[Memory] = Field(description="사용자에 대한 메모리들의 컬렉션")

print("✅ 메모리 스키마 정의 완료")
```

메모리 컬렉션을 저장하고 업데이트하는 방법을 살펴봅시다.

```python
import uuid
from langgraph.store.memory import InMemoryStore
from langchain_core.messages import HumanMessage
from langchain_openai import ChatOpenAI

store = InMemoryStore()
model = ChatOpenAI(model="gpt-4o", temperature=0)

# 구조화된 출력으로 메모리 컬렉션 생성
model_with_structure = model.with_structured_output(MemoryCollection)

# 초기 메모리 생성
memory_collection = model_with_structure.invoke([
    HumanMessage("안녕, 나는 치와와를 좋아하고 취미는 운동이야.")
])

# 각 메모리를 개별적으로 저장
namespace = ("user_001", "memories")
memory_keys = []

for memory in memory_collection.memories:
    key = str(uuid.uuid4())
    memory_keys.append(key)
    store.put(namespace, key, memory.model_dump())
    print(f"메모리 저장: {key} - {memory.content}")

print(f"\n✅ 총 {len(memory_keys)}개의 메모리 저장 완료")
```

메모리 컬렉션의 장점은 특정 메모리만 선택적으로 업데이트할 수 있다는 것입니다.

```python
# 특정 메모리만 업데이트
if memory_keys:
    # 첫 번째 메모리 업데이트
    first_key = memory_keys[0]
    existing_memory = store.get(namespace, first_key)
    
    if existing_memory:
        # 기존 내용 수정
        updated_content = {
            "content": "치와와를 매우 좋아하고 매일 산책을 나갑니다."
        }
        store.put(namespace, first_key, updated_content)
        print(f"✅ 메모리 업데이트 완료: {first_key}")
        
        # 업데이트 확인
        updated_memory = store.get(namespace, first_key)
        print(f"업데이트된 내용: {updated_memory.value['content']}")
```

기존 메모리는 유지하면서 새로운 메모리를 추가할 수 있습니다.

```python
# 새로운 메모리 추가
new_memory = Memory(content="내일은 친구와 저녁약속이 있어.")
new_key = str(uuid.uuid4())
store.put(namespace, new_key, new_memory.model_dump())
print(f"✅ 새 메모리 추가: {new_key} - {new_memory.content}")

# 전체 메모리 확인
all_memories = list(store.search(namespace))
print(f"\n총 메모리 개수: {len(all_memories)}")
for memory in all_memories:
    print(f"- {memory.value['content']}")
```

`with_structured_output`을 사용하여 대화에서 자동으로 메모리를 추출하고 Store에 저장할 수 있습니다. 먼저 메모리를 자동으로 생성하는 방법을 살펴봅시다.

```python
from langchain_core.messages import HumanMessage, AIMessage
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

class Memory(BaseModel):
    content: str = Field(description="메모리의 주요 내용")

model = ChatOpenAI(model="gpt-4o", temperature=0)
model_with_structure = model.with_structured_output(Memory)

# 대화 내용
conversation = [
    HumanMessage(content="안녕, 나는 치와와를 좋아하고 취미는 운동이야."), 
    AIMessage(content="안녕하세요, 치와와를 좋아하고 운동을 취미로 즐기시는군요"), 
    HumanMessage(content="내일은 친구와 저녁약속이 있어.")
]

# 메모리 추출
memory = model_with_structure.invoke(conversation)

# Store에 저장
namespace = ("user_001", "memories")
store.put(namespace, str(uuid.uuid4()), memory.model_dump())

print(f"✅ 메모리 저장: {memory.content}")
```

기존 메모리를 가져와서 새로운 정보와 병합할 수 있습니다.

```python
# 추가 대화 내용
updated_conversation = [
    AIMessage(content="내일 저녁에 일정이 있으시군요!"), 
    HumanMessage(content="응 그리고 내일 모레에는 치과 예약이 있어.")
]

# 기존 메모리 검색
existing_memories = list(store.search(namespace))
context = "\n".join([m.value["content"] for m in existing_memories])

# 컨텍스트와 함께 새 메모리 추출
full_context = f"기존 메모리:\n{context}\n\n새 대화:\n" + "\n".join([msg.content for msg in updated_conversation])
new_memory = model_with_structure.invoke([HumanMessage(content=full_context)])

# 새 메모리 저장
store.put(namespace, str(uuid.uuid4()), new_memory.model_dump())
print(f"✅ 새 메모리 저장: {new_memory.content}")
```


업데이트 전략을 선택할 때는 상황에 따라 다릅니다. 단순한 단일 객체는 같은 키로 덮어쓰기를 사용하고, 여러 개별 항목은 메모리 컬렉션 패턴을 사용하며, 대화에서 자동 추출은 `with_structured_output`을 활용하고, 구조화된 데이터는 Pydantic 모델로 검증 후 업데이트합니다.

이제 저장, 검색, 업데이트의 전체 플로우를 실습해보겠습니다. 먼저 초기 데이터를 저장합니다.

```python
from langgraph.store.memory import InMemoryStore
import uuid

store = InMemoryStore()
namespace = ("user_001", "knowledge_base")

# 초기 지식베이스 구축
knowledge_items = [
    {"topic": "반려동물", "content": "치와와를 키우고 있음"},
    {"topic": "취미", "content": "독서를 좋아함"},
    {"topic": "음식", "content": "비빔밥을 좋아함"},
]

keys = []
for item in knowledge_items:
    key = str(uuid.uuid4())
    keys.append(key)
    store.put(namespace, key, item)

print(f"✅ 초기 지식베이스 저장 완료 ({len(keys)}개 항목)")
```

다음으로 저장된 정보를 검색합니다. `search` 메서드를 사용하여 네임스페이스의 모든 항목을 가져올 수 있습니다.

특정 항목을 업데이트하려면 먼저 `get` 메서드로 기존 항목을 가져온 후, 수정할 내용을 포함한 전체 객체를 `put` 메서드로 저장합니다. 업데이트가 완료되면 다시 `get` 메서드로 확인할 수 있습니다.

새로운 정보를 추가하려면 새로운 키를 생성하여 `put` 메서드로 저장합니다. 최종 상태를 확인하려면 `search` 메서드로 모든 항목을 가져와서 확인하면 됩니다.

상황에 맞는 최적의 업데이트 방법을 선택하는 것이 중요합니다. 단일 객체 전체 교체는 같은 키로 `put()`을 사용하면 간단하고 직관적입니다. 여러 개별 항목 관리는 메모리 컬렉션을 사용하면 유연하고 확장 가능합니다. 대화에서 자동 추출은 `with_structured_output`을 사용하면 편리하고 자동화됩니다. 부분 필드만 수정하려면 기존 값을 가져와서 병합하면 안전하고 간단합니다. 구조화된 데이터 검증은 Pydantic 모델을 사용하면 타입 안전성을 보장할 수 있습니다.

기본 업데이트는 간단하지만 정보 손실 위험이 있습니다. 메모리 컬렉션은 유연하고 확장 가능하며, 자동 업데이트는 편리하지만 제어가 필요합니다. 메모리 컬렉션의 강점은 각 메모리를 독립적으로 처리할 수 있고, 필요에 따라 추가하거나 삭제할 수 있으며, 개별 메모리를 검색하고 필터링할 수 있다는 것입니다. 실무에서는 상황에 맞는 업데이트 방법을 선택하고, `with_structured_output`을 통해 자동화할 수 있습니다. Pydantic을 활용하면 데이터 검증도 쉽게 할 수 있습니다.

이제 지식베이스를 저장, 검색, 업데이트하는 방법을 모두 배웠습니다. 다음 페이지에서는 이러한 지식베이스를 활용하여 SQL 데이터베이스와 상호작용하는 에이전트를 구축해봅시다. 실전 예제를 통해 지금까지 배운 내용을 종합적으로 활용하겠습니다.
