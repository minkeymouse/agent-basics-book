에이전트 지식베이스를 만들고 관리하기 위해서는 먼저 스토어(Store)의 개념을 이해해야 합니다. 스토어는 에이전트가 기억해야 할 정보를 영구적으로 보관하는 저장소입니다. 마치 인간의 장기 기억과 같은 역할을 하며, 대화가 끝나도 프로그램이 재시작되어도 사라지지 않는 정보를 담고 있습니다. 4장에서 본 체크포인트가 “에이전트의 단기 메모장”이라면, Store는 “오랫동안 보관하고 싶은 기록을 모아두는 파일 캐비닛”에 가깝습니다.

LangGraph v1는 메모리 스토어(Memory Store)라는 기능을 제공합니다. 스토어는 정보를 저장하는 객체로, 네임스페이스(namespace), 키(key) 그리고 값(value)으로 이루어집니다. 

스토어는 단순한 데이터베이스가 아닙니다. 에이전트가 사용자와의 대화에서 얻은 정보, 선호도, 과거 경험 등을 체계적으로 저장하고 관리할 수 있게 해주는 구조화된 저장 시스템입니다. 예를들어 사용자가 "나는 치와와를 좋아해"라고 말했다면, 이 정보를 스토어에 저장해두고 나중에 "강아지에 대한 추천을 해줘"라고 물었을 때 활용할 수 있습니다.

지식베이스에 객체를 저장할 때에는 [put](https://langchain-ai.github.io/langgraph/reference/store/#langgraph.store.base.BaseStore.put) 메소드로 `namespace`와 `key`를 활용해 객체를 저장합니다. 네임스페이스는 마치 폴더처럼 관련된 정보들을 그룹화하는 역할을 하며, 키는 그 안에서 특정 정보를 식별하는 고유한 식별자입니다. 마찬가지로 메모리를 검색할 때에는 `search(namespace)`와 `get(namespace, key)` 메소드를 활용하게 됩니다. 얼마나 구체적으로 검색하고싶은지에 따라 다른 메소드를 활용합니다.

예를들어 사용자별로 정보를 분리하고 싶다면 `("user_001", "preferences")`와 같은 네임스페이스를 사용할 수 있고, 특정 사용자의 선호도를 찾고 싶다면 `get(("user_001", "preferences"), "favorite_pet")`와 같이 정확한 키를 사용할 수 있습니다. 반면에 사용자의 모든 선호도를 보고 싶다면 `search(("user_001", "preferences"))`를 사용하여 해당 네임스페이스의 모든 정보를 가져올 수 있습니다.

메모리 스토어의 구조를 도식화 해 보면 다음과 같습니다. 메모리 스토어는 여러 네임스페이스로 구성되어 있고, 각 네임스페이스 안에는 여러 키와 값이 저장됩니다. 예를들어 사용자별, 카테고리별로 네임스페이스를 나눌 수 있고, 각 네임스페이스 안에는 key1, key2 등으로 정보가 저장됩니다.

이제 본격적으로 지식베이스를 만들어 보겠습니다. 초급자도 쉽게 따라할 수 있도록 `InMemoryStore`를 사용하겠습니다. `InMemoryStore`는 메모리에 데이터를 저장하므로 별도의 데이터베이스 설치 없이 바로 사용할 수 있습니다.

먼저 필요한 패키지를 설치해봅시다:

```bash
pip install -U langgraph
```

LangGraph에는 두 가지 종류의 메모리가 있습니다. 하나는 단기 메모리인 Checkpointer이고, 다른 하나는 장기 메모리인 Store입니다. Checkpointer는 대화 세션의 상태를 저장하는데, 이는 2장에서 학습한 내용입니다. Store는 사용자 정보, 선호도 등 영구적으로 보관할 정보를 저장하는데, 이번 장에서 학습하는 내용입니다.

Checkpointer와 Store는 서로 다른 목적으로 함께 작동합니다. Checkpointer는 특정 대화 스레드(thread)의 상태를 저장합니다. 예를들어 한 대화 세션에서 주고받은 메시지들을 저장하여, 나중에 같은 스레드에서 대화를 이어갈 수 있게 해줍니다. 반면에 Store는 스레드와 무관하게 사용자별로 정보를 저장하고 검색할 수 있습니다.

예를들어 사용자가 "나는 치와와를 좋아해"라고 말한 정보는 Store에 저장되어, 나중에 다른 대화 세션(다른 thread_id)에서도 활용할 수 있습니다. 같은 사용자 ID를 사용하면, 어떤 스레드에서든 그 사용자의 정보를 가져올 수 있습니다. 

이제 실제로 지식베이스를 구축해봅시다. 지식베이스는 단순히 데이터를 저장하는 것이 아니라, 에이전트가 사용자에 대해 알고 있는 모든 정보를 체계적으로 관리하는 시스템입니다. 사용자의 선호도, 과거 대화 내용, 개인 정보 등이 모두 지식베이스에 저장되며, 에이전트는 이를 바탕으로 더 개인화된 응답을 제공할 수 있습니다.

`InMemoryStore`는 가장 간단한 스토어입니다. 별도의 데이터베이스 설치 없이 바로 사용할 수 있어 초급자에게 적합합니다.

```python
from langgraph.store.memory import InMemoryStore

# 메모리 스토어 생성
store = InMemoryStore()
print("✅ 스토어 생성 완료!")
```

이렇게 하면 지식베이스를 사용할 준비가 완료됩니다. `InMemoryStore`는 프로그램이 종료되면 데이터가 사라지지만, 학습 목적으로는 충분합니다.

지식베이스의 기본 단위는 `namespace` 입니다. 네임스페이스는 마치 파일 시스템의 디렉토리처럼, 관련된 정보들을 논리적으로 그룹화하는 역할을 합니다. 예를들어 사용자별로 정보를 분리하거나 정보의 유형별로 분리할 수 있습니다.

`namespace`를 기준으로 사용자의 필요에 따라 지식을 계층적으로 구조화해서 저장할 수 있습니다. 튜플로 `namespace`를 지정하여 지식을 계층화 할 수도 있습니다. 예를들어 `("user_001", "preferences")`는 사용자 001의 선호도를 나타내고, `("user_001", "conversations")`는 사용자 001의 대화 기록을 나타낼 수 있습니다. 

이런 계층적 구조는 여러 가지 장점이 있습니다. 관련된 정보를 논리적으로 그룹화하여 관리하기 쉽고, 특정 사용자나 카테고리의 정보만 검색할 수 있어 효율적입니다. 또한 권한 관리가 용이합니다. 예를들어 사용자는 자신의 정보만 접근할 수 있도록 제한할 수 있습니다.

네임스페이스는 튜플로 표현되며, 각 요소는 계층의 한 단계를 나타냅니다. 예를들어 `("users", "user_001", "preferences")`는 세 단계의 계층 구조를 나타냅니다. 첫 번째 레벨은 전체 사용자 그룹, 두 번째 레벨은 특정 사용자, 세 번째 레벨은 선호도 정보를 나타냅니다.

이제 실제로 메모리를 저장해보겠습니다. 실제 시나리오를 가정해보겠습니다. 온라인 쇼핑몰의 고객 서비스 에이전트를 만든다고 생각해봅시다. 고객이 "나는 작은 강아지를 키우고 있어. 매일 산책을 나가는데, 강아지용 장난감을 추천해줘"라고 말했다면, 이 정보를 Store에 저장해두고 나중에 활용할 수 있습니다.

단계별로 하나씩 살펴보겠습니다.

```python
# 필요한 라이브러리 임포트
import uuid
from langgraph.store.memory import InMemoryStore

# 메모리 스토어 인스턴스 생성
memory_store = InMemoryStore()
```

먼저 `InMemoryStore`를 임포트하고 인스턴스를 생성합니다. 이 스토어는 메모리에 데이터를 저장하므로 프로그램이 종료되면 데이터가 사라집니다. 하지만 학습 목적으로는 충분하며, 별도의 데이터베이스 설정 없이 바로 사용할 수 있습니다. 실제 프로덕션 환경에서는 PostgreSQL이나 Redis 같은 영구 저장소를 사용하는 것이 좋습니다.

```python
# 실제 사용 시나리오: 온라인 쇼핑몰 고객 서비스
# 고객 ID를 사용하여 사용자별로 정보를 분리
customer_id = "customer_12345"
memory_namespace = (customer_id, "preferences")
```

다음으로 네임스페이스를 정의합니다. 실제 애플리케이션에서는 고객 ID나 사용자 ID를 사용합니다. 여기서는 `(customer_id, "preferences")` 형태로 네임스페이스를 정의했습니다. 첫 번째 요소는 고객 식별자이고, 두 번째 요소는 메모리 유형입니다. 

이렇게 하면 같은 고객의 다른 유형의 메모리를 구분할 수 있습니다. 예를들어 `(customer_id, "preferences")`는 고객의 선호도 정보를, `(customer_id, "purchase_history")`는 구매 이력을, `(customer_id, "support_tickets")`는 고객 지원 티켓을 나타냅니다. 각각 독립적으로 관리할 수 있어서, 선호도만 검색하거나 구매 이력만 검색하는 것이 가능합니다.

```python
# 고유 키 생성
# 실제로는 대화 내용이나 시간 기반으로 키를 생성할 수도 있습니다
memory_key = str(uuid.uuid4())
```

각 메모리는 고유한 키를 가져야 합니다. `uuid.uuid4()`는 랜덤한 고유 식별자를 생성합니다. 이를 문자열로 변환하여 키로 사용합니다. 

실제로는 다양한 방식으로 키를 생성할 수 있습니다. UUID를 사용하면 완전히 랜덤한 키를 만들 수 있고, 타임스탬프 기반으로 시간을 포함한 키를 만들 수도 있습니다. 내용 기반으로 메모리 내용의 해시값을 키로 사용할 수도 있습니다.

키는 같은 네임스페이스 내에서 메모리를 구분하는 역할을 합니다. 같은 네임스페이스에 같은 키로 저장하면 기존 메모리가 덮어써집니다.

```python
# 저장할 데이터
# 고객이 제공한 정보를 구조화하여 저장
memory_data = {
    "pet_type": "강아지",
    "pet_size": "작은 강아지",
    "pet_activity": "매일 산책",
    "interests": ["강아지용 장난감"],
    "timestamp": "2024-01-15T14:30:00",
    "source": "고객 대화"
}
```

저장할 데이터를 딕셔너리 형태로 정의합니다. 실제 애플리케이션에서는 고객이 제공한 정보를 구조화하여 저장합니다. 이 데이터는 반려동물 종류(`pet_type`), 반려동물 크기(`pet_size`), 반려동물 활동 패턴(`pet_activity`), 관심사 목록(`interests`), 정보가 수집된 시간(`timestamp`), 정보 출처(`source`) 등의 정보를 담고 있습니다.

이렇게 구조화하면 나중에 검색하거나 필터링할 때 유용합니다. 예를들어 "작은 강아지를 키우는 고객"을 찾거나, "산책을 나가는 고객"을 찾을 수 있습니다.

```python
# 메모리 스토어에 데이터 저장
memory_store.put(memory_namespace, memory_key, memory_data)
print(f"✅ 메모리 저장 완료: 키={memory_key}")
print(f"   네임스페이스: {memory_namespace}")
print(f"   저장된 데이터: {memory_data}")
```

마지막으로 `put` 메서드를 사용하여 데이터를 저장합니다. `put` 메서드는 세 가지 인자를 받습니다. 첫 번째는 메모리를 그룹화하는 네임스페이스로 튜플 형태입니다. 두 번째는 메모리를 식별하는 고유 키로 문자열입니다. 세 번째는 저장할 실제 데이터로 딕셔너리 또는 다른 JSON 직렬화 가능한 객체입니다.

실행하면 다음과 같은 결과가 나옵니다:

```
✅ 메모리 저장 완료: 키=a1b2c3d4-e5f6-7890-abcd-ef1234567890
   네임스페이스: ('customer_12345', 'preferences')
   저장된 데이터: {'pet_type': '강아지', 'pet_size': '작은 강아지', ...}
```

이렇게 하면 메모리가 성공적으로 저장됩니다! 나중에 이 고객이 다시 접속했을 때, Store에서 이 정보를 가져와서 개인화된 추천을 제공할 수 있습니다.

저장한 정보를 다시 찾아오는 것은 지식베이스의 핵심 기능입니다. LangGraph Store는 다양한 방법으로 저장된 정보를 검색할 수 있게 해줍니다.

`search` 메서드를 사용하여 `namespace`로 스토어에서 객체를 검색합니다. 이 메서드는 해당 네임스페이스에 저장된 모든 항목을 반환합니다. 반면에 정확한 키를 알고 있다면 `get` 메서드를 사용하여 더 빠르게 특정 항목을 가져올 수 있습니다. 이 메서드는 리스트를 반환하며, 리스트의 각 항목은 `StoreValue` 객체로, 실제 데이터뿐만 아니라 메타데이터(생성 시간, 수정 시간 등)도 포함하고 있습니다.

LangGraph Store는 두 가지 기본적인 검색 방법을 제공합니다. 하나는 `search(namespace)`로 특정 네임스페이스의 모든 메모리를 검색하는 방법입니다. 네임스페이스에 저장된 모든 항목을 반환하므로 데이터가 많을 경우 성능에 영향을 줄 수 있지만, 전체 목록이 필요할 때 사용합니다. 다른 하나는 `get(namespace, key)`로 특정 네임스페이스와 키로 정확한 메모리를 검색하는 방법입니다. 정확한 키를 알고 있을 때 가장 빠른 방법이며, 단일 항목만 반환하므로 효율적입니다. 특정 정보를 찾을 때 사용합니다.

이제 저장한 메모리를 검색해보겠습니다. 실제 시나리오를 생각해보면, 고객이 다시 접속했을 때 "이전에 말씀하신 강아지 정보를 기억하고 있어요"라고 말할 수 있도록, Store에서 해당 고객의 정보를 가져와야 합니다.

`search` 메서드를 사용하면 특정 네임스페이스에 저장된 모든 메모리를 가져올 수 있습니다.

```python
# 네임스페이스로 메모리 검색
# 고객의 선호도 정보를 모두 가져옵니다
retrieved_memories = memory_store.search(memory_namespace)
print(f"검색된 메모리 개수: {len(retrieved_memories)}개")
```

`search` 메서드는 네임스페이스를 인자로 받아서, 해당 네임스페이스에 저장된 모든 메모리를 리스트로 반환합니다. 만약 해당 네임스페이스에 메모리가 없다면 빈 리스트가 반환됩니다.

실제로는 고객이 여러 번 대화를 나누면서 여러 개의 메모리가 저장될 수 있습니다. 예를들어 첫 번째 대화에서는 "작은 강아지를 키우고 있음"이라는 정보가 저장되고, 두 번째 대화에서는 "매일 산책을 나감"이라는 정보가 저장되며, 세 번째 대화에서는 "강아지용 장난감에 관심 있음"이라는 정보가 저장될 수 있습니다. 이런 메모리들이 모두 같은 네임스페이스에 저장되어 있다면, `search` 메서드로 모두 가져올 수 있습니다.

```python
# 검색된 메모리들의 내용 확인
print(f"\n고객 {customer_id}의 선호도 정보:")
for i, memory in enumerate(retrieved_memories, 1):
    print(f"\n메모리 {i}:")
    print(f"  키: {memory.key}")
    print(f"  저장 시간: {memory.created_at}")
    print(f"  내용:")
    for key, value in memory.value.items():
        print(f"    - {key}: {value}")
```

검색된 각 메모리는 `StoreValue` 객체입니다. 이 객체는 메모리의 고유 키(`key`), 저장된 실제 데이터(`value`, 딕셔너리 형태), 메모리가 속한 네임스페이스(`namespace`), 메모리가 생성된 시간(`created_at`), 메모리가 마지막으로 수정된 시간(`updated_at`) 등의 속성을 가지고 있습니다.

실행하면 다음과 같은 결과가 나옵니다:

```
검색된 메모리 개수: 1개

고객 customer_12345의 선호도 정보:

메모리 1:
  키: a1b2c3d4-e5f6-7890-abcd-ef1234567890
  저장 시간: 2024-01-15 14:30:00
  내용:
    - pet_type: 강아지
    - pet_size: 작은 강아지
    - pet_activity: 매일 산책
    - interests: ['강아지용 장난감']
    - timestamp: 2024-01-15T14:30:00
    - source: 고객 대화
```

이렇게 검색된 정보를 활용하면, 에이전트가 고객에게 "이전에 말씀하신 작은 강아지를 위한 장난감을 추천해드릴게요"와 같이 개인화된 응답을 할 수 있습니다.

`StoreValue` 객체를 딕셔너리로 변환하려면 `.dict()` 메서드를 사용할 수 있습니다. 이렇게 하면 모든 속성을 딕셔너리 형태로 가져올 수 있어서, JSON으로 직렬화하거나 다른 용도로 활용하기 편리합니다.

```python
# StoreValue를 딕셔너리로 변환
memory_dict = memory.dict()
print(memory_dict)
```

이렇게 하면 저장한 메모리의 모든 정보를 확인할 수 있습니다!

`get` 메서드를 사용하여 `namespace`와 `key`로 객체를 검색할 수도 있습니다. `search` 메서드는 네임스페이스의 모든 메모리를 리스트로 반환하는 반면, `get` 메서드는 특정 메모리를 단일 객체 또는 None으로 반환합니다. 정확한 키를 알고 있다면 `get` 메서드를 사용하여 더 빠르게 특정 메모리를 가져올 수 있습니다.

```python
# 특정 키로 메모리 조회
specific_memory = memory_store.get(memory_namespace, memory_key)
```

`get` 메서드는 두 가지 인자를 받습니다. 첫 번째는 메모리가 속한 네임스페이스이고, 두 번째는 찾고자 하는 메모리의 고유 키입니다. 만약 해당 키의 메모리가 존재한다면 `StoreValue` 객체를 반환하고, 존재하지 않는다면 `None`을 반환합니다.

```python
if specific_memory:
    print("✅ 메모리 조회 성공!")
    print(f"  네임스페이스: {specific_memory.namespace}")
    print(f"  키: {specific_memory.key}")
    print(f"  값: {specific_memory.value}")
    print(f"  생성시간: {specific_memory.created_at}")
    print(f"  수정시간: {specific_memory.updated_at}")
else:
    print("❌ 메모리를 찾을 수 없습니다.")
```

메모리가 존재하는지 확인한 후, 각 속성을 출력합니다. `get` 메서드는 `search` 메서드보다 훨씬 빠릅니다. 왜냐하면 전체 네임스페이스를 검색하는 대신, 정확한 키로 바로 접근하기 때문입니다. 따라서 키를 알고 있다면 `get` 메서드를 사용하는 것이 좋습니다.

저장된 메모리는 메모리가 속한 네임스페이스(`namespace`), 메모리의 고유 키(`key`), 메모리의 실제 데이터(`value`), 메모리 생성 시간(`created_at`), 메모리 마지막 수정 시간(`updated_at`), 메모리의 점수(`score`, 벡터 검색 시 사용) 등의 메타데이터를 포함합니다.

네임스페이스를 사용하면 사용자별로 메모리를 분리하거나 메모리 유형에 따라 체계적으로 관리할 수 있습니다. 새로운 사용자나 카테고리를 추가하는 것도 쉽습니다. 메타데이터를 통해 메모리가 언제 생성되었는지, 마지막으로 언제 수정되었는지 추적할 수 있습니다. 벡터 검색을 사용하는 경우 점수 시스템으로 메모리의 중요도나 관련성을 평가할 수도 있습니다. 검색할 때는 `search` 메서드로 네임스페이스의 모든 메모리를 조회하거나, `get` 메서드로 키를 통해 정확한 메모리에 접근할 수 있습니다. 필요에 따라 조건에 따라 메모리를 필터링할 수도 있습니다.

이제 메모리 스토어의 기본 개념을 이해했습니다. 다음으로 메모리 프로파일을 활용하여 사용자 정보를 구조화된 데이터로 저장하고 관리하는 방법을 학습합니다.

지금까지는 단순한 딕셔너리 형태로 데이터를 저장했습니다. 하지만 실제 애플리케이션에서는 사용자 정보를 더 구조화된 형태로 관리해야 합니다. 예를들어 사용자의 이름, 나이, 취미, 선호도 등을 각각의 필드로 구분하여 저장하고, 타입 검증을 통해 데이터의 정확성을 보장해야 합니다.

메모리 프로파일을 사용하여 사용자 정보를 구조화된 데이터로 저장하고 관리하는 방법을 배워봅시다. 메모리 프로파일은 Pydantic 모델이나 TypedDict를 사용하여 데이터 구조를 정의하고, 이를 통해 타입 안전성과 데이터 검증을 보장합니다.

메모리 프로파일을 이해하기 위해 몇 가지 개념을 알아야 합니다. 구조화된 저장은 문자열 형태가 아닌 스키마 기반 프로필로 관리하는 것입니다. 단순 문자열 대신 구조화된 객체로 저장하여 데이터의 일관성을 보장하고, 스키마를 정의함으로써 어떤 필드가 있는지, 각 필드의 타입이 무엇인지 명확히 할 수 있습니다. 예를들어 사용자 프로필에는 `name`(문자열), `age`(정수), `hobby`(문자열 리스트) 등의 필드가 있을 수 있습니다.

프로필 업데이트는 새로운 정보가 들어오면 기존 프로필을 업데이트하는 것입니다. 사용자가 새로운 정보를 제공하면, 기존 프로필에 추가하거나 수정해야 합니다. 예를들어 사용자가 처음에는 "독서를 좋아함"이라고 했지만, 나중에 "독서와 영화감상을 좋아함"으로 변경했다면, 프로필을 업데이트해야 합니다.

자동 업데이트는 LLM을 활용하여 대화에서 자동으로 정보를 추출하고 프로필을 업데이트하는 것입니다. `with_structured_output`을 사용하여 대화 내용에서 구조화된 정보를 추출하고, 추출한 정보를 기존 프로필과 병합하여 업데이트합니다.

프로필 병합은 기존 프로필을 가져와서 새로운 정보와 합치는 것입니다. 기존 정보를 보존하면서 새로운 정보를 추가하는 방법입니다. 예를들어 나이만 변경하려면 기존 프로필을 가져와서 나이만 수정한 후 다시 저장합니다.

먼저 스키마를 정의하겠습니다. 스키마는 데이터의 구조를 정의하는 것으로, 어떤 필드가 있는지, 각 필드의 타입이 무엇인지를 명시합니다. 

왜 스키마가 필요할까요? 단순한 딕셔너리로 데이터를 저장하면, 나중에 실수로 잘못된 필드명을 사용하거나, 잘못된 타입의 값을 저장할 수 있습니다. 예를들어 나이를 저장할 때 실수로 문자열 "25"를 저장하는 대신 정수 25를 저장해야 하는데, 스키마가 없으면 이런 실수를 방지하기 어렵습니다.

스키마를 정의하면 타입 체커가 코드를 분석할 때 도움을 주고, 개발자가 실수로 잘못된 필드명이나 타입을 사용하는 것을 방지할 수 있으며, 코드를 읽는 사람이 데이터 구조를 쉽게 이해할 수 있습니다.

Python에서는 `TypedDict`나 Pydantic의 `BaseModel`을 사용하여 스키마를 정의할 수 있습니다. 여기서는 `TypedDict`를 사용하겠습니다.

`TypedDict`는 Python 3.8부터 도입된 기능으로, 딕셔너리의 구조를 타입 힌트로 정의할 수 있게 해줍니다. 일반 딕셔너리처럼 사용할 수 있지만, 타입 정보를 제공하여 더 안전하게 코드를 작성할 수 있습니다.

다음 예제에서는 할 일 항목을 나타내는 스키마를 정의합니다. 각 할 일 항목은 제목, 설명, 완료 여부, 우선순위, 마감일 등의 정보를 포함합니다.

```python
# 스키마 정의
from typing import TypedDict

class ToDoItem(TypedDict):
    title: str          # 할 일의 제목
    description: str     # 할 일에 대한 상세 설명
    completed: bool      # 완료 여부 (True 또는 False)
    priority: str        # 우선순위 (예: "high", "medium", "low")
    due_date: str        # 마감일 (예: "2024-12-31")
```

이 스키마를 사용하면, 할 일 항목을 저장할 때 항상 이 구조를 따르도록 보장할 수 있습니다. 각 필드의 의미를 살펴보면, `title`은 할 일의 제목으로 문자열이고, `description`은 할 일에 대한 상세 설명으로 문자열입니다. `completed`는 완료 여부로 불리언(True 또는 False)이고, `priority`는 우선순위로 문자열(예: "high", "medium", "low")이며, `due_date`는 마감일로 문자열(예: "2024-12-31")입니다.

예를들어 `completed` 필드에 문자열을 저장하려고 하면 타입 체커가 경고를 표시할 수 있습니다. 이렇게 하면 데이터의 일관성을 유지할 수 있습니다.

스키마를 정의했으니, 이제 이 스키마에 맞는 데이터를 생성해봅시다. `TypedDict`로 정의한 스키마는 일반 딕셔너리처럼 사용할 수 있지만, 타입 힌트를 통해 구조를 보장받을 수 있습니다. 다음 예제에서는 할 일 항목을 생성하고, 그 내용을 출력합니다. 각 필드는 스키마에서 정의한 타입에 맞게 값을 할당해야 합니다.

```python
# 할 일 인스턴스 생성
sample_todo: ToDoItem = {
    "title": "강아지 산책시키기",
    "description": "집 주변 공원에서 강아지를 산책시키기",
    "completed": False,
    "priority": "high",
    "due_date": "2024-12-31"
}

print(f"할 일: {sample_todo['title']}")
print(f"완료 여부: {sample_todo['completed']}")
```

이렇게 생성한 할 일 항목은 스키마에 정의된 모든 필드를 포함하고 있으며, 각 필드의 타입도 올바릅니다. 이 데이터를 스토어에 저장하면, 나중에 검색하거나 업데이트할 때도 이 구조를 유지할 수 있습니다.

네임스페이스를 사용하여 사용자별 데이터를 분리하여 메모리 저장소에 저장할 수 있습니다. 메모리는 `put` 메소드를 통해 저장합니다.

```python
# 메모리 저장소 설정
from langgraph.store.memory import InMemoryStore

memory_store = InMemoryStore()
namespace = ("user_001", "todo_memory")
memory_store.put(namespace, "sample_todo", dict(sample_todo))

print("✅ 데이터 저장 완료")
```

`search`와 `get` 메소드를 통해 저장된 데이터를 검색하고 조회할 수 있습니다.

```python
# 데이터 검색
search_results = list(memory_store.search(namespace))
print(f"검색된 데이터: {len(search_results)}개")

for item in search_results:
    data = item.dict()
    print(f"키: {data['key']}")
    print(f"데이터: {data['value']}")

# 특정 데이터 가져오기
todo_item = memory_store.get(namespace, "sample_todo")

if todo_item:
    data = todo_item.value
    print(f"제목: {data['title']}")
    print(f"완료 여부: {'완료' if data['completed'] else '미완료'}")
else:
    print("❌ 데이터 없음")
```

LLM은 기본적으로 자유 형식의 텍스트를 생성합니다. 하지만 애플리케이션에서는 종종 구조화된 데이터가 필요합니다. 예를들어 사용자가 "강아지 산책시키기"라고 말했을 때, 이를 할 일 항목으로 변환하여 저장하고 싶을 수 있습니다.

구조화된 출력 메소드인 `with_structured_output`을 활용하면 모델의 결과값을 스키마에 맞게 가져올 수 있습니다. 이 메서드는 LLM이 생성한 텍스트를 자동으로 파싱하여 정의한 스키마에 맞는 객체로 변환해줍니다. `with_structured_output`은 Pydantic 모델을 사용합니다. Pydantic은 데이터 검증과 직렬화를 위한 라이브러리로, 런타임에 데이터의 타입과 구조를 검증할 수 있습니다. `Field`를 사용하여 각 필드에 대한 설명을 추가하면 LLM이 더 정확하게 데이터를 추출할 수 있습니다.

```python
# with_structured_output 기본 사용법
from langchain_core.messages import HumanMessage
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

class ToDo(BaseModel):
    title: str = Field(description="할 일 제목")
    description: str = Field(description="할 일 설명")
    completed: bool = Field(default=False, description="완료 여부")
    priority: str = Field(description="우선순위: high, medium, low")

model = ChatOpenAI(model="gpt-4o", temperature=0)
model_with_structure = model.with_structured_output(ToDo)

result = model_with_structure.invoke([HumanMessage("강아지 산책시키기")])
print(f"결과: {result}")
print("✅ 장점: 간단하고 직관적")
```

이 코드를 실행하면, LLM은 "강아지 산책시키기"라는 입력을 받아서 `ToDo` 스키마에 맞는 객체를 생성합니다. `title` 필드에는 "강아지 산책시키기"가 들어가고, `description` 필드에는 LLM이 생성한 설명이 들어갑니다. `completed`는 기본값인 `False`로 설정되고, `priority`는 LLM이 판단한 우선순위가 들어갑니다.

이 방법의 장점은 간단하고 직관적이라는 것입니다. LLM에게 스키마만 제공하면 자동으로 구조화된 데이터를 생성해줍니다.

메모리 프로파일을 업데이트할 때는 기존 프로필을 가져와서 새로운 정보와 병합해야 합니다. `with_structured_output`을 사용할 때는 매번 전체 프로필을 새로 생성하므로, 기존 정보를 보존하려면 명시적으로 병합 로직을 구현해야 합니다.

```python
# 기존 프로필 가져오기
existing_profile = store.get(namespace, "user_profile")
if existing_profile:
    # 기존 정보와 새 정보 병합
    updated_profile = {**existing_profile.value, **new_info}
    store.put(namespace, "user_profile", updated_profile)
else:
    # 새 프로필 생성
    store.put(namespace, "user_profile", new_info)
```

프로필을 업데이트할 때는 항상 기존 정보를 가져와서 새로운 정보와 병합한 후 저장해야 합니다. 이렇게 하면 정보 손실을 방지할 수 있습니다.

TypedDict나 Pydantic 모델을 사용하면 타입 안전한 데이터 구조를 정의할 수 있고, 자동 검증 및 직렬화를 지원받을 수 있습니다. 스키마 기반으로 저장하면 일관된 데이터 형식을 보장할 수 있습니다. 프로파일을 업데이트할 때는 전체 교체 방식이 간단하지만 정보 손실 위험이 있으므로, 기존 정보와 새 정보를 병합하는 방법을 사용하는 것이 좋습니다. 네임스페이스를 활용하여 사용자별로 데이터를 분리하고, `search`와 `get` 메서드를 효율적으로 활용하면 됩니다. 메타데이터를 통해 생성 시간과 수정 시간을 추적할 수 있습니다.

LangGraph의 StateGraph를 사용할 때 Store를 통합하면, 노드에서 지식베이스에 접근할 수 있습니다. 이제 실제로 LangGraph 에이전트에서 Store를 사용하는 방법을 배워봅시다.

LangGraph의 노드 함수는 `store`와 `config`를 인자로 받을 수 있습니다. 이를 통해 노드 내에서 Store에 접근하여 메모리를 저장하거나 검색할 수 있습니다.

```python
from langgraph.graph import StateGraph, MessagesState
from langgraph.store.base import BaseStore
from langchain_core.runnables import RunnableConfig
from langchain_core.messages import HumanMessage, AIMessage
from langchain_openai import ChatOpenAI

# Store 생성
from langgraph.store.memory import InMemoryStore
store = InMemoryStore()

# LLM 초기화
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
```

먼저 Store와 LLM을 초기화합니다.

```python
def assistant_with_memory(
    state: MessagesState, 
    config: RunnableConfig, 
    *, 
    store: BaseStore
):
    """Store를 사용하는 Assistant 노드"""
    
    # 사용자 ID 가져오기 (config에서)
    # config는 RunnableConfig 타입이며, configurable 딕셔너리에 사용자 정보가 저장됩니다
    user_id = config.get("configurable", {}).get("user_id", "default_user")
    
    # 네임스페이스 정의
    # 사용자별로 메모리를 분리하기 위해 (user_id, "memories") 형태로 네임스페이스를 정의합니다
    namespace = (user_id, "memories")
    
    # Store에서 관련 메모리 검색
    # search 메서드는 해당 네임스페이스의 모든 메모리를 반환합니다
    memories = list(store.search(namespace))
    
    # 메모리를 컨텍스트로 추가
    # 검색된 메모리를 LLM에게 전달하기 위해 컨텍스트 문자열로 변환합니다
    context = ""
    if memories:
        context = "\n\n사용자에 대한 정보:\n"
        for memory in memories[:3]:  # 최대 3개만 사용 (너무 많으면 컨텍스트가 길어짐)
            # memory.value는 저장된 실제 데이터입니다
            if isinstance(memory.value, dict):
                context += f"- {memory.value.get('content', memory.value)}\n"
            else:
                context += f"- {memory.value}\n"
    
    # 시스템 메시지에 메모리 정보 추가
    # 검색된 메모리를 시스템 프롬프트에 포함시켜 LLM이 사용자 정보를 참고할 수 있게 합니다
    system_prompt = f"""당신은 사용자 정보를 기억하는 도우미입니다.
{context}
사용자의 질문에 답변하고, 필요하면 새로운 정보를 Store에 저장하세요."""
    
    # LLM 호출 (SystemMessage 사용)
    from langchain_core.messages import SystemMessage
    messages = state["messages"]
    system_msg = SystemMessage(content=system_prompt)
    response = llm.invoke([system_msg] + messages)
    
    return {"messages": [response]}
```

이 노드는 다음과 같은 작업을 수행합니다. 먼저 `config["configurable"]["user_id"]`로 현재 사용자의 ID를 가져옵니다. 만약 `user_id`가 없으면 "default_user"를 사용합니다. 다음으로 `(user_id, "memories")` 형태로 네임스페이스를 정의합니다. 이렇게 하면 사용자별로 메모리를 분리할 수 있습니다. 그 다음 `store.search(namespace)`를 사용하여 해당 사용자의 모든 메모리를 가져옵니다. 검색 결과는 `StoreValue` 객체의 리스트입니다. 검색된 메모리를 문자열로 변환하여 LLM에게 전달할 컨텍스트를 만듭니다. 최대 3개만 사용하여 컨텍스트 길이를 제한합니다. 마지막으로 시스템 메시지에 메모리 정보를 포함시켜 LLM을 호출합니다. LLM은 사용자의 과거 정보를 참고하여 더 개인화된 답변을 생성할 수 있습니다.

왜 이렇게 하나요? 사용자가 "강아지에 대한 추천을 해줘"라고 질문했을 때, Store에 "치와와를 좋아함"이라는 정보가 있다면, LLM은 이를 참고하여 "치와와에 대한 정보를 알려드리겠습니다"와 같이 개인화된 답변을 할 수 있습니다. 이렇게 하면 매번 사용자 정보를 다시 물어볼 필요가 없습니다.

```python
def save_memory(
    state: MessagesState,
    config: RunnableConfig,
    *,
    store: BaseStore
):
    """대화 내용에서 정보를 추출하여 Store에 저장하는 노드"""
    
    user_id = config.get("configurable", {}).get("user_id", "default_user")
    namespace = (user_id, "memories")
    
    # 마지막 메시지 확인
    last_message = state["messages"][-1]
    
    # 사용자가 새로운 정보를 제공했는지 확인
    if isinstance(last_message, HumanMessage):
        # 간단한 예제: "나는 치와와를 좋아해" 같은 패턴 감지
        content = last_message.content
        if "좋아" in content or "선호" in content:
            # 메모리로 저장
            import uuid
            memory_id = str(uuid.uuid4())
            store.put(namespace, memory_id, {"content": content})
            print(f"✅ 메모리 저장: {content}")
    
    return state
```

이 노드는 대화 내용에서 중요한 정보를 추출하여 Store에 저장합니다. 작동 원리를 살펴보면, 먼저 마지막 메시지가 사용자 메시지인지 확인합니다. 다음으로 간단한 예제로 "좋아"나 "선호" 같은 키워드를 감지합니다. 마지막으로 감지된 정보를 Store에 저장합니다.

실제 사용 시에는 이렇게 간단한 패턴 매칭 대신, `with_structured_output`을 사용하여 더 정교하게 정보를 추출할 수 있습니다. 예를들어 사용자가 "나는 치와와를 좋아하고 비빔밥을 즐겨 먹어"라고 말했을 때, 자동으로 취미와 음식 선호도를 분리하여 저장할 수 있습니다. 이는 앞서 배운 메모리 프로파일 섹션에서 다룬 내용입니다.

```python
from langgraph.graph import START, END

# 그래프 구성
builder = StateGraph(MessagesState)

# 노드 추가
builder.add_node("assistant", assistant_with_memory)
builder.add_node("save_memory", save_memory)

# 엣지 정의
builder.add_edge(START, "assistant")
builder.add_edge("assistant", "save_memory")
builder.add_edge("save_memory", END)

# Store와 함께 그래프 컴파일
graph = builder.compile(store=store)
```

그래프를 컴파일할 때 `store=store`를 전달하면, 모든 노드에서 Store에 접근할 수 있습니다. Checkpointer도 함께 사용하려면 `checkpointer=checkpointer`를 추가로 전달하면 됩니다.

```python
from langgraph.checkpoint.memory import MemorySaver

# Checkpointer 생성 (단기 메모리용)
checkpointer = MemorySaver()

# Store와 Checkpointer를 함께 사용하여 그래프 컴파일
graph = builder.compile(store=store, checkpointer=checkpointer)
```

Checkpointer와 Store를 함께 사용하면, 단기 메모리(대화 히스토리)와 장기 메모리(사용자 정보)를 모두 관리할 수 있습니다. Checkpointer는 특정 스레드의 대화 상태를 저장하고, Store는 사용자별 정보를 저장합니다.

```python
# 에이전트 실행
config = {
    "configurable": {
        "thread_id": "thread_001",  # 대화 스레드 ID
        "user_id": "user_001"       # 사용자 ID
    }
}

result = graph.invoke({
    "messages": [
        HumanMessage(content="나는 치와와를 좋아해")
    ]
}, config=config)

print(result["messages"][-1].content)
```

`config`에 `thread_id`와 `user_id`를 함께 전달하면, `thread_id`는 Checkpointer가 대화 히스토리를 관리하는 데 사용되고, `user_id`는 Store에서 사용자별 메모리를 검색하고 저장하는 데 사용됩니다. 같은 `user_id`를 사용하면 다른 스레드에서도 같은 사용자의 메모리에 접근할 수 있습니다.

노드에서 Store를 사용하는 방법을 정리하면, 노드 함수 시그니처에서 `store: BaseStore`와 `config: RunnableConfig`를 인자로 받습니다. `config["configurable"]["user_id"]`로 사용자 ID를 가져오고, `(user_id, "memories")` 형태로 네임스페이스를 정의합니다. `store.put()`, `store.get()`, `store.search()` 등의 메서드를 사용하고, `builder.compile(store=store)`로 Store를 전달합니다. 이렇게 하면 LangGraph 에이전트가 대화 중에 얻은 정보를 Store에 저장하고, 나중에 다시 활용할 수 있습니다.

이제 LangGraph와 Store를 통합하는 방법을 이해했습니다. 다음 페이지에서는 지식베이스에서 정보를 검색하는 다양한 방법을 학습합니다.
