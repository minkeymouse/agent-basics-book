지식베이스에 정보를 저장하는 것만으로는 충분하지 않습니다. 저장한 정보를 효과적으로 찾아내는 것이 진정한 지식베이스의 핵심입니다. 마치 도서관에 책을 쌓아두기만 하고 분류 체계나 검색 시스템이 없다면, 원하는 책을 찾기 어려운 것과 같습니다.

실제로 지식베이스가 유용하려면, 사용자가 질문한 내용과 관련된 정보를 빠르고 정확하게 찾아낼 수 있어야 합니다. 예를들어 사용자가 "강아지에 대한 정보를 알려줘"라고 물었을 때, 지식베이스에 "치와와를 좋아함"이라는 정보가 저장되어 있다면, 이를 찾아서 응답에 활용할 수 있어야 합니다. 하지만 단순히 키워드로 "강아지"를 검색한다면 "치와와"라는 키워드로 저장된 정보를 찾을 수 없을 것입니다.

이번 섹션에서는 LangGraph Store에서 저장된 정보를 검색하는 다양한 방법을 배워봅시다. 기본적인 키워드 검색부터 의미 기반 벡터 검색까지, 상황에 맞는 최적의 검색 방법을 선택할 수 있게 됩니다. 5장에서 봤던 것처럼, 상태 설계와 리듀서를 잘 정의해 두면 “검색된 정보를 어디에, 어떤 형식으로 쌓을지”도 자연스럽게 정리할 수 있습니다.

지식베이스에 수천, 수만 개의 정보가 저장되어 있다고 생각해봅시다. 사용자가 "치와와에 대한 정보를 알려줘"라고 질문했을 때, 정확한 키워드로 저장되어 있지 않다면 어떻게 찾을 수 있을까요? 

예를들어 지식베이스에 "사용자는 작은 강아지를 좋아함"이라는 정보가 저장되어 있다고 가정해봅시다. 사용자가 "치와와에 대한 정보"를 요청했을 때, 단순 키워드 검색으로는 "치와와"라는 단어가 없으므로 이 정보를 찾을 수 없습니다. 하지만 의미 기반 검색을 사용한다면 "작은 강아지"와 "치와와"가 의미적으로 유사하다는 것을 이해하고 관련 정보를 찾아낼 수 있습니다.

전통적인 키워드 기반 검색은 정확한 단어 매칭에 의존합니다. 저장된 키워드와 검색 키워드가 정확히 일치해야 하므로, "강아지"로 저장했으면 "개"로는 찾을 수 없습니다. 또한 "작은 강아지"와 "치와와"가 같은 의미라는 것을 이해하지 못하고, "반려동물"과 "애완동물"이 같은 맥락이라는 것을 알 수 없습니다.

효과적인 검색 시스템은 지식베이스의 가치를 극대화합니다. 저장만 해서는 의미가 없고, 찾아서 활용할 수 있어야 합니다. 의미 기반 검색으로 키워드가 달라도 의미가 유사하면 찾을 수 있고, 사용자의 의도를 이해하고 관련 정보를 제공할 수 있으며, 사용자의 과거 선호도나 경험을 바탕으로 맞춤형 정보를 제공할 수 있습니다.

LangGraph Store는 두 가지 기본 검색 메서드를 제공합니다. 이 메서드들은 벡터 검색 없이도 사용할 수 있으며, 간단한 검색 작업에 적합합니다. 다만 대량의 데이터나 의미 기반 검색이 필요한 경우에는 벡터 검색을 사용하는 것이 좋습니다.

`search(namespace)` 메서드는 특정 네임스페이스에 저장된 모든 항목을 반환합니다.

`search(namespace)` 메서드는 특정 네임스페이스에 저장된 모든 항목을 반환합니다. 이는 해당 네임스페이스의 모든 메모리를 가져와야 할 때 유용합니다. 예를들어 사용자의 모든 선호도를 확인하거나 특정 카테고리의 모든 정보를 조회할 때 사용할 수 있습니다.

이 메서드는 간단하고 직관적이지만, 대량의 데이터에서는 비효율적일 수 있습니다. 네임스페이스에 수천 개의 항목이 있다면, 모든 항목을 메모리로 가져오는 것은 시간이 오래 걸리고 메모리 사용량도 증가시킬 수 있습니다. 또한 사용자가 원하는 특정 정보만 찾고 싶을 때는 불필요한 데이터까지 가져오게 됩니다.

따라서 이 메서드는 데이터가 적을 때나 네임스페이스의 모든 항목이 필요할 때만 사용하는 것이 좋습니다.

```python
from langgraph.store.memory import InMemoryStore
import uuid

# 메모리 스토어 초기화
memory_store = InMemoryStore()

# 테스트 데이터 저장
namespace = ("user_001", "memories")
memory_store.put(namespace, "memory_1", {"content": "치와와를 좋아함"})
memory_store.put(namespace, "memory_2", {"content": "비빔밥을 좋아함"})
memory_store.put(namespace, "memory_3", {"content": "독서를 취미로 함"})

# 네임스페이스의 모든 메모리 검색
retrieved_memories = list(memory_store.search(namespace))
print(f"검색된 메모리 개수: {len(retrieved_memories)}")

for memory in retrieved_memories:
    print(f"키: {memory.key}, 내용: {memory.value['content']}")
```

실행하면 다음과 같은 결과가 나옵니다:

```
검색된 메모리 개수: 3
키: memory_1, 내용: 치와와를 좋아함
키: memory_2, 내용: 비빔밥을 좋아함
키: memory_3, 내용: 독서를 취미로 함
```

`get(namespace, key)` 메서드는 정확한 키를 알고 있을 때 사용하는 가장 빠른 방법입니다. 이 메서드는 네임스페이스와 키를 사용하여 특정 항목 하나만 가져오므로, 매우 효율적입니다.

예를들어 사용자의 프로필 정보를 저장할 때 "user_profile"이라는 키를 사용했다면, 나중에 `get(("user_001", "profile"), "user_profile")`을 호출하여 바로 해당 정보를 가져올 수 있습니다. 이는 데이터베이스의 기본키로 조회하는 것과 유사하며, 인덱스를 사용하므로 매우 빠릅니다.

다만 이 방법의 단점은 정확한 키를 알아야 한다는 것입니다. 키를 모르거나 여러 항목 중에서 관련된 것만 찾고 싶을 때는 사용할 수 없습니다. 또한 키를 잘못 입력하면 `None`을 반환하므로 에러 처리가 필요합니다.

```python
# 특정 키로 메모리 조회
specific_memory = memory_store.get(namespace, "memory_1")

if specific_memory:
    print("✅ 메모리 조회 성공!")
    print(f"  키: {specific_memory.key}")
    print(f"  내용: {specific_memory.value['content']}")
    print(f"  생성시간: {specific_memory.created_at}")
else:
    print("❌ 메모리를 찾을 수 없습니다.")
```

`search(namespace)` 메서드는 네임스페이스의 모든 메모리를 가져오므로 간단하고 직관적이지만, 대량 데이터에서 비효율적일 수 있습니다. `get(namespace, key)` 메서드는 특정 메모리를 가져오므로 매우 빠르지만, 정확한 키를 알아야 합니다. 기본 `search()` 메서드는 네임스페이스의 모든 항목을 반환하므로, 수천 개의 메모리가 있다면 모든 것을 가져오는 것은 비효율적입니다. 의미 기반 검색이 필요한 경우 벡터 검색을 사용하는 것이 좋습니다.

벡터 검색은 텍스트를 숫자로 변환하여 의미적으로 비슷한 내용을 찾는 방법입니다. 정확한 키워드가 없어도 의미적으로 유사한 내용을 찾을 수 있습니다.

예를들어 "강아지"로 검색했을 때 "개"나 "반려동물"로 저장된 정보도 찾을 수 있습니다. 또한 "작은 강아지를 좋아함"이라는 정보가 있을 때 "치와와에 대한 정보"를 요청하면 의미적으로 유사한 정보를 찾아낼 수 있습니다.

InMemoryStore에서 벡터 검색을 사용하려면 Store를 초기화할 때 `index` 설정을 추가해야 합니다. 

벡터 검색이 작동하는 원리를 살펴보면, 먼저 Embedding 모델이 텍스트를 숫자로 변환합니다. 다음으로 검색 쿼리와 저장된 메모리들을 벡터로 변환한 후, 벡터 간 거리를 계산합니다. 마지막으로 거리가 가까울수록 의미적으로 유사하다고 판단하여, 유사도가 높은 순서로 정렬합니다.

이제 실제로 벡터 검색을 활성화한 Store를 만들어보겠습니다.

```python
from langgraph.store.memory import InMemoryStore
from langchain.embeddings import init_embeddings

# Embedding 모델 초기화
embeddings = init_embeddings("openai:text-embedding-3-small")
```

먼저 Embedding 모델을 초기화합니다. `init_embeddings`는 LangChain에서 제공하는 함수로, 다양한 Embedding 모델을 쉽게 초기화할 수 있게 해줍니다. 여기서는 OpenAI의 `text-embedding-3-small` 모델을 사용합니다. 이 모델은 텍스트를 1536차원의 벡터로 변환합니다.

```python
# 벡터 검색을 활성화한 Store 생성
store = InMemoryStore(
    index={
        "embed": embeddings,  # Embedding 모델
        "dims": 1536,         # Embedding 차원 (text-embedding-3-small의 경우)
    }
)
```

Store를 생성할 때 `index` 파라미터를 전달합니다. `index`는 딕셔너리 형태로, `embed`는 텍스트를 벡터로 변환하는 Embedding 모델이고, `dims`는 벡터의 차원 수입니다. text-embedding-3-small의 경우 1536입니다. `fields`는 어떤 필드를 임베딩할지 지정하는 리스트로 선택사항입니다.

`fields` 파라미터는 저장된 데이터의 어떤 부분을 벡터로 변환할지 결정합니다. `["$"]`를 사용하면 전체 문서를 임베딩하고, `["content", "title"]`처럼 특정 필드만 지정할 수도 있습니다. 예를들어 메모리에 `content`와 `metadata` 필드가 있다면, `fields: ["content"]`로 설정하면 `content` 필드만 벡터 검색에 사용됩니다.

이렇게 설정하면 Store가 자동으로 저장된 텍스트를 벡터로 변환하고, 검색 시 의미적 유사도를 계산할 수 있습니다.

실제 시나리오를 가정해보겠습니다. 온라인 서점의 개인 비서 에이전트를 만든다고 생각해봅시다. 고객이 여러 번 대화를 나누면서 다양한 정보를 제공했습니다. 이제 고객이 "추천해줘"라고 말했을 때, 과거 대화에서 얻은 정보를 바탕으로 개인화된 추천을 제공해야 합니다.

```python
# 고객의 메모리 네임스페이스
namespace = ("customer_12345", "memories")

# 고객이 여러 번 대화를 나누면서 제공한 정보들을 저장
# 첫 번째 대화: "나는 작은 강아지를 키우고 있어"
memory_data_1 = {
    "content": "작은 강아지를 키우고 있으며, 매일 산책을 나감",
    "category": "반려동물",
    "timestamp": "2024-01-10T10:00:00"
}

# 두 번째 대화: "한국 음식을 좋아해, 특히 비빔밥을 즐겨 먹어"
memory_data_2 = {
    "content": "한국 음식을 좋아하며, 비빔밥을 자주 먹음",
    "category": "음식",
    "timestamp": "2024-01-12T15:30:00"
}

# 세 번째 대화: "소설을 읽는 것을 좋아해, 특히 추리 소설을 즐겨 읽어"
memory_data_3 = {
    "content": "독서를 취미로 하며, 추리 소설을 즐겨 읽음",
    "category": "취미",
    "timestamp": "2024-01-14T20:15:00"
}

# 메모리 저장
store.put(namespace, "memory_1", memory_data_1)
store.put(namespace, "memory_2", memory_data_2)
store.put(namespace, "memory_3", memory_data_3)

print("✅ 3개의 메모리가 저장되었습니다.")
```

이제 벡터 검색을 실행해보겠습니다. 고객이 "강아지에 대한 추천을 해줘"라고 말했다고 가정해봅시다. 정확히 "강아지"라는 단어가 저장된 메모리에 없어도, "작은 강아지를 키우고 있다"는 메모리를 의미적으로 찾아낼 수 있어야 합니다.

```python
# 고객이 "강아지에 대한 추천을 해줘"라고 말했다고 가정
query_text = "강아지에 대한 정보"
results = list(store.search(
    namespace,
    filter=None,  # 필터 없음 (모든 카테고리의 메모리 검색)
    query=query_text,  # 벡터 검색 쿼리
    limit=2  # 상위 2개만 반환
))
```

`search` 메서드에 `query` 파라미터를 전달하면 벡터 검색이 실행됩니다. `namespace`는 검색할 네임스페이스로 고객의 메모리만 검색합니다. `filter`는 메타데이터 필터인데, 여기서는 None으로 설정하여 모든 카테고리 검색합니다. `query`는 검색할 텍스트로, 이 텍스트가 벡터로 변환되어 유사도 계산에 사용됩니다. `limit`은 반환할 결과 개수로, 상위 2개만 반환하여 컨텍스트 길이를 제한합니다.

검색 쿼리 "강아지에 대한 정보"는 벡터로 변환되고, 저장된 각 메모리와의 유사도가 계산됩니다. 

벡터 검색이 작동하는 과정을 살펴보면, 먼저 "강아지에 대한 정보"라는 텍스트가 Embedding 모델을 통해 1536차원의 벡터로 변환됩니다. 다음으로 저장된 각 메모리의 `content` 필드도 벡터로 변환되어 있으므로, 쿼리 벡터와 각 메모리 벡터 간의 거리를 계산합니다. 코사인 유사도나 유클리드 거리 등을 사용하여 유사도를 계산하는데, 거리가 가까울수록 의미적으로 유사하다고 판단합니다. 마지막으로 유사도가 높은 순서로 정렬되어 `limit` 개수만큼 반환됩니다.

```python
print(f"\n'{query_text}' 검색 결과:")
print(f"총 {len(results)}개의 관련 메모리를 찾았습니다.\n")

for i, result in enumerate(results, 1):
    print(f"[{i}] 유사도 점수: {result.score:.3f}")
    print(f"    내용: {result.value['content']}")
    print(f"    카테고리: {result.value.get('category', 'N/A')}")
    print(f"    저장 시간: {result.value.get('timestamp', 'N/A')}")
    print()
```

검색 결과를 출력합니다. 각 결과는 `StoreValue` 객체이며, `score` 속성을 통해 유사도를 확인할 수 있습니다. 유사도는 0과 1 사이의 값으로, 1에 가까울수록 의미적으로 더 유사합니다.

실행하면 다음과 같은 결과가 나옵니다:

```
'강아지에 대한 정보' 검색 결과:
총 2개의 관련 메모리를 찾았습니다.

[1] 유사도 점수: 0.892
    내용: 작은 강아지를 키우고 있으며, 매일 산책을 나감
    카테고리: 반려동물
    저장 시간: 2024-01-10T10:00:00

[2] 유사도 점수: 0.234
    내용: 한국 음식을 좋아하며, 비빔밥을 자주 먹음
    카테고리: 음식
    저장 시간: 2024-01-12T15:30:00
```

첫 번째 결과는 "작은 강아지"라는 내용이 있어서 유사도가 높게 나왔습니다. 두 번째 결과는 관련성이 낮지만, 의미적으로 완전히 무관하지 않아서 낮은 점수로 포함되었습니다. 실제로는 `limit=2`로 설정했기 때문에 가장 관련성 높은 2개만 반환됩니다.

이렇게 검색된 정보를 활용하면, 에이전트가 "이전에 말씀하신 작은 강아지를 위한 추천을 해드릴게요"와 같이 개인화된 응답을 할 수 있습니다.

`StoreValue` 객체를 딕셔너리로 변환하려면 `.dict()` 메서드를 사용할 수 있습니다. 이렇게 하면 모든 속성(값, 키, 네임스페이스, 생성 시간, 수정 시간, 점수 등)을 딕셔너리 형태로 가져올 수 있어서, JSON으로 직렬화하거나 다른 용도로 활용하기 편리합니다.

```python
# StoreValue를 딕셔너리로 변환
for result in results:
    result_dict = result.dict()
    print(f"키: {result_dict['key']}")
    print(f"값: {result_dict['value']}")
    print(f"유사도: {result_dict.get('score', 'N/A')}")
```

`search()` 메서드의 벡터 검색 파라미터는 다음과 같습니다. `namespace`는 검색할 네임스페이스로 필수입니다. `filter`는 메타데이터 필터로 딕셔너리 형태이며 기본값은 None입니다. `query`는 검색할 텍스트로 벡터로 변환되며 기본값은 None입니다. `limit`은 반환할 결과 개수로 기본값은 None이며, None이면 모두 반환합니다.

```python
# 필터와 쿼리를 함께 사용하는 예제
results = list(store.search(
    namespace,
    filter={"topic": "반려동물"},  # 메타데이터 필터
    query="강아지 산책",  # 벡터 검색 쿼리
    limit=5  # 상위 5개만 반환
))

for result in results:
    print(f"내용: {result.value['content']}")
    if hasattr(result, 'score'):
        print(f"유사도 점수: {result.score:.3f}")
    print("---")
```

벡터 검색을 사용하려면 Store 초기화 시 `index` 파라미터로 Embedding 모델을 설정합니다:

```python
from langgraph.store.memory import InMemoryStore
from langchain.embeddings import init_embeddings

# Embedding 모델 초기화
embeddings = init_embeddings("openai:text-embedding-3-small")

# 벡터 검색 활성화
store = InMemoryStore(
    index={
        "embed": embeddings,
        "dims": 1536,  # text-embedding-3-small의 차원
        "fields": ["$"]  # 전체 문서 임베딩 (특정 필드만 지정 가능)
    }
)
```

이제 실제로 다양한 검색 방법을 비교해보겠습니다. 먼저 데이터를 준비합니다.

```python
from langgraph.store.memory import InMemoryStore
from langchain.embeddings import init_embeddings
import uuid

# Embedding 모델 초기화
embeddings = init_embeddings("openai:text-embedding-3-small")

# 벡터 검색이 활성화된 Store 생성
store = InMemoryStore(
    index={
        "embed": embeddings,
        "dims": 1536,
    }
)

namespace = ("user_001", "knowledge_base")

# 다양한 주제의 정보 저장
knowledge_items = [
    {"topic": "반려동물", "content": "치와와를 키우고 있고 매일 산책을 나갑니다."},
    {"topic": "음식", "content": "비빔밥을 좋아하고 한국 전통 음식을 즐깁니다."},
    {"topic": "취미", "content": "독서를 좋아하고 특히 소설을 즐겨 읽습니다."},
    {"topic": "운동", "content": "주 3회 헬스장에 가서 운동을 합니다."},
    {"topic": "여행", "content": "제주도를 좋아하고 자주 방문합니다."},
]

for item in knowledge_items:
    key = str(uuid.uuid4())
    store.put(namespace, key, item)

print("✅ 지식베이스 데이터 저장 완료!")
```

다음으로 네임스페이스의 모든 항목을 검색합니다. `search(namespace)`를 사용하면 모든 항목을 가져올 수 있습니다.

의미 기반 검색을 사용하려면 `query` 파라미터를 전달합니다. 예를들어 "반려동물과 운동에 대한 정보"라는 쿼리로 검색하면, 의미적으로 유사한 내용을 찾을 수 있습니다. `limit=3`으로 설정하면 상위 3개만 반환됩니다.

특정 키를 알고 있다면 `get(namespace, key)`를 사용하여 가장 빠르게 조회할 수 있습니다.

상황에 맞는 검색 방법을 선택하는 것이 중요합니다. 정확한 키를 알고 있다면 `get(namespace, key)`가 가장 빠르고, 네임스페이스의 모든 항목이 필요하다면 `search(namespace)`가 간단하고 직관적입니다. 의미적으로 유사한 내용을 찾으려면 `search(namespace, query=...)`를 사용하면 키워드가 달라도 찾을 수 있습니다. 대량 데이터에서 관련 정보만 찾으려면 `search(namespace, query=..., limit=...)`를 사용하면 효율적이고 정확합니다.

벡터 검색을 사용할 때는 `limit` 파라미터로 필요한 개수만 가져오고, 유사도 점수를 확인하여 관련성 높은 결과만 사용하는 것이 좋습니다.

벡터 검색과 함께 `filter` 파라미터를 사용하면 특정 조건에 맞는 항목만 검색할 수 있습니다.

```python
# 메타데이터와 함께 저장
store.put(
    namespace,
    "item_1",
    {"content": "치와와 정보", "category": "반려동물"}
)

# 필터와 벡터 검색 함께 사용
results = list(store.search(
    namespace,
    filter={"category": "반려동물"},  # category가 "반려동물"인 항목만
    query="강아지",
    limit=5
))

for result in results:
    print(f"내용: {result.value['content']}")
```

벡터 검색은 키워드가 정확히 일치하지 않아도 의미적으로 유사한 내용을 찾을 수 있습니다. `limit` 파라미터를 사용하여 필요한 개수만 가져오는 것이 좋고, Embedding 모델은 OpenAI의 `text-embedding-3-small`을 사용하는 것이 일반적입니다.

기본 검색은 모든 항목을 반환하므로 간단하지만 비효율적일 수 있습니다. 벡터 검색은 의미 기반으로 작동하여 키워드가 달라도 관련 정보를 찾을 수 있습니다. 특정 조회는 가장 빠르지만 정확한 키가 필요합니다. 벡터 검색의 장점은 정확한 키워드 없이도 관련 정보를 발견할 수 있고, 유사도 점수로 결과의 관련성을 수치로 확인할 수 있으며, 대량의 데이터에서도 효율적으로 작동한다는 것입니다. 실무에서는 상황에 맞는 검색 방법을 선택하고, `limit` 파라미터로 필요한 개수만 가져오는 것이 좋습니다.

이제 지식베이스에서 정보를 찾는 방법을 배웠습니다. 다음 페이지에서는 찾은 정보를 업데이트하고 관리하는 방법을 학습합니다. 메모리 컬렉션을 활용하여 동적으로 지식베이스를 유지보수하는 방법을 알아보겠습니다.
