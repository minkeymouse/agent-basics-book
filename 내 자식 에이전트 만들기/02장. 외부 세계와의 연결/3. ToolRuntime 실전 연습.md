LangGraph의 툴은 단순히 함수를 호출하는 수준을 넘어서,
**실행 중(runtime)** 환경 속에서 에이전트의 상태(state)와 컨텍스트(context)를 함께 다룹니다.
**LangChain v1**에서는 이런 복잡한 런타임 제어가 대부분 **자동화**되었지만,
여전히 툴이 내부적으로 “어떤 실행 맥락에서 작동하는지”를 이해하는 것은 중요합니다.  
v0 시절에는 `ToolRuntime`을 직접 다루는 코드가 많았지만, v1에서는 대부분 `create_agent()`와 LangGraph 런타임이 대신 처리해 주고, 우리는 “어떤 상태를 노출할지”에만 신경 쓰면 됩니다.

## ⚙️ ## LangChain v1에서의 ToolRuntime 개념

이전 버전에서는 개발자가 `ToolRuntime` 객체를 직접 받아서
`state`, `store`, `context`를 조작해야 했습니다.
하지만 v1에서는 이 역할을 **에이전트 내부 런타임 컨테이너**가 자동으로 처리합니다.

| 구성 요소 | 설명 |
|------|------|
| 🧠 state | 대화의 현재 상태 (MessagesState로 관리) |
| 🌐 context | 세션, 사용자, 실행 환경 등 메타 정보 |
| 💾 store | 툴 간 공유 가능한 임시 저장소 (예: 캐시, 중간 데이터) |
| 🔁 flow control | 툴 실행 중 상태 업데이트 및 제어 (내부적으로 Command 기반으로 처리됨) |

즉, 이제 `ToolRuntime`을 직접 다루지 않아도,
`create_agent()`가 모든 상태 전달·업데이트를 **자동으로 처리**합니다.

## 🧩 기본 구조 — “상태를 읽고 쓰는 툴”

LangChain v1에서는 `ToolRuntime` 객체 대신
함수 내부에서 상태 접근 함수 `(runtime.update_state(), runtime.state.get())`를 직접 다루지 않습니다.
대신, 상태를 MessagesState에 통합하거나,
필요한 경우 `memory` 또는 `store` 객체를 통해 접근할 수 있습니다.

아래 예시는 “사용자 입력을 기억하는 툴”을 v1 구조로 구현한 간단한 예시입니다.
 
```python
from langchain.tools import tool

@tool
def remember(entry: str, memory: dict = {}) -> str:
    """사용자의 입력을 저장하는 간단한 기억 툴"""
    memory.setdefault("entries", []).append(entry)
    return f"'{entry}'를 기억했습니다. 총 {len(memory['entries'])}개의 기록이 있습니다."
```

`create_agent()`를 사용하면 이 툴의 상태는 자동으로 내부 메모리 컨텍스트에 반영됩니다.

```python
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI

agent = create_agent(
    model=ChatOpenAI(model="gpt-4o-mini"),
    tools=[remember],
    system_prompt="사용자가 말하는 내용을 기억하고 관리하세요."
)

agent.invoke({"messages": [{"role": "user", "content": "오늘은 LangChain을 공부했어."}]})
agent.invoke({"messages": [{"role": "user", "content": "오늘 공부한 내용을 다시 알려줘."}]})
```
 
**핵심 포인트**
* v1에서는 `ToolRuntime` 인자를 직접 받지 않습니다.
* 툴이 호출될 때의 상태(state)는 LangGraph가 자동으로 관리합니다
* 툴의 상태적 동작은 “MessagesState + memory + context”를 통해 간접적으로 표현됩니다.

## 💾 툴 내부에서 임시 데이터 저장하기

LangGraph는 툴 간 임시 데이터를 저장할 수 있는 `store` 개념을 제공합니다.
이 역시 `create_agent()` 내부에서 자동 생성되지만,
필요하다면 툴 내에서 전역 상태처럼 활용할 수도 있습니다.

```python
@tool
def save_temp(key: str, value: str, store: dict = {}) -> str:
    """간단한 캐시 저장 툴"""
    store[key] = value
    return f"'{key}'에 '{value}'를 저장했습니다."
```

이렇게 만든 툴은 LLM이 스스로
**“값을 저장해야 하는 상황”**을 판단해 호출할 수 있습니다.

## 🔁 흐름 제어: Command 개념의 자동화

LangGraph 내부에서는 툴 실행 시 `Command` 객체를 통해
상태 업데이트나 실행 중단을 제어합니다.
v0에서는 직접 `Command(update={...})`를 반환해야 했지만,
v1에서는 이 과정이 자동으로 처리됩니다!

즉, 아래처럼 명시적으로 `Command`를 반환할 필요가 없습니다:

```python
# (이전 방식)
from langgraph.types import Command

def step_tool(runtime, step: int) -> Command:
    if step < 3:
        return Command(update={"progress": step + 1})
    else:
        return Command(stop=True)
```

이제는 단순히 상태를 리턴하거나,
LLM에게 결과를 전달하면 LangGraph가 내부적으로 Command로 변환합니다.

```python
@tool
def progress_tracker(step: int) -> str:
    """현재 진행 단계를 갱신합니다."""
    return f"지금은 {step}단계입니다. 다음 단계로 진행합니다."
```

## 🧠 상태와 컨텍스트 통합 동작 예시

LangGraph는 MessagesState를 중심으로
툴 호출 중의 대화 맥락과 상태 업데이트를 자동으로 병합합니다

```python
from langgraph.graph import StateGraph, START, END, MessagesState

def weather_node(state: MessagesState):
    return {"messages": agent.invoke({"messages": state["messages"]})}

builder = StateGraph(MessagesState)
builder.add_node("weather_node", weather_node)
builder.add_edge(START, "weather_node")
builder.add_edge("weather_node", END)

graph = builder.compile()
```

이렇게 하면 에이전트가 툴을 호출할 때마다
**상태(state)** 는 자동으로 MessagesState에 반영되고, 대화 맥락이 끊기지 않습니다.

## 🔍 핵심 정리

| 항목 | 핵심 내용 |
|------|------|
| ToolRuntime | 더 이상 직접 사용하지 않음. 내부 런타임이 자동 관리 |
| state |MessagesState에 통합되어 자동 전달 |
| context | 세션/사용자 정보 등 자동 포함 |
| store | 툴 간 임시 데이터 저장소 (필요시 인자로 전달) |
| Command | 내부적으로 자동 처리 (명시적 반환 불필요) |

[[TIP]]
💡 **ToolRuntime 핵심 요약**

* `runtime`을 직접 다루지 않아도 됩니다 — 모든 것은 에이전트가 자동 관리합니다.
* 툴은 “상태 변경자(state mutator)”가 아니라 “행동 단위(behavioral unit)”로 설계하세요.
* 상태, 컨텍스트, 저장소는 LangGraph가 자동으로 연결합니다.
[[/TIP]]

[[TIP("실무 팁")]]
🧩 **ToolRuntime 베스트 프랙티스**

* 툴의 입력은 명확히 정의하되, 상태는 LangGraph가 관리하도록 맡기세요.
* `create_agent()`를 통해 스키마, 메모리, 상태가 모두 자동 연결됩니다.
* 임시 캐시나 툴 간 공유 데이터는 store나 외부 저장소를 활용하세요.
* 더 복잡한 상태 제어가 필요한 경우 MessagesState 기반 그래프 노드를 설계하세요.
[[/TIP]]


✅ 이제 LangChain v1 환경에서는 ToolRuntime이 “직접 사용하는 객체”가 아니라 자동 관리되는 실행 컨텍스트라는 점을 이해했습니다. <br>
