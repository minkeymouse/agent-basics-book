LangGraph의 에이전트는 단순히 대화만 하는 존재가 아닙니다.
필요할 때 **외부 세계와 연결되는 도구(tool)** 를 사용할 수 있어야 진정한 **‘행동하는 AI’**가 됩니다.

이번 섹션에서는 **툴(tool)의 개념과 정의 방법**, 그리고 LangGraph에서
`@tool` 데코레이터를 사용해 **에이전트에 장착 가능한 툴을 만드는 방법**을 배워봅시다.  
여기서 소개하는 패턴은 LangChain v1 공식 문서의 [Tools](https://docs.langchain.com/oss/python/langchain/tools) 섹션과 동일한 개념을 따르며, 뒤에서 사용할 `create_agent`와도 직접 연결됩니다.

## 🧰 툴이 왜 필요할까요?

LLM은 지식을 가지고 있지만, 외부 시스템에 접근할 수 없습니다. <br>
예를 들어, 

* 오늘 날짜를 계산하거나
* 데이터베이스에서 정보를 검색하거나
* 파일을 읽고 쓰는 일

은 모두 “세상 밖의 일”이죠.

이때 필요한 것이 **툴(tool)** 입니다.
LangGraph의 툴은 LLM이 **직접 함수(API)** 를 호출해 실제 행동을 수행할 수 있도록 돕습니다.

| 기능 | 설명 |
|------|------|
| 🔧 도구 호출 | 모델이 직접 함수를 실행하여 외부 정보 활용 |
| 🧠 컨텍스트 활용 | 이전 대화 맥락에 따라 어떤 도구를 쓸지 판단 |
| 🪄 자동 인수 추론 | 자연어 명령에서 함수 인수를 자동으로 채움 |
| 🚀 확장성 | 새로운 도구를 손쉽게 추가하고 관리 가능 |

## 📘 툴의 기본 정의

LangGraph의 툴은 LangChain의 @tool 데코레이터로 쉽게 정의할 수 있습니다.
Python의 일반 함수를 툴로 등록하면, LLM이 자연어로 호출할 수 있는 형태가 됩니다.

```python
from langchain.tools import tool

@tool
def greet(name: str) -> str:
    """이름을 받아 인사말을 반환합니다."""
    return f"안녕하세요, {name}님!"
```

**특징**

* @tool 한 줄로 LangGraph가 인식 가능한 표준 툴이 됩니다.
* 함수의 이름은 툴 이름으로 사용되고, docstring은 설명으로 자동 등록됩니다.
* LLM은 "name" 파라미터를 자동으로 추론하여 이 함수를 호출할 수 있습니다.

## 🧩 툴의 구조 살펴보기

LangGraph는 각 툴을 구조화된 데이터로 관리합니다.

```python
print(greet.name)          # greet
print(greet.description)   # 이름을 받아 인사말을 반환합니다.
print(greet.args)          # {'name': {'type': 'string'}}
```

| 구성 요소 | 설명 |
|------|------|
| name | 툴의 이름 (기본: 함수 이름) |
| description | LLM이 언제 사용할지 판단하는 힌트 |
| args | 함수 인수의 구조 (타입 힌트 기반) |

💡 **Tip**: <br>
함수의 docstring이 곧 “모델에게 주는 설명서”이므로,
언제 / 왜 / 어떤 상황에서 호출해야 하는지를 구체적으로 써주세요!

## ⚙️ 복잡한 입력이 필요할 때: Pydantic 스키마 사용

단일 인수가 아닌 여러 인수나 옵션을 다루려면 **Pydantic 모델**을 사용할 수 있습니다.
이를 통해 모델이 **입력 구조를 명확히 이해**하도록 돕습니다.

```python
from pydantic import BaseModel, Field
from langchain.tools import tool

class SearchInput(BaseModel):
    query: str = Field(..., description="검색할 키워드")
    limit: int = Field(5, description="검색 결과 개수")

@tool(args_schema=SearchInput)
def search(query: str, limit: int = 5) -> str:
    """키워드를 받아 검색 결과를 반환합니다."""
    return f"'{query}'에 대한 상위 {limit}개 결과를 보여드릴게요."
```

**장점**:

* 입력 구조를 강제할 수 있어 오류를 줄입니다.
* 필수/옵션 인수 구분 가능
* LLM이 어떤 필드를 어떻게 채워야 할지 쉽게 학습함

## 🔧 툴 이름과 설명 변경하기

툴 이름이나 설명을 명시적으로 바꿔야 할 때는
@tool("이름", description="설명") 형식을 사용하세요.

```python
@tool("today_date", description="오늘 날짜를 반환하는 함수입니다.")
def today() -> str:
    from datetime import date
    return str(date.today())
```

이제 모델은 "오늘 날짜"와 관련된 질문에서 today_date 툴을 스스로 선택할 수 있습니다.

## 🧠 툴의 실제 동작 테스트

LangGraph를 사용하지 않고도 툴은 독립적으로 실행 가능합니다.

```python
print(greet.invoke({"name": "짱구"}))
print(search.invoke({"query": "LangGraph", "limit": 3}))
print(today.invoke({}))
```

**출력 예시**
```
안녕하세요, 지수님!
'LangGraph'에 대한 상위 3개 결과를 보여드릴게요.
2025-10-27
```

## 🤖 내 에이전트에 툴 장착하기

이제 내 에이전트에  장착해봅시다.

```python
from langchain.agents import create_agent

agent = create_agent(
    model="gpt-4o-mini",            # 문자열 또는 모델 객체(ChatOpenAI 등)
    tools=[greet, search, today],   # 위에서 정의한 툴들
    system_prompt=(
        "당신은 도움을 주는 도우미입니다. "
        "날짜/검색/인사 관련 요청 시 적절한 도구를 사용하세요."
    )
)

result = agent.invoke({
    "messages": [
        {"role": "user", "content": "오늘 날짜 알려줘. 그리고 LangGraph v1도 검색해줘."}
    ]
})
```

* 에이전트는 핵심 루프(모델 호출 → 툴 선택/실행 → 툴이 없을 때 종료)를 자동으로 수행합니다.
* messages는 {role, content} 형식으로 전달합니다. (원하면 langchain.messages.HumanMessage 등을 써도 됩니다.)
* 결과는 모델 응답/툴 호출 결과가 포함된 표준 구조로 돌아옵니다.

## 🔍 핵심 정리

| 항목 | 핵심 내용 |
|------|------|
| @tool | 함수를 LangGraph 툴로 등록 |
| docstring | 툴의 사용 목적과 상황을 설명 |
| Pydantic | 복잡한 입력 구조를 명확히 정의 |
|`create_agent`에서`tools`정의 | 에이전트에 툴을 장착해 “행동하는 AI” 구성 |
| 실행 테스트 | invoke()로 직접 호출 가능 |

[[TIP]]
**💡 툴 설계 시 주의사항**

* 함수의 이름과 docstring은 최대한 “자연어에 가깝게” 작성하세요.
* 인수 이름은 짧지만 의미 있게(query, location, amount 등).
* LLM은 문맥 기반으로 툴을 선택하므로, 설명 문구가 곧 “사용 조건”이 됩니다.
[[/TIP]]

[[TIP("실무 팁")]]
**🧩 툴 정의 베스트 프랙티스**

* `@tool` 한 줄로 간단하게 시작하세요.
* 복잡한 입력은 Pydantic으로 스키마화하세요.
* 툴 설명에 “이 툴은 언제 쓰이는가?”를 반드시 포함하세요.
[[/TIP]]
