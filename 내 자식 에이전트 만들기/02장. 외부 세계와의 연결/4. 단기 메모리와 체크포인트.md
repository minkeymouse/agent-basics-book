LangGraph는 단순 일회성 호출이 아니라, 대화 맥락을 보존하고 특정 시점으로 복원할 수 있는 실행 기반 메모리 시스템을 제공합니다.
v1에서는 이를 에이전트 차원의 자동 체크포인팅으로 간편하게 사용할 수 있습니다.

* 🧠 **단기 메모리 (Short-term Memory)**: 현재 세션의 대화 상태를 유지

* 💾 **체크포인트 (Checkpoint)**: 실행 시점의 스냅샷을 저장/복원

### 핵심 요약 (v0 vs. v1)
| 주제 | LangChain v0 | LangChain v1 |
|------|------|------|
| 메모리/체크포인트 연결 | 그래프에 별도 연결 필요 | 에이전트/그래프 생성 시 `checkpointer` 한 줄 |
| 상태 식별자 | 임의 구현 | thread_id로 세션 분리 (config에 포함) |
| 복원/이어하기 | 수동 스토어 핸들링 | 같은 thread_id로 invoke() 하면 자동 복원 |

## 🧠 단기 메모리(Short-term Memory)란?

단기 메모리는 “현재 세션 내의 대화 맥락”을 저장합니다.
즉, 사용자가 여러 차례 대화를 이어갈 때
이전 대화 내용과 도구 호출 결과를 그대로 이어받는 시스템입니다.

LangGraph에서는 `MemorySaver` 클래스로 이 기능을 제공합니다.

```python
from langgraph.checkpoint.memory import MemorySaver

memory = MemorySaver()
```

이 객체는 실행 중 생성되는 **상태(state)** 를 자동으로 저장하며,
그래프 실행이 끝난 후에도 해당 세션의 상태를 다시 불러올 수 있습니다.

## 💾 체크포인트(Checkpoint)란?

체크포인트는 말 그대로 **“상태 저장소(state snapshot)”**입니다.
즉, 대화 도중의 특정 시점에서
모든 메시지와 내부 상태를 “스냅샷” 형태로 저장하는 기능입니다.

이를 통해 다음과 같은 작업이 가능합니다:

| 활용 목적 | 설명 |
|------|------|
| 🔁 대화 이어서 진행 | 이전 실행 결과에서 이어서 다음 단계 수행 |
| 🧩 부분 실행 재시도 | 오류가 발생한 시점부터 다시 실행 |
| 🕓 실행 이력 관리 | 각 시점의 상태를 기록·비교 |
| 🚀 분기 시뮬레이션 | 동일한 시작점에서 여러 가지 대화 흐름 테스트 |


## 가장 간단한 형태: 에이전트에 MemorySaver 장착

```python
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.memory import MemorySaver

# 1) 체크포인터 준비
memory = MemorySaver()

# 2) 에이전트 생성 시 연결 (tools 생략 예시)
agent = create_agent(
    model=ChatOpenAI(model="gpt-4o-mini"),
    tools=[],  # 필요 시 도구 배열
    system_prompt="대화를 기억하고 이어서 응답하세요.",
    checkpointer=memory,  # ✅ 한 줄로 장착
)

# 3) 대화 실행 (thread_id로 세션 구분)
tid = "user_001"

agent.invoke({
    "messages": [{"role": "user", "content": "안녕! 오늘 일정 정리해줘."}]
}, config={"configurable": {"thread_id": tid}})

# 같은 thread_id로 이어서 대화 → 이전 컨텍스트가 자동 로드
agent.invoke({
    "messages": [{"role": "user", "content": "아까 말한 첫 번째 일정만 다시 알려줘."}]
}, config={"configurable": {"thread_id": tid}})
```

**포인트**

* `checkpointer=MemorySaver()`만 붙이면, 실행마다 **자동 저장**됩니다.
* 같은 thread_id로 호출하면, **자동 복원 + 이어서 대화**가 됩니다

## 그래프와 함께 쓰는 형태 (MessagesState)

그래프를 쓰는 경우에도 방식은 동일합니다. `compile(checkpointer=…)`에 연결하세요!

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
from langgraph.checkpoint.memory import MemorySaver

llm = ChatOpenAI(model="gpt-4o-mini")
memory = MemorySaver()

def chat_node(state: MessagesState):
    # 누적 메시지를 그대로 모델에 투입
    ai = llm.invoke(state["messages"])
    return {"messages": [ai]}

builder = StateGraph(MessagesState)
builder.add_node("chat", chat_node)
builder.add_edge(START, "chat")
builder.add_edge("chat", END)

graph = builder.compile(checkpointer=memory)

tid = "session_1"

# 1회차
out1 = graph.invoke(
    {"messages": [HumanMessage(content="안녕, 오늘 날씨 어때?")]},
    config={"configurable": {"thread_id": tid}}
)

# 2회차 (자동 복원)
out2 = graph.invoke(
    {"messages": [HumanMessage(content="내일은 비 올까?")]},
    config={"configurable": {"thread_id": tid}}
)
```

## 체크포인트가 자동 저장되는 흐름
```
[입력 메시지] → [노드/에이전트 실행] → [상태 업데이트] → ✅ [체크포인트 저장]
```

* 저장 단위: **`thread_id` × 실행 시점**
* 이어서 실행: 같은 thread_id로 새 메시지를 주면 **이전 상태 + 새 입력**이 합쳐져 실행됩니다.

## 스레드(세션) 분리 전략

여러 사용자/대화를 동시에 처리하려면 `thread_id`만 다르게 주면 됩니다.

```python
tid_a = "user_A"
tid_b = "user_B"

agent.invoke(..., config={"configurable": {"thread_id": tid_a}})
agent.invoke(..., config={"configurable": {"thread_id": tid_b}})
```

> 권장: thread_id는 사용자 고유 식별자 + 시나리오/세션 키로 구성하면 운영이 쉽습니다.
> (예: "{`user_id`}:{`channel`}:{`date`}")

## MemorySaver vs. 커스텀 저장소

* **MemorySaver**: 프로토타입/로컬 실행에 적합 (프로세스 메모리 기반)
* **서비스 운영**: DB/파일/클라우드 기반 CheckpointStore로 교체

예: 파일 기반 체크포인터(개념 예시)
```python
from langgraph.checkpoint.base import BaseCheckpointSaver
import json, os

class FileCheckpointSaver(BaseCheckpointSaver):
    def put_checkpoint(self, config, checkpoint):
        tid = config["configurable"]["thread_id"]
        os.makedirs("ckpt", exist_ok=True)
        with open(f"ckpt/{tid}.json", "w", encoding="utf-8") as f:
            json.dump(checkpoint, f, ensure_ascii=False)

    def get_latest_checkpoint(self, config):
        tid = config["configurable"]["thread_id"]
        path = f"ckpt/{tid}.json"
        if not os.path.exists(path):
            return None
        with open(path, "r", encoding="utf-8") as f:
            data = json.load(f)
        return data
```
> 실제 운영에서는 **트랜잭션/버전/보안**을 고려해 RDB/Key-Value/오브젝트 스토리지 기반 구현을 권장합니다


## 🔍 핵심 정리

| 항목 | 핵심 내용 |
|------|------|
| Short-term Memory | 현재 세션의 대화 맥락을 자동 저장하고 복원 |
| Checkpoint | 실행 시점의 상태를 스냅샷으로 저장해 이후 이어서 실행 가능 |
| MemorySaver | 메모리 기반 기본 체크포인터 (`checkpointer`=`MemorySaver()`) |
| Thread ID | 세션·사용자별 상태를 구분하는 고유 식별자 |
| Custom CheckpointStore |MemorySaver를 DB·파일 기반으로 교체 가능 (운영 환경에 적합) |

[[TIP]]
💡 **메모리 관리 핵심 요약**
	
* `checkpointer=MemorySaver()` 한 줄로 자동 상태 저장이 활성화됩니다.
* `thread_id`가 같으면 자동 복원, 다르면 새로운 세션이 생성됩니다.
* 체크포인트는 “세션 단위 대화 연속성”을 보장하므로, 멀티 세션 환경에서 특히 중요합니다.
* 장기 대화 세션은 주기적으로 **요약(Summarization)** 을 병행하여 토큰 낭비를 줄이세요.
[[/TIP]]

[[TIP("실무 팁")]]
🧩 **체크포인트 베스트 프랙티스**

* 프로토타입 → `MemorySaver`, 운영 서비스 → DB·파일 기반 `CheckpointStore` 사용.
* `thread_id`는 사용자 이메일, UUID 등 **고유한 세션 키**로 구성하세요.
* **개인정보 마스킹**: Checkpoint에는 민감 데이터를 직접 저장하지 않도록 설계하세요.
* **복구 전략**: 주기적으로 저장된 체크포인트를 백업하고 버전 관리하세요.
* **대규모 세션 관리**: SummarizationMiddleware와 함께 사용하면 메모리 부담을 최소화할 수 있습니다.
[[/TIP]]

✅ 이제 LangChain v1에서의 **대화 기억과 상태 복원 메커니즘**을 이해했습니다. <br>
다음 장에서는 이 기억을 요약(summarization)하고 장기 대화에서도 효율적으로 유지하는 방법을 살펴봅시다.
