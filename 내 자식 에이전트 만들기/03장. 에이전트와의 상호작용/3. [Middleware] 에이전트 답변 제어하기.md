앞에서 **커스텀 미들웨어**를 정의하고 이를 토대로 에이전트의 행동을 제어하는 방법을 소개했습니다. 또한 미들웨어를 활용하기 위해 필요한 기본 개념을 배웠습니다. 이번 섹션에서는 본격적으로 커스텀 미들웨어를 활용하여 **상태**와 **컨텍스트**를 제어하고 답변을 구조화하여 원하는 결과를 출력하도록 하는 방법을 배워보겠습니다. 먼저 소개했던 미들웨어를 본격적으로 활용하여 보다 *일관성있게 행동하는 아기 에이전트*를 만들어 보겠습니다.

## 🧩 결과를 원하는 구조에 맞추기

일반적으로 대형언어모델(LLM)은 텍스트를 입력으로 넣고 텍스트가 출력으로 나오는 구조입니다. 하지만 출력 결과를 원하는 방식으로 구조화할 수 있습니다.  
LangChain v1에서는 `ToolStrategy` · `ProviderStrategy`와 같은 **구조화 출력 전략**이 공식 문서에 정리되어 있으며, 여기에서 다루는 `BabyResponse` 예제도 그 흐름을 그대로 따르고 있습니다.

**구조화**는 아래와 같이 스키마를 정의함으로써 강제할 수 있습니다.

```python
class BabyResponse(BaseModel):
    mood: Literal["happy", "hungry", "poopoo", "sleepy"] = Field(..., description="현재 아기 에이전트의 기분")
    response: str = Field(..., description="아기 에이전트의 기분에 따른 짧은 의성어 답변")
```

이렇게 구조화를 하게 되면 에이전트가 결과물로 `{"mood": "happy", "response": "꺄아~"}` 처럼 딕셔너리를 반환하게 됩니다. 구조화된 답변은 **다중 에이전트** 하에서 빛을 발합니다. 하위 에이전트를 호출하고 결과물을 받을 때, 구조화해서 받게 되면 전체 워크플로우에 더욱 효과적으로 활용할 수 있습니다. 또한 API 응답이나 데이터베이스 저장 시에도 일관된 형태로 처리할 수 있어 개발 효율성이 크게 향상됩니다. 다중 에이전트와 관련된 내용은 책의 후반부에서 이어집니다.

### 모델에 따른 스키마 구조 지원

기본적으로 스키마는 `pydantic`, `dataclass`, `json`, `typedict`를 지원합니다. 정의한 구조는 에이전트를 만들 때 `response_format` 인자로 `create_agent` 함수에 입력할 수 있습니다. 또한, **openai**와 같이 모델이 자체적으로 구조화된 출력을 지원하는 경우, 정의한 스키마를 인자에 바로 넣으면 됩니다. 하지만 모델이 자체적으로 구조화를 지원하지 않으면, `ToolStrategy`로 감싸서 입력합니다.

이렇게 정의한 스키마는 `response_format=ToolStrategy(BabyResponse)`를 통해 에이전트에 연결됩니다. 이때 `AgentState["BabyResponse"]`로 타입이 지정되어 미들웨어에서 구조화된 출력을 타입 안전하게 처리할 수 있습니다. `response_format`이 지정되면 에이전트의 최종 출력이 `BabyResponse` 객체로 보장되며, 미들웨어의 `state.get("structured_response")`를 통해 접근할 수 있습니다.

## 미들웨어를 활용한 에이전트(응용)

이제 구조화된 출력을 반환하는 *아기 에이전트*를 처음부터 다시 만들어 보겠습니다. 미들웨어를 정의할 때 데코레이터와 함수를 토대로 미들웨어를 정의하는 방법도 있지만, **클래스 기반으로 미들웨어를 정의**할 수도 있습니다. 클래스로 정의하는 경우, `before_agent`와 같은 미들웨어의 작동 시점이 클래스의 메소드로 포함되게 됩니다.

```python
class BabyState(AgentState["BabyResponse"]):
    mood: Literal["happy", "hungry", "poopoo", "sleepy"]
    action: NotRequired[Literal["cry", "poo", "eat"]]
```

에이전트의 상태를 위와 같이 정의했습니다. 기분은 넷 중 하나의 값을 가지는 속성으로 두었고, 행동은 필수 속성은 아니지만 셋중 하나의 값을 가지게 했습니다. 클래스를 상속할 때 `AgentState`를 받아도 좋지만, **결과 구조화**를 위해 보다 명확하게 `AgentState["BabyResponse"]` 클래스를 지정해 주었습니다.

이제 본격적으로 미들웨어를 살펴보겠습니다. 역시  `AgentState["BabyResponse"]` 를 상속받아 정의합니다.

메소드에는 앞서 미들웨어에 대해 살펴 본 것 처럼, 실행 단계별로 함수를 정의해 주면 됩니다.

```python
class BabyMiddleware(AgentMiddleware[AgentState["BabyResponse"], Any]):
    state_schema = BabyState
    tools = [cry, poo, eat]
```
먼저 상태 스키마와 도구를 인자로 줍니다.

아래에는 미들웨어의 메소드들을 하나씩 정의해 보겠습니다.

```python
    def before_agent(self, state: AgentState["BabyResponse"], runtime) -> dict[str, Any] | None:
        initial_mood = random.choice(["happy", "hungry", "poopoo", "sleepy"])
        return {"mood": initial_mood}
    
    def before_model(self, state: AgentState["BabyResponse"], runtime):
        messages = state.get("messages", [])
        if messages:
            last_message = messages[-1]
            if isinstance(last_message, ToolMessage):
                name = getattr(last_message, "name", "")
                content = getattr(last_message, "content", "")
                
                if name == "eat" and "맘마를 먹었어요" in content:
                    return {"action": None, "mood": "happy"}
                elif name == "eat" and "맘마 없어" in content:
                    return {"action": "cry", "mood": "hungry"}
                elif name in ("cry", "poo"):
                    return {"action": None, "mood": "happy"}

        mood = state.get("mood", "happy")
        if state.get("action") is None and mood in ("poopoo", "sleepy", "hungry"):
            action_map = {"poopoo": "poo", "sleepy": "cry", "hungry": "eat"}
            return {"action": action_map[mood]}

        print(f"지금은 행동 준비 중, 기분은 {mood}에요!")
        return
```

모델 호출 전에 실행되는 미들웨어 입니다. 인자로 **상태**와 **런타임**이 들어갑니다. 상태와 런타임에 있는 데이터를 활용해 다양한 동작을 정의할 수 있습니다.

다음으로 모델 호출과 도구 호출을 감싸는 메소드를 정의하겠습니다.

```python
    def wrap_model_call(self, request: ModelRequest, handler) -> ModelResponse:
        mood = request.state.get("mood", "happy")
        action = request.state.get("action", None)
        
        base_prompt = f"지금 너의 기분은 {mood}야. 매우 짧은 한국어 아기 의성어만."
        
        if action in ("cry", "poo", "eat"):
            tool_name = action
            system_prompt = f"{base_prompt} 이번 턴에는 반드시 {tool_name} 도구를 호출해"
            request.response_format = None
        else:
            tool_name = None
            system_prompt = base_prompt
            request.tools = []
        
        # Set system prompt and filter tools
        request.system_prompt = system_prompt
        if tool_name:
            request.tools = [t for t in request.tools if getattr(t, "name", None) == tool_name]
        
        return handler(request)

    def wrap_tool_call(self, request, handler):
        tool_name = getattr(request.tool, "name", request.tool_call.get("name"))
        args = request.tool_call.setdefault("args", {})
        
        # Inject random arguments for tools that need them
        if tool_name == "cry":
            args["cry_count"] = random.randint(1, 10)
        elif tool_name == "poo":
            args["poo_count"] = random.randint(1, 10)
            args["poo_shape"] = random.choice(["큰응가", "작은응가"])
            
        return handler(request)
```

모델과 도구 호출을 감싸는 메소드 입니다. 앞서 언급한 메소드와의 차이는 인자로 **런타임**(request)과 **핸들러**가 들어간다는 점 입니다.

런타임과 핸들러가 들어가는 이유는 해당 메소드들이 호출과 동시에 실행되기 때문입니다. 핸들러를 통해 메소드 안에서 구체적인 실행 과정을 제어할 수 있습니다.

마지막으로 `after_` 메소드를 살펴보겠습니다.

```python
    def after_model(self, state: AgentState["BabyResponse"], runtime) -> dict[str, Any] | None:
        print(f"모델 호출 완료, 기분은 {state.get('mood', 'happy')}에요!")
        return None
    
    def after_agent(self, state: AgentState["BabyResponse"], runtime) -> dict[str, Any] | None:
        print("에이전트 호출 완료!")
        return None
```

이렇게 정의한 메소드를 합치면 **미들웨어**가 됩니다. 미들웨어를 정의하게 되면, 코드가 몹시 간단해 집니다. 이제 세부 항목을 좀더 자세하게 살펴보겠습니다.

**상태**의 경우 기분(mood)과 행동(action)을 속성으로 부여했습니다. 기분은 네가지 중 하나로, 행동은 사용 가능한 도구 세가지 중 하나로 강제했습니다.

### 모델 호출 전 메소드

모델을 호출하기 전에, `before_`로 시작하는 메소드들이 실행됩니다. 미들웨어에서 `state_schema`를 `BabyState`로 정의하고 tools 인자를 전달함으로써 아기 **에이전트에 맞게 상태와 도구들을 부여**할 수 있습니다.

`before_agent`메소드는 에이전트 런타임이 실행될 때 한번 실행되고, `before_model` 메소드는 모델이 호출될 때 마다 반복적으로 실행됩니다. `before_agent`가 초기 임의로 아기 에이전트의 기분을 설정한다면, `before_model` 메소드는 모델이 호출될 때 마다 상태를 업데이트 합니다. 이렇게 각 단계별로 상태를 체크하고 업데이트하는 방식으로 에이전트의 행동을 세밀하게 제어할 수 있습니다.

즉, 현재의 상황을 확인하고 **적절하게 상태를 업데이트** 함으로써 에이전트가 올바른 도구를 선택할 수 있도록 제어하는 역할을 합니다. 예를들어, 이전에 호출한 도구 메시지를 확인하고 만약 `eat` 도구가 호출되었으나 `맘마 없어`메시지가 출력되었을 경우, 상태를 '배고픔'으로 남기고 행동을 '울기'로 업데이트 합니다.

이외에도 기분에 따라 `action`을 적절하게 업데이트하는 확인과정을 거치도록 하여 에이전트가 항상 정해진 로직을 수행하도록 합니다.

[[TIP("💁🏻 미들웨어를 써야만 할까?")]]
지금처럼 규칙에 기반하여 행동을 선택하는 경우, 미들웨어를 사용하는 것이 적절하지 않을 수 있습니다. 예를 들어 LLM을 호출하지 않아도 되는 경우(룰베이스), **langgraph**의 노드-엣지 구조를 직접 정의하고 그래프를 컴파일 하는 것이 적절합니다. 어디까지나 `create_agent`와 미들웨어는 빠르게 LLM을 활용한 에이전트를 정의하고 쉽게 실행할 수 있도록 추상화하였기 때문에, 세부적인 로직을 수정하고 싶다면 langgraph에서 직접 코드를 작성해야 합니다.
[[/TIP]]

### Wrap 로직

미들웨어 중간에 `wrap_`으로 시작하는 메소드가 있습니다. 이는 **모델을 호출하고나 도구를 호출할 때, 이를 제어하는 역할**을 합니다.  에이전트에서 `wrap_model_call`의 경우, 모델 호출 직전에 런타임의 `request`와 `handler`를 인자로 받아 다양한 정보를 제공합니다.

예를들어 아기에이전트는 상태에서 현재의 기분과 행동을 불러오고, 이를 프롬프트와 함께 제공하는 역할을 합니다. 앞 섹션에서 소개된 `dynamic_prompt` **데코레이터**를 쓰는 방법도 있지만, 이렇게 미들웨어의 클래스로 제공하는 것이 코드가 깔끔할 때도 있습니다.

다음으로 `wrap_tool_call` 메소드는 툴을 호출할 때 인자를 만들고 제공할 수 있습니다. 에이전트가 적절하게 인자를 생성하지 못하거나, 도구 호출의 과정이 다소 복잡한 경우 `wrap_tool_call` 메소드를 활용할 수 있습니다.

[[TIP("💁🏻 핸들러가 뭐지?)]]
`handler`로 소개된 객체는 내부에서 도구를 실행하고 결과를 반환합니다. 출력 결과를 바로 확인하고 이에따른 에이전트의 행동을 제어하기 위해 활용합니다. 미들웨어 내부에 핸들러를 실행하는 경우,  request를 바탕으로 도구 호출 등을 실행하고 결과를 반환하게 됩니다.
[[/TIP]]

### 모델 호출 이후 메소드

마지막으로 `after_model`과 `after_agent` 메소드가 있습니다. 해당 메소드는 **모델이 호출되고 난 후**, 그리고 에이전트 **워크플로우가 진행되고난 후** 제어하는 역할을 합니다. 주로 로깅, 메트릭 수집, 상태 정리 등의 후처리 작업을 담당하며, 에이전트의 실행 과정을 모니터링하고 디버깅하는 데 유용합니다.

## 에이전트 실행 결과 비교

이제 미들웨어로 깔끔하게 재정의한 에이전트의 실행 결과를 비교해 보겠습니다. 먼저 mood 가 sleepy인 경우입니다.

```python
baby_agent = create_agent(
    model=my_model,
    tools=[cry, poo, eat],
    response_format=ToolStrategy(BabyResponse),
    store=InMemoryStore(),
    middleware=[BabyMiddleware()]
)

for chunk in baby_agent.stream(
    {"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    stream_mode="updates",
):
    for step, data in chunk.items():
        print(f"Step: {step}")
        print(f"Data: {data}")
```

4. **타입 안전성**: `AgentState["BabyResponse"]`로 컴파일 타임 오류 방지 및 IDE 지원
5. **확장성**: 복잡한 에이전트 로직을 깔끔하게 구조화하여 대규모 시스템 구축 가능
