이번 장의 마지막 순서는 **Human in the loop(HITL)**, 즉 사람이 에이전트에게 개입하는 방법 입니다.

## 🧠 왜 HITL가 필요할까?

에이전트는 완벽하지 않습니다. AI 열풍이 부는 지금, 인공지능이 무엇이든 해결해 줄 것이라는 믿음이 있지만 생각보다 에이전트는 세심한 제어가 필요합니다.

예를들어, 파일을 삭제하거나 수정하는 경우 시스템의 **중요 파일을 실수로 삭제**할 수도 있습니다. SQL 쿼리를 자동으로 실행하는 경우, 데이터 베이스의 잘못된 데이터 까지도 삭제할 수도 있습니다. 나아가 **잘못된 도구를 호출**하거나, 사용자의 의도와는 다른 행동을 취할수도 있습니다.

HITL은 이를 제어할 수 있는 가장 효과적인 방법 중 하나입니다. 랭체인의 미들웨어를 통해 HITL로 개입하는 경우 `approve`, `edit`, `reject`의 세가지 타입을 활용할 수 있습니다.  
LangGraph/LangChain v1 문서의 [Human-in-the-loop](https://docs.langchain.com/oss/python/deepagents/human-in-the-loop) 섹션에서도, 민감한 도구 호출에 대해서는 반드시 체크포인터와 HITL을 함께 사용할 것을 권장합니다.

### HITL를 적용한 에이전트

먼저 랭체인의 기본 미들웨어인 `HumanInTheLoopMiddleware`를 불러와 적용시켜 보겠습니다. HITL을 적용하기 위해서는 체크포인터가 필요하기 때문에 `InMemorySaver`를 불러와 활용하겠습니다.

```python
from langgraph.checkpoint.memory import InMemorySaver
from langchain.agents.middleware import HumanInTheLoopMiddleware

# 에이전트 생성
baby_agent = create_agent(
    model=my_model,
    tools=[cry, poo, eat],
    response_format=ToolStrategy(BabyResponse),
    store=InMemoryStore(),
    middleware=[BabyMiddleware(),
        HumanInTheLoopMiddleware(
            interrupt_on={
                "eat": {"allowed_decisions": ["approve", "reject"]},
                "cry": False
            }
        )],
    checkpointer=InMemorySaver(),
)
```

위와 같이 HITL를 실행하는 **미들웨어**를 추가하고 에이전트를 다시 만들 수 있습니다. HITL를 활용하는 경우 메모리 영속성이 반드시 필요하기 때문에 `checkpointer`를 정의했음을 기억하세요!

이제 에이전트를 실행해 보겠습니다.

```python
from langgraph.types import Command

config = {"configurable": {"thread_id": "baby_agent1"}}

result = baby_agent.invoke({"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    config=config)

print(result["__interrupt__"])
```
```
[Interrupt(value={'action_requests': [{'name': 'eat', 'args': {}, 'description': 'Tool execution requires approval\n\nTool: eat\nArgs: {}'}], 'review_configs': [{'action_name': 'eat', 'allowed_decisions': ['approve', 'reject']}]}, id='e8014e7118d52d2cd252000cd86f295e')]
```

위와 같이 `Interrupt` 객체가 생성되면서 **에이전트의 실행이 중단**된 것을 확인할 수 있습니다.

### HITL 허용

이제 `Command` 객체로 에이전트에게 도구 호출을 허락한 뒤 연속해서 실행해 보겠습니다.

```python
baby_agent.invoke(
    Command(
        resume={
            "decisions":[
                {
                    "type":"approve"
                }
            ]
        }
    ),
    config=config
)
```
```
[Interrupt(value={'action_requests': [{'name': 'eat', 'args': {}, 'description': 'Tool execution requires approval\n\nTool: eat\nArgs: {}'}], 'review_configs': [{'action_name': 'eat', 'allowed_decisions': ['approve', 'reject']}]}, id='c3cdfd5516d87c2f634dcdc41b8c9048')]
모델 호출 완료, 기분은 hungry에요!
모델 호출 완료, 기분은 hungry에요!
모델 호출 완료, 기분은 happy에요!
에이전트 호출 완료!
```

결과를 보면, 도구 호출 후, 실행을 허가했더니 체크포인터를 통해 대화를 불러온 뒤 마저 실행한 것을 알 수 있습니다.

## Approve, Edit, Reject

마찬가지로 `edit` 과 `reject` 명령 역시 `Command`객체를 `invoke`에 전달하면 됩니다. 한가지 주의해야 할 점은 두 명령어의 경우 키가 추가된다는 점입니다.

```python
agent.invoke(
    Command(
        resume={
            "decisions": [
                {
                    "type": "edit",
                    "edited_action": {
                        # 호출하고자 하는 도구의 이름과 상응하는 변수를 제공해야 합니다.
                        "name": "new_tool_name",
                        "args": {"key1": "new_value", "key2": "original_value"},
                    }
                }
            ]
        }
    ),
    config=config
)
```

위처럼 `edit`의 경우 호출해야 하는 도구와 인자를 지정해야 합니다. 마찬가지로 `reject`를 보겠습니다.

```python
agent.invoke(
    Command(
        resume={
            "decisions": [
                {
                    "type": "reject",
                    # 거절한 이유를 적어야 합니다.
                    "message": "아직 맘마가 준비되지 않았어",
                }
            ]
        }
    ),
    config=config  # Same thread ID to resume the paused conversation
)
```

에이전트에게 왜 거절했는지 이유를 메시지로 줘야 합니다.

이처럼 **미들웨어**와 `Command` 객체를 활용해 에이전트에게 HITL를 적용하고 제어할 수 있습니다.

## 에이전트와의 상호작용

3장 전반에서 배운 것처럼 에이전트와의 상호작용은 나만의 에이전트를 한 단계 진화시키는 필수적인 단계입니다.

### 에이전트 개발의 철학

에이전트 개발은 단순히 기술적 구현을 넘어서 **사용자와의 신뢰 관계 구축**이 핵심입니다. 에이전트가 무엇을 하고 있는지 사용자가 이해할 수 있는 투명성, 일관된 행동 패턴으로 신뢰를 얻는 예측 가능성, 사용자 피드백을 통해 지속적으로 개선되는 학습 능력, 그리고 실수를 최소화하고 위험한 행동을 방지하는 안전성이 모두 중요합니다.

이를 위해서는 **지속적인 모니터링과 개선**이 가장 중요합니다. 에이전트의 실행 시간, 도구 호출 횟수, 사용자 만족도 등을 지속적으로 추적하고, 성능이 저하되거나 예상과 다른 결과가 나올 때는 프롬프트나 미들웨어를 개선해야 합니다. 특히 사용자 피드백을 수집하여 에이전트의 행동을 지속적으로 개선하는 피드백 루프를 구축하는 것이 핵심입니다.

## 핵심 정리
-  **스트리밍의 중요성**: `invoke`만으로는 에이전트의 실행 과정을 파악하기 어려움. `stream` 메소드를 활용해 실시간으로 에이전트의 행동을 추적하고 디버깅
-  **미들웨어를 통한 제어**: 기본 미들웨어로 호출 횟수와 재시도를 제한하고, 커스텀 미들웨어로 상태와 컨텍스트를 세밀하게 제어하여 예측 가능한 에이전트를 만들 수 있음
-  **컨텍스트 엔지니어링**: 모델 컨텍스트(프롬프트, 도구 선택), 도구 컨텍스트(인자 제어), 라이프사이클 컨텍스트(상태 관리)를 통해 에이전트에게 적절한 맥락을 제공
-  **구조화된 출력**: `response_format`을 활용해 일관된 응답 형태를 보장하고, 다중 에이전트 환경에서 효과적인 협업이 가능하도록 함
-  **HITL과 안전성**: 위험한 도구 호출에 대해 Human in the Loop을 적용하여 사용자의 명시적 승인을 받고, 에이전트의 안전한 운영을 보장
