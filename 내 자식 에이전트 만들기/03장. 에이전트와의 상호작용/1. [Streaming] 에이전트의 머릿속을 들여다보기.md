**도입부**에서 정의한 도구와 스키마를 바탕으로, `create_agent`함수를 활용해 **에이전트를 만들어 보겠습니다**. 우선 임의로 `current_mood`를 통해 기분을 생성하고, 이를 시스템 프롬프트에 반영하겠습니다.

아기 에이전트처럼 행동하기 위해 상태에 맞는 행동을 system prompt 변수에 정의했습니다. 모델 호출 빈도가 많기 때문에 ollama를 활용하겠습니다.

```python
my_model = init_chat_model("ollama:gpt-oss:20b")

current_mood = random.choice(["happy","hungry","poopoo","sleepy"])
```

현재의 기분을 정의할 때, 상태에 반영할수도 있겠지만 설명을 위해 일반 변수로 정의하겠습니다.

다음으로 `create_agent` 함수를 통해 에이전트를 생성합니다. 도구는 세가지가 주어졌고, 시스템 프롬프트가 다소 복잡하게 정의된 것을 볼 수 있습니다.

```python
baby_agent = create_agent(
    model = my_model,
    tools = [cry, poo, eat],
    store=InMemoryStore(),
    system_prompt = f"""
    너는 아기 에이전트야. 너의 지금 기분은 {current_mood}야. 이 값에 따라 아래 상태 규칙을 엄격히 따르며 응답해. 
    - happy: 도구 호출 금지. 아기가 기분이 좋은 것 처럼 짧은 의성어로 즉시 답해.
    - hungry: 반드시 eat 도구를 1회 호출. 
        • food.txt가 있어 내용을 읽으면(도구가 텍스트 반환) 내부 상태를 happy로 전환했다고 가정하고, 짧은 의성어로 마무리.
        • food.txt가 없으면(도구가 "맘마 없어" 등) hungry 유지 후 cry 도구를 1회 호출하고, 현재의 기분을 고려해서 짧은 의성어로 마무리.
    - poopoo: 반드시 poo 도구를 1회 호출(poo_shape="큰응가" 또는 "작은응가"), 성공 후 cry 도구 1회 호출하고, 현재의 기분을 고려해서 짧은 의성어로 마무리.
    - sleepy: cry 도구 1회 호출하고, 현재의 기분을 고려해서 짧은 의성어로 마무리.
    추가 규칙:
    - 총 도구 호출 수는 최대 2회.
    - 도구 입력 값은 위에서 지정한 값으로 단순하게 사용. 숫자 인자는 생략 가능하며, 생략 시 내부에서 1~10 사이 랜덤으로 설정.
    - 그 외에는 도구를 사용하지 말고, 항상 현재의 기분을 고려해서 짧은 의성어로 마무리해.
    """
)
```

아직 미들웨어를 통해 에이전트를 세밀하게 제어하는 법을 배우지 않았기 때문에 프롬프트가 복잡하게 정의됩니다. 이 경우 도구 호출 과정에서 에러가 많이 발생하기도 하고, 에이전트 실행에도 오랜 시간이 걸립니다.

## 스트리밍(Streaming)이 왜 필요할까요?

### invoke의 한계

앞서 배운 일반적인 `invoke`로 에이전트를 여러 번 실행해 보겠습니다.
```python
result =baby_agent.invoke({"messages": [{"role": "user", "content": "아기야 안녕?"}]})
print(실행 결과: result["messages"][-1].content)
```
```
실행 결과: 우아
실행 결과: 구구~
실행 결과: 으으 ...
```

**맙소사**🫢 ! 의성어로만 대답하라고 했기 때문에, 왜 저런 대답을 하는지, 무슨 행동을 한건지 알 수가 없습니다. 디렉토리를 보면 `cry.txt`와 `poo.txt`파일이 있습니다. 해당 파일들을 열어보겠습니다.

```text
# cry.txt
응애
응애
응애응애
```

```text
# poo.txt
큰응가큰응가큰응가
큰응가
큰응가큰응가
```

기분에 따라 도구를 호출하고 적절하게 행동한 것 같은데 어떤 과정을 거쳐서 저런 파일들을 결과로 작성했는지 알 수가 없습니다!

### 해결책: 업데이트 스트리밍

다행히 에이전트는 사람이 아니기 때문에, 인간 아기와 달리 머릿속을 훤히 들여다 볼 수 있습니다. 바로 `stream`메소드를 활용하면 가능합니다. 다시 스트리밍으로 결과를 출력해 보겠습니다.

```python
print("지금의 기분:", current_mood)
for chunk in baby_agent.stream(
    {"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    stream_mode="updates",
):
    for step, data in chunk.items():
        print(f"step: {step}")
        print(f"content: {data['messages'][-1].content_blocks}")
```

## 다양한 스트리밍 방법들

LangGraph는 여러 가지 스트리밍 모드를 제공합니다. 각 모드는 다른 목적과 사용 사례를 가지고 있습니다.  
여기에서 소개하는 `updates` / `values` / `messages` / `custom` / `debug` 모드는 LangGraph v1 문서에 나오는 스트리밍 옵션과 동일하며, Studio·LangSmith에서 그래프를 관찰할 때도 같은 개념으로 동작합니다.

### 스트리밍 모드 종류

| 모드 | 설명 | 사용 사례 |
|------|------|----------|
| `updates` | 각 단계에서 상태의 변경사항만 스트리밍 | 에이전트의 실행 과정을 단계별로 추적할 때 |
| `values` | 각 단계에서 전체 상태 값을 스트리밍 | 현재 상태의 전체 스냅샷이 필요할 때 |
| `messages` | LLM 토큰과 메타데이터를 스트리밍 | 채팅 애플리케이션에서 실시간 응답 표시 |
| `custom` | 도구나 노드에서 정의한 커스텀 데이터 스트리밍 | 진행 상황이나 사용자 정의 이벤트 전달 |
| `debug` | 디버깅을 위한 상세한 정보 스트리밍 | 문제 해결이나 성능 분석 |

### values 모드: 전체 상태 스트리밍

`values` 모드는 각 단계에서 상태의 전체 값을 반환합니다. `updates` 모드가 변경된 부분만 보여주는 것과 달리, `values` 모드는 현재 상태의 완전한 스냅샷을 제공합니다.

```python
for chunk in baby_agent.stream(
    {"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    stream_mode="values",
):
    print(f"전체 상태: {chunk}")
```

`values` 모드는 상태의 전체 구조를 확인하고 싶을 때 유용합니다. 예를들어 에이전트가 여러 번 실행되는 동안 상태가 어떻게 누적되는지 확인할 수 있습니다.

### updates 모드: 변경사항만 스트리밍

앞서 사용한 `updates` 모드는 각 단계에서 변경된 부분만 반환합니다. 이는 에이전트의 실행 과정을 효율적으로 추적할 수 있게 해줍니다.

```python
for chunk in baby_agent.stream(
    {"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    stream_mode="updates",
):
    for step, data in chunk.items():
        print(f"step: {step}")
        print(f"변경된 내용: {data}")
```

### 토큰 스트리밍 (messages 모드)

만약 토큰 단위로 스트리밍을 하고자 한다면, `stream_mode="messages"` 로 인자를 변경하고 호출하면 됩니다. 

```python
for token, metadata in baby_agent.stream(
    {"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    stream_mode="messages",
):
    print(f"실행노드: {metadata['langgraph_node']}")
    print(f"내용: {token.content_blocks}")
    print("\n")

```
토큰 단위로 호출시 위에서 봤던 *chunk*보다 세밀한 단위로 결과가 출력됩니다. 아래에서 몇가지 예시를 살펴보겠습니다.

```
실행노드: model
내용: [{'type': 'tool_call_chunk', 'id': 'd8aff430-38bd-467b-b544-d62842b2fb98', 'name': 'cry', 'args': '{}'}]

실행노드: tools
내용: [{'type': 'text', 'text': '울음 성공적으로 생성!'}]


실행노드: model
내용: [{'type': 'text', 'text': '아'}]


실행노드: model
내용: [{'type': 'text', 'text': '르'}]


실행노드: model
내용: [{'type': 'text', 'text': '르'}]


실행노드: model
내용: [{'type': 'text', 'text': '…'}]
```

`tool call`의 경우 *chunk*단위로 출력되고, *token*이 존재하는 나머지 단위의 경우 토큰 하나하나가 출력됩니다.

토큰 스트리밍은 토큰 단위로 하나하나 출력되기 때문에 결과값이 많습니다.

### 커스텀 스트리밍

그렇다면 도구를 호출하면서 기본 스트리밍에 기록되지 않지만 개인적으로 기록하고 싶은 내용이 있을때 어떻게 해야 할까요? 이는 `get_stream_writer()` 함수를 통해 추가할 수 있습니다. `poo` 도구에 커스텀 스트리밍을 추가해 보겠습니다.

```python
from langgraph.config import get_stream_writer

@tool("poo", description="응가를 봅니다. 디렉토리에 poo.txt 파일에 기록을 추가합니다.", args_schema=PooInput)
def poo(poo_shape: Literal["큰응가", "작은응가"] = "큰응가", poo_count: Optional[int] = None) -> str:
    c = poo_count if isinstance(poo_count, int) and poo_count > 0 else random.randint(1, 10)
    writer = get_stream_writer()
    writer("응가를 봅니다. 디렉토리에 poo.txt 파일에 기록을 추가합니다.")
    with open("poo.txt", "a") as f:
        f.write(poo_shape * c + "\n")
    writer("응가 성공적으로 생성!")
    return f"{poo_shape} {c}개 응가 성공적으로 생성!"
```

이제 아기 에이전트가 응가를 볼 때 마다 스트리밍에 추가됩니다. 커스텀 스트리밍을 사용할 때 주의할 점은, 도구에 `get_stream_writer`를 추가하는 경우, 해당 도구를 랭그래프 밖에서 실행하기 어렵다는 점입니다.

아래와 같이 결과를 확인해 보겠습니다.

```python
print("지금의 기분:", current_mood)
for chunk in baby_agent.stream(
    {"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    stream_mode="custom",
):
    print(chunk)
```
```
지금의 기분: poopoo
응가를 봅니다. 디렉토리에 poo.txt 파일에 기록을 추가합니다.
응가 성공적으로 생성!
```

응가 도구가 호출될 때 마다 성공적으로 스트리밍이 이루어지는 것을 확인할 수 있습니다. `print`를 써도 좋지만 스트리밍을 쓰는 이유는 **이를 활용한 제어**가 가능하기 때문입니다. 단순 기록을 넘어서 복잡한 에이전트를 조율하고 실행할 때 스트리밍은 필수적입니다.

### 다중 스트리밍

앞서 언급한 스트리밍을 동시에 실행하는 것도 가능합니다.

print("지금의 기분:", current_mood)
for stream_mode, chunk in baby_agent.stream(
    {"messages": [{"role": "user", "content": "아기야 안녕?"}]},
    stream_mode=["updates", "custom"],
):
    print(f" stream_mode: [{stream_mode}]")

## 스트리밍 모드 선택 가이드

각 스트리밍 모드는 다른 목적을 가지고 있습니다. 상황에 맞는 모드를 선택하는 것이 중요합니다.

**`updates` 모드를 사용하는 경우:**
- 에이전트의 실행 과정을 단계별로 추적하고 싶을 때
- 어떤 노드가 실행되었는지 확인하고 싶을 때
- 상태의 변경사항만 관심이 있을 때

**`values` 모드를 사용하는 경우:**
- 현재 상태의 전체 스냅샷이 필요할 때
- 상태가 누적되는 과정을 확인하고 싶을 때
- 디버깅 중 전체 상태 구조를 확인하고 싶을 때

**`messages` 모드를 사용하는 경우:**
- 채팅 애플리케이션에서 실시간으로 응답을 표시하고 싶을 때
- LLM이 생성하는 토큰을 하나씩 받아서 처리하고 싶을 때
- 사용자에게 점진적으로 응답을 보여주고 싶을 때

**`custom` 모드를 사용하는 경우:**
- 도구 실행 중 진행 상황을 사용자에게 알리고 싶을 때
- 사용자 정의 이벤트나 메시지를 전달하고 싶을 때
- 도구 내부에서 `get_stream_writer()`를 사용하여 커스텀 데이터를 전송할 때

**`debug` 모드를 사용하는 경우:**
- 에이전트의 실행 과정을 최대한 상세하게 추적하고 싶을 때
- 성능 문제를 분석하고 싶을 때
- 문제 해결을 위해 모든 정보가 필요할 때

## 핵심 정리

- **updates**: 단계별(model/tools) 진행 상황을 확인하기 좋은 스트리밍 방법. 각 단계에서 변경된 부분만 반환
- **values**: 각 단계에서 전체 상태 값을 반환. 상태의 완전한 스냅샷이 필요할 때 사용
- **messages**: 토큰 단위로 확인이 가능. 채팅 애플리케이션에서 실시간 응답 표시에 적합
- **custom**: 도구 내부에서 `get_stream_writer()`로 정의해야 함. 사용자 정의 진행 상황이나 이벤트 전달
- **debug**: 디버깅을 위한 상세한 정보 제공. 문제 해결이나 성능 분석에 유용
- **복수의 스트리밍 동시 사용 가능**: `stream_mode=["updates", "custom"]`처럼 여러 모드를 동시에 사용할 수 있음
- **커스텀 스트리밍의 제약**: `get_stream_writer()`를 사용하는 도구는 LangGraph 실행 컨텍스트 내에서만 호출 가능
