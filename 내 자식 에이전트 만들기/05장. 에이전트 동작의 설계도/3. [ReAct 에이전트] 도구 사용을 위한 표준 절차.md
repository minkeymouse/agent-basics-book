ReAct는 **Reasoning + Acting**의 줄임말입니다. <br>
이 패턴은 **모델이 스스로 “생각(Reason)”하고, 행동(Act)”하며,** <br>
그 결과를 다시 “관찰(Observe)”해 다음 행동을 결정하는 **순환형 에이전트 구조**입니다.

## 🎯 학습 목표

|목표|설명|
|:--:|:--:|
|🧠 ReAct 패턴 이해|Reason → Act → Observe의 반복 추론 구조 이해|
|🔁 루프 구조 구현|assistant → tools → assistant 반복 루프 구성|
|⚙️ 자율적 제어|모델이 스스로 도구 사용 여부를 판단|
|🧩 복합 문제 해결|여러 단계의 도구 호출로 복잡한 문제를 단계별로 해결|

## ReAct 패턴이란?

ReAct 패턴은 **사람이 문제를 해결하는 방식**을 모방한 구조입니다.

|단계|설명|
|:--:|:--:|
|🧩 Reason (추론)|현재 상황을 분석하고 어떤 행동이 필요한지 판단|
|⚙️ Act (행동)|필요한 도구를 실행해 결과를 얻음|
|👀 Observe (관찰)|도구 결과를 확인하고 다음 행동을 결정|

이 과정을 **여러 번 반복**하면서, <br>
에이전트는 복잡한 문제를 **스스로 단계별로 분해하고 해결**할 수 있습니다.

### 📊 ReAct vs 단순 도구 호출

|비교 항목|단순 도구 호출|ReAct 패턴|
|:--:|:--:|:--:|
|구조|단일 호출 후 종료|반복적 추론 루프|
|문제 해결|단일 단계|다단계 문제 해결|
|맥락 유지|없음|이전 결과를 기억|
|제어 방식|개발자가 결정|모델이 자율 결정|

## 환경 설정

```python
import os
from dotenv import load_dotenv
load_dotenv()

from datetime import datetime
from IPython.display import Image, display
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition
```

## 도구 정의

ReAct는 여러 단계의 도구 호출을 통해 문제를 해결합니다.
아래는 **간단한 수학 연산 도구 3개**를 예시로 사용합니다.

```python
def add(a: int, b: int) -> int:
    """두 수를 더하는 함수"""
    return a + b

def multiply(a: int, b: int) -> int:
    """두 수를 곱하는 함수"""
    return a * b

def divide(a: int, b: int) -> float:
    """두 수를 나누는 함수"""
    return a / b

tools = [add, multiply, divide]
llm = ChatOpenAI(model="gpt-4o")

# ReAct는 순차적 실행이 중요하므로 병렬 호출은 비활성화
llm_with_tools = llm.bind_tools(tools, parallel_tool_calls=False)
```

## 시스템 메시지와 어시스턴트 노드

ReAct 에이전트의 ‘사고 습관’을 정해주는 것이 바로 **SystemMessage**입니다.

```python
sys_msg = SystemMessage(
    content="당신은 입력된 숫자에 대해 단계별로 계산을 수행하는 수학 어시스턴트입니다."
)

def assistant(state: MessagesState):
    """ReAct 에이전트의 추론(Reasoning) 단계"""
    return {"messages": [llm_with_tools.invoke([sys_msg] + state["messages"])]}
```

> 💡 **Tip**: 시스템 메시지는 모델에게 “어떻게 사고할지”를 알려주는 역할을 합니다.

## ReAct 루프 그래프 구성

ReAct의 핵심은 “assistant → tools → assistant” 구조입니다.

```python
builder = StateGraph(MessagesState)

# 노드 정의
builder.add_node("assistant", assistant)
builder.add_node("tools", ToolNode(tools))

# 엣지 정의 (흐름)
builder.add_edge(START, "assistant")
builder.add_conditional_edges("assistant", tools_condition)  # 도구 호출 판단
builder.add_edge("tools", "assistant")  # 도구 실행 후 다시 추론
builder.add_edge("assistant", END)      # 더 이상 도구 호출 없으면 종료

react_graph = builder.compile()

# 시각화
display(Image(react_graph.get_graph(xray=True).draw_mermaid_png()))
```

### 🔄 ReAct 루프 흐름 정리

```
START → assistant → (tools_condition) → tools → assistant → END
                           ↑
                         반복 실행
```

* **assistant**: 추론 및 도구 호출 판단
* **tools**: 도구 실행 및 결과 메시지 추가
* **loop**: 도구 결과를 보고 다시 추론
* **END**: 도구 호출이 더 이상 필요 없을 때 종료

## ReAct 에이전트 테스트

```python
messages = [HumanMessage(content="3과 4를 더하세요. 그 결과에 2를 곱하고 5로 나누세요.")]
result = react_graph.invoke({"messages": messages})

for m in result["messages"]:
    m.pretty_print()
```

**🧩 예시 결과 (예상 흐름)**

```
Human: 3과 4를 더하세요. 그 결과에 2를 곱하고 5로 나누세요.

AI → add 호출
Tool(add): 7
AI → multiply 호출
Tool(multiply): 14
AI → divide 호출
Tool(divide): 2.8
AI: 최종 결과는 2.8입니다.
```


## 단계별 동작 분석

### 복잡한 수학 문제로 ReAct 에이전트 테스트

|단계|역할|수행 내용|
|:--:|:--:|:--:|
|①|Reason|“3과 4를 더하세요”를 인식 → add(3,4) 호출|
|②|Act|도구 실행 → 결과 7|
|③|Observe + Reason|“그 결과에 2를 곱하세요” 인식 → multiply(7,2)|
|④|Act|결과 14|
|⑤|Observe + Reason|“그 결과를 5로 나누세요” 인식 → divide(14,5)|
|⑥|Final|최종 답변 생성 및 종료|


## ReAct의 3가지 핵심 능력

|능력|설명|
|:--:|:--:|
|🧠 반복적 추론 (Reasoning Loop)|각 단계에서 스스로 다음 행동을 결정|
|🧩 맥락 유지 (Context Tracking)|이전 결과를 기억하고 다음 연산에 활용|
|⚙️ 자율적 제어 (Autonomy)|외부 개입 없이 언제 종료할지도 스스로 판단|

## ReAct 패턴의 장점 요약

|항목|설명|
|:--:|:--:|
|🔁 순환 구조|assistant → tools → assistant 루프를 통해 단계별 해결|
|🧩 복잡한 문제 해결|여러 연산이나 단계를 자동으로 이어가기 가능|
|🧠 맥락 기억|도구 결과를 기억하여 연속적 사고 가능|
|⚙️ 유연성|어떤 도구를 추가하더라도 동일 구조로 확장 가능|

ReAct 에이전트는 3장에서 살펴본 스트리밍·미들웨어·HITL과도 자연스럽게 연결됩니다.  
예를 들어 Studio에서 `assistant → tools → assistant` 루프를 한 단계씩 따라가며 로그를 확인하면 “어떤 생각으로, 어떤 도구를, 몇 번 호출했는지”를 시각적으로 검증할 수 있습니다. 또 Human-in-the-Loop를 이용해 특정 단계에서 사람에게 결정을 넘기는 구조를 추가하면, 복잡한 업무를 “모델이 먼저 시도하고, 중요한 순간에 사람에게 확인을 받는” 형태로 안전하게 설계할 수 있습니다.

[[TIP]]
**ReAct 패턴 요약**
* 단순한 “한 번의 도구 호출”이 아니라,“도구 결과를 관찰 → 다음 추론 → 재행동”이 반복되는 루프입니다.
* 이 패턴이 **“스스로 생각하는 AI 에이전트”**의 핵심입니다.
[[/TIP]]

[[TIP("실무 팁")]]
**ReAct 에이전트 구축 시 주의사항**

* `parallel_tool_calls=False`로 반드시 순차 실행 보장
* 각 도구의 **Docstring**은 명확하고 구체적으로 작성
* SystemMessage로 **역할과 사고 패턴을 명확히 설정**
* 그래프를 시각화하여 데이터 흐름을 이해
* 필요시 `tools → LLM` 요약 노드 추가로 후속 자연어 응답 강화
[[/TIP]]
