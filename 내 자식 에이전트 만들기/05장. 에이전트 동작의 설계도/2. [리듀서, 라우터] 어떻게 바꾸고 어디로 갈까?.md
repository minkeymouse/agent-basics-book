## 02-02. 리듀서(Reducers) - 이론적 배경

### 함수형 프로그래밍의 핵심: 리듀서

**리듀서(Reducer)**는 함수형 프로그래밍에서 **데이터 변환**을 담당하는 핵심 개념입니다. LangGraph에서 리듀서는 **상태 업데이트 방식**을 제어하는 메커니즘으로 활용됩니다.

#### 리듀서의 수학적 정의
리듀서는 두 개의 값을 받아서 하나의 값으로 **축약(reduce)**하는 함수입니다:
```
reducer: (T, T) → T
```

리듀서는 여러 가지 일반적인 패턴을 가지고 있습니다. 누적(Accumulation)은 여러 값을 하나로 합산하는 방식이고, 병합(Merging)은 두 데이터 구조를 하나로 결합하는 방법입니다. 또한 데이터를 다른 형태로 변환하는 변환(Transformation)과 조건에 따라 데이터를 선택하는 필터링(Filtering)도 가능합니다.

LangGraph에서 리듀서는 다양한 용도로 활용됩니다. 기본적인 덮어쓰기 대신 커스텀 로직을 적용하여 상태 업데이트를 제어할 수 있으며, 대화 기록을 안전하게 누적하는 메시지 관리에 사용됩니다. 또한 여러 노드의 결과를 안전하게 통합하는 병렬 처리와 상태 데이터를 원하는 형태로 변환하는 데이터 변환에도 활용됩니다.

이제 앞서 학습한 함수형 프로그래밍의 리듀서 개념이 LangGraph에서 어떻게 구현되는지 살펴보겠습니다. 리듀서의 수학적 정의 `reducer: (T, T) → T`가 Python 함수로 어떻게 구현되는지 확인하고, 누적, 병합, 변환, 필터링 패턴이 실제 상태 관리에서 어떻게 활용되는지 살펴보겠습니다. 또한 함수형 프로그래밍의 원칙들이 LangGraph의 상태 관리 시스템에서 어떻게 적용되는지 확인해보겠습니다.

이 섹션에서는 상태 업데이트 방식을 제어하는 리듀서의 역할과 필요성을 이해하고, 기본 동작과 리듀서 사용 시의 차이점과 장단점을 파악할 것입니다. 또한 메시지 추가를 위한 표준 리듀서인 add_messages의 동작 원리와 활용법을 학습하고, 리듀서를 사용한 메시지 상태 관리와 그래프 구축을 실제로 구현해보겠습니다.

## 리듀서의 필요성

### 문제 상황

LangGraph에서 각 노드는 상태 키에 대한 새로운 값을 반환합니다. 기본적으로 이 새로운 값은 이전 값을 **완전히 덮어씁니다**.

```python
# 기본 동작: 덮어쓰기
class State(TypedDict):
    messages: list[str]

def node1(state: State):
    return {"messages": ["메시지 1"]}

def node2(state: State):
    return {"messages": ["메시지 2"]}  # 이전 메시지가 사라짐!

# 실행 결과:
# 1단계: {"messages": ["메시지 1"]}
# 2단계: {"messages": ["메시지 2"]}  # ["메시지 1"]은 완전히 사라짐!
```

이러한 방식은 여러 가지 문제점을 야기합니다. 가장 심각한 문제는 데이터 손실로, 이전 메시지가 완전히 사라진다는 점입니다. 이로 인해 대화 맥락을 유지할 수 없고, 메시지를 누적하는 것이 불가능해집니다. 결과적으로 예상과 다른 결과가 발생하여 상태 불일치 문제가 생깁니다.

> **참고**: 이 문제는 01장에서 학습한 기본 메시지 추가 패턴의 한계입니다. 리듀서를 통해 이를 해결할 수 있습니다.

### 해결책: 리듀서 사용

우리는 메시지를 **추가**하고 싶습니다! 리듀서를 사용하면 이 문제를 해결할 수 있습니다.

### 리듀서의 역할

리듀서 함수는 상태 업데이트가 어떻게 수행될지 지정합니다.

- **기본 동작**: 덮어쓰기 (overwrite) - 이전 값을 완전히 대체
- **리듀서 사용**: 추가 (append), 병합 (merge), 누적 등 다양한 방식

### add_messages 리듀서

메시지를 추가하려면 `add_messages` 리듀서를 사용합니다. 이는 LangGraph에서 제공하는 표준 메시지 관리 리듀서입니다.

## 리듀서를 사용한 MessagesState

### Annotated 타입을 활용한 리듀서 지정

리듀서를 사용하려면 `Annotated` 타입을 활용하여 상태 키에 리듀서 함수를 지정합니다:

```python
from typing import Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import AnyMessage

class MessagesState(TypedDict):
    """리듀서를 사용한 메시지 상태 정의"""
    messages: Annotated[list[AnyMessage], add_messages]  # 메시지를 추가하는 리듀서 사용
```

**핵심 구성 요소**:
- `Annotated`: 타입 힌트와 메타데이터를 함께 지정하는 Python 타입
- `list[AnyMessage]`: 메시지 리스트의 타입
- `add_messages`: 메시지를 추가하는 리듀서 함수

### 내장 MessagesState 사용

LangGraph는 미리 구축된 `MessagesState`를 제공합니다:

**내장 MessagesState의 특징**:
- 미리 구축된 `messages` 키
- `AnyMessage` 객체들의 리스트  
- `add_messages` 리듀서 자동 적용
- 표준화된 메시지 관리 방식

**장점**: 커스텀 정의보다 간단하고 표준화됨

```python
# 내장 MessagesState 사용 (권장)
from langgraph.graph import MessagesState

# 확장된 상태 (추가 키 필요시)
class ExtendedMessagesState(MessagesState):
    user_id: str
    session_id: str
    # 기타 필요한 키들...
```

### 리듀서 동작 방식 비교

```python
# 덮어쓰기 방식 (기본)
class OverwriteState(TypedDict):
    messages: list[str]

# 추가 방식 (리듀서 사용)
class AppendState(TypedDict):
    messages: Annotated[list[str], add_messages]

# 동작 차이:
# 덮어쓰기: ["메시지1"] → ["메시지2"] (메시지1 사라짐)
# 추가: ["메시지1"] → ["메시지1", "메시지2"] (메시지1 보존)
```

### 리듀서의 핵심 개념

리듀서는 상태 업데이트 방식을 제어하는 함수입니다:

```python
# 리듀서 함수의 기본 구조
def reducer_function(existing_value, new_value):
    """기존 값과 새 값을 결합하여 최종 값을 반환"""
    # 예: add_messages 리듀서
    if not existing_value:
        existing_value = []
    if not new_value:
        new_value = []
    return existing_value + new_value  # 리스트 연결
```

**리듀서의 역할**:
- **상태 업데이트 규칙 정의**: 어떻게 기존 값과 새 값을 결합할지 명시
- **데이터 보존**: 기존 데이터를 보존하면서 새 데이터 추가
- **일관성 보장**: 항상 동일한 방식으로 상태 업데이트 수행

## add_messages 리듀서 동작 확인

### 리듀서의 핵심 기능

`add_messages` 리듀서는 메시지 상태 관리의 핵심입니다. 이 리듀서는 다음과 같은 기능을 제공합니다:

- **메시지 추가**: 기존 메시지 리스트에 새 메시지를 추가
- **순서 보장**: 메시지들의 시간 순서 유지
- **타입 안전성**: 모든 메시지 타입을 안전하게 처리
- **메타데이터 보존**: 메시지 ID, 이름 등 메타데이터 유지

### 리듀서 테스트

```python
from langchain_core.messages import AIMessage, HumanMessage

# 초기 메시지들
initial_messages = [
    AIMessage(content="안녕하세요! 어떻게 도와드릴까요?", name="Model"),
    HumanMessage(content="해양 생물학에 대한 정보를 찾고 있습니다.", name="Lance")
]

# 새 메시지 추가
new_message = AIMessage(content="물론 도와드릴 수 있습니다. 구체적으로 무엇에 관심이 있으신가요?", name="Model")

# add_messages 리듀서 테스트
result = add_messages(initial_messages, new_message)
print("리듀서 결과:")
for msg in result:
    if hasattr(msg, 'content'):
        print(f"- {type(msg).__name__}: {msg.content}")
    else:
        print(f"- {type(msg).__name__}: {msg}")
```

**실행 결과**:
```
리듀서 결과:
- AIMessage: 안녕하세요! 어떻게 도와드릴까요?
- HumanMessage: 해양 생물학에 대한 정보를 찾고 있습니다.
- AIMessage: 물론 도와드릴 수 있습니다. 구체적으로 무엇에 관심이 있으신가요?
```

### 리듀서 동작 원리

```python
# add_messages 리듀서의 내부 동작 (단순화된 버전)
def add_messages(left: list, right: list) -> list:
    """메시지 리스트를 안전하게 결합"""
    if not left:
        left = []
    if not right:
        right = []
    return left + right  # 리스트 연결
```

**핵심 특징**:
- **None 안전성**: None 값이 전달되어도 안전하게 처리
- **순서 보장**: 왼쪽 리스트 + 오른쪽 리스트 순서로 결합
- **불변성**: 원본 리스트를 변경하지 않고 새 리스트 반환
- **타입 호환성**: 다양한 메시지 타입을 안전하게 처리

## MessagesState를 사용한 그래프 구축

### 환경 설정

리듀서를 사용한 메시지 상태 관리 그래프를 구축해보겠습니다:

```python
# API 키 설정
import os
from dotenv import load_dotenv
load_dotenv()

# 필요한 라이브러리 임포트
from langchain_openai import ChatOpenAI
from IPython.display import Image, display
from langgraph.graph import StateGraph, START, END, MessagesState
from langchain_core.messages import HumanMessage
```

### 도구 정의

간단한 수학 연산 도구를 정의합니다:

```python
# 간단한 도구 정의
def add(a: int, b: int) -> int:
    """두 정수를 더하는 함수"""
    return a + b

# LLM과 도구 설정
llm = ChatOpenAI(model="gpt-4o")
llm_with_tools = llm.bind_tools([add])
```

### 노드 정의

메시지 상태를 처리하는 노드를 정의합니다:

```python
# 노드 정의: 도구 호출 가능한 LLM
def tool_calling_llm(state: MessagesState):
    """도구를 호출할 수 있는 LLM 노드"""
    return {"messages": [llm_with_tools.invoke(state["messages"])]}
```

**노드의 역할**:
- 입력된 메시지 상태를 받아서 LLM에 전달
- LLM이 도구 호출을 결정하면 ToolMessage 생성
- 결과를 메시지 상태로 반환
- **중요**: add_messages 리듀서로 인해 메시지가 누적됨

### 그래프 구성

```python
# 그래프 구성
builder = StateGraph(MessagesState)
builder.add_node("tool_calling_llm", tool_calling_llm)
builder.add_edge(START, "tool_calling_llm")
builder.add_edge("tool_calling_llm", END)
graph = builder.compile()

# 그래프 시각화
display(Image(graph.get_graph().draw_mermaid_png()))
```

**그래프 구조**:
- `START` → `tool_calling_llm` → `END`
- 단순한 선형 구조로 메시지 처리
- MessagesState의 add_messages 리듀서로 메시지 누적

## 그래프 테스트

### 일반 대화 테스트

도구 호출이 필요하지 않은 일반적인 대화를 테스트합니다:

```python
# 도구 호출 없는 일반 대화
result = graph.invoke({"messages": [HumanMessage(content="안녕하세요!")]})
for m in result['messages']:
    m.pretty_print()
```

**예상 결과**:
```
================================ Human Message =================================
안녕하세요!
================================== Ai Message ===================================
안녕하세요! 무엇을 도와드릴까요?
```

**리듀서의 효과**:
- HumanMessage와 AIMessage가 모두 메시지 상태에 누적
- add_messages 리듀서로 인해 대화 기록이 보존됨
- 메시지 순서가 시간 순서대로 유지됨

### 도구 호출 테스트

수학 연산이 필요한 경우 도구 호출을 테스트합니다:

```python
# 도구 호출이 필요한 수학 문제
result = graph.invoke({"messages": [HumanMessage(content="2와 3을 더해주세요")]})
for m in result['messages']:
    m.pretty_print()
```

**예상 결과**:
```
================================ Human Message =================================
2와 3을 더해주세요
================================== Ai Message ===================================
Tool Calls:
  add (call_abc123)
 Call ID: call_abc123
  Args:
    a: 2
    b: 3
```

**리듀서의 효과**:
- HumanMessage와 AIMessage가 모두 누적됨
- AIMessage에 tool_calls 정보가 포함됨
- 메시지 상태에 모든 대화 기록이 보존됨

### 리듀서 vs 덮어쓰기 비교

```python
# 리듀서 사용 시 (현재 구현)
print("리듀서 사용 시 메시지 수:", len(result['messages']))
print("메시지 타입들:", [type(msg).__name__ for msg in result['messages']])

# 만약 덮어쓰기였다면:
# - HumanMessage만 남고 AIMessage는 사라짐
# - 대화 기록이 보존되지 않음
# - 메시지 수가 1개만 됨
```

### 실제 비교 테스트

```python
# 덮어쓰기 방식 테스트
class OverwriteState(TypedDict):
    messages: list[str]

def overwrite_node(state: OverwriteState):
    return {"messages": ["새로운 메시지"]}

# 리듀서 방식 테스트
class ReducerState(TypedDict):
    messages: Annotated[list[str], add_messages]

def reducer_node(state: ReducerState):
    return {"messages": ["새로운 메시지"]}

# 비교 결과:
# 덮어쓰기: {"messages": ["새로운 메시지"]}  # 기존 메시지 사라짐
# 리듀서: {"messages": ["기존 메시지", "새로운 메시지"]}  # 기존 메시지 보존
```

**리듀서의 장점 확인**:
- **대화 맥락 유지**: 모든 메시지가 순서대로 보존
- **타입 구분**: HumanMessage, AIMessage 등 명확한 구분
- **메타데이터**: 각 메시지의 ID, 이름 등 풍부한 정보
- **확장성**: 새로운 메시지 타입 쉽게 추가 가능
- **일관성**: 예측 가능한 상태 업데이트 동작

## 핵심 학습 포인트

### 1. 리듀서의 중요성
- **상태 업데이트 제어**: 덮어쓰기 vs 추가 방식의 차이점과 장단점 이해
- **메시지 관리**: add_messages 리듀서를 통한 대화 기록 관리
- **표준화**: LangGraph에서 제공하는 표준 리듀서 활용
- **타입 안전성**: Annotated 타입을 통한 안전한 리듀서 지정

### 2. add_messages 리듀서의 특징
- **메시지 추가**: 기존 메시지 리스트에 새 메시지를 추가
- **순서 보장**: 메시지들의 시간 순서 유지
- **None 안전성**: 예외 상황에서도 안전하게 동작
- **메타데이터 보존**: 메시지 ID, 이름 등 풍부한 정보 유지

### 3. MessagesState의 장점
- **대화 맥락 유지**: 이전 대화 내용을 기억하여 연속적인 상호작용 지원
- **역할 구분**: HumanMessage, AIMessage, SystemMessage, ToolMessage로 명확한 역할 구분
- **확장성**: 다양한 메시지 유형과 도구 호출 결과 처리
- **표준화**: LangGraph에서 제공하는 표준 메시지 관리 방식

### 4. 내장 MessagesState 활용
- **간편성**: 커스텀 정의 없이 바로 사용 가능
- **표준화**: 일관된 메시지 관리 방식
- **확장성**: 필요시 추가 키로 확장 가능
- **최적화**: LangGraph에서 최적화된 성능 제공

### 5. 리듀서 vs 덮어쓰기 비교
- **덮어쓰기**: 이전 값이 완전히 사라짐, 대화 기록 보존 불가
- **리듀서**: 이전 값과 새 값을 결합, 대화 기록 완전 보존
- **메모리 효율성**: 리듀서는 메모리를 더 사용하지만 대화 맥락 유지
- **복잡성**: 리듀서는 약간 복잡하지만 더 강력한 기능 제공

[[TIP]]
**리듀서 사용 팁**
리듀서는 상태 업데이트 방식을 제어하는 핵심 메커니즘입니다. 메시지 기반 상태에서는 add_messages 리듀서를 사용하여 대화 기록을 효과적으로 관리할 수 있습니다. 특히 대화형 AI 에이전트에서는 리듀서 없이는 대화 맥락을 유지할 수 없습니다.
[[/TIP]]

[[TIP("실무 팁")]]
**리듀서 활용 베스트 프랙티스**
- 내장 MessagesState와 add_messages 리듀서를 우선적으로 사용하세요
- 메시지에 적절한 name 속성을 설정하여 역할을 명확히 하세요
- 도구 호출 결과는 ToolMessage로 처리하세요
- 대화 맥락이 길어지면 메시지 필터링을 고려하세요
- Annotated 타입을 사용하여 리듀서를 명확히 지정하세요
[[/TIP]]
