한동안 우리의 에이전트는 혼자서 세상을 이해하려 애썼습니다.
하지만 세상은 생각보다 복잡합니다.
하나의 에이전트가 모든 일을 혼자 해결하려고 하면, 곧 이렇게 중얼거리게 됩니다.

> “저… 일정도 정리해야 하고, 이메일도 요약해야 하고, 계산도 해야 하는데요…”

이때 등장하는 것이 바로 멀티에이전트(Multi-agent) 시스템입니다. <br>
이 장에서는 그중에서도 Tool Calling 패턴,  <br>
즉 **감독(agent supervisor)** 이 여러 **전문가(sub-agent)** 를 불러 협업하는 방식을 다룹니다.

## 🌱 혼자서 모든 일을 하는 건 힘들어요

LangChain v1에서는 한 에이전트가 너무 많은 도구를 갖거나 너무 큰 컨텍스트를 추적하려 하면,
성능이 급격히 떨어질 수 있습니다. <br>
이 문제를 해결하는 가장 직관적인 방법이 바로 **“전문가를 부르는 것”**입니다.

* **컨트롤러 에이전트(controller)** : 전체 흐름을 관리하는 감독
* **툴 에이전트(tool agent)** : 특정 업무에 특화된 하위 에이전트

컨트롤러는 상황을 파악하고, “이건 수학 전문가에게 맡기자!” 혹은
“이건 검색 담당이 처리해야겠군.” 하며 적절한 하위 에이전트를 호출합니다.

## 🧩 Tool Calling 구조 이해하기

Tool Calling은 다음과 같은 순서로 진행됩니다:

1. 사용자가 입력을 보냅니다. <br>
2.	컨트롤러 에이전트가 문제를 이해하고, “어떤 하위 에이전트가 적합할까?”를 결정합니다. <br>
3.	해당 서브에이전트를 도구처럼 호출합니다. <br>
4.	서브에이전트는 자신의 일을 수행한 뒤 결과를 컨트롤러에게 반환합니다. <br>
5.	컨트롤러는 결과를 종합해 사용자에게 최종 답변을 제공합니다.

![](https://wikidocs.net/images/page/299152/fig1_mkemH0u.png)

> 💡 **Tip**: <br>
> Tool agent는 사용자와 직접 대화하지 않습니다. <br>
> 그들은 “묵묵히 일만 하는 조용한 전문가”로, 컨트롤러의 요청에만 반응합니다. <br>
> 만약 사용자가 직접 각 전문가와 대화하도록 만들고 싶다면 Handoff 패턴을 사용해야 합니다.

## ⚙️ 구현: 아기 에이전트에게 친구를 소개하기

LangChain v1에서는 `create_agent()`를 사용하면 간단히
“에이전트 안에 또 다른 에이전트”를 넣을 수 있습니다.

```python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain_openai import ChatOpenAI

# 1️⃣ 수학 전문가 에이전트 (Sub-agent)
math_agent = create_agent(
    model=ChatOpenAI(model="gpt-4o-mini"),
    tools=[],
)

@tool("math_solver", description="수학 문제를 해결하는 친구")
def call_math_agent(query: str):
    result = math_agent.invoke({
        "messages": [{"role": "user", "content": query}]
    })
    return result["messages"][-1].content

# 2️⃣ 감독 에이전트 (Controller)
supervisor = create_agent(
    model=ChatOpenAI(model="gpt-4o"),
    tools=[call_math_agent]
)

response = supervisor.invoke({
    "messages": [{"role": "user", "content": "25 * 4는 얼마야?"}]
})

print(response["messages"][-1].content)
```

이 코드에서 감독(supervisor)은 수학 관련 질문이 들어오면
`math_solver`라는 툴(즉, 수학 에이전트)을 호출합니다.
이렇게 하면 에이전트가 점점 “협업하는 존재”로 성장하기 시작하죠.

## 🧠 Context Engineering: 친구에게 정보를 어떻게 전달할까

멀티에이전트 설계의 핵심은 **컨텍스트 엔지니어링(context engineering)** 입니다. <br>
즉, 각 친구(에이전트)에게 “어떤 정보까지 보여줄지”를 정하는 일입니다.

LangChain v1에서는 에이전트 간 입력/출력을 세밀하게 제어할 수 있습니다.

| 제어 포인트 | 설명 |
|------|------|
| 이름 (name) | 메인 에이전트가 부를 때 사용하는 별명입니다. 이름 자체가 프롬프트에 포함되므로 의미가 중요합니다. |
| 설명 (description) | 어떤 일을 하는 친구인지 설명합니다. 감독이 “언제 부를지” 결정할 때 이 설명을 참고합니다. |
| 입력 (input) | 어떤 데이터를 서브에이전트에게 넘길지 결정합니다. |
| 출력 (output) | 서브에이전트의 결과를 어떻게 해석하고 활용할지 결정합니다. |

## 🧩 입력과 출력 다듬기

예를 들어, 감독이 단순히 질의 텍스트만 넘기는 대신
“이전 대화 기록”이나 “현재 상태 정보”까지 함께 전달하고 싶을 수 있습니다.

```python
from langchain.agents import AgentState
from langchain.tools import tool, ToolRuntime

class CustomState(AgentState):
    context: str

@tool("math_solver", description="수학 문제를 푸는 친구")
def call_math_agent(query: str, runtime: ToolRuntime[None, CustomState]):
    # 대화 내역을 포함한 입력 구성
    full_input = f"이전 문맥: {runtime.state.context}\n현재 질문: {query}"
    result = math_agent.invoke({"messages": [{"role": "user", "content": full_input}]})
    return result["messages"][-1].content
```

이런 방식으로, 아기 에이전트는 각 친구에게 필요한 만큼의 정보를 전달할 수 있습니다. <br>
즉, “필요 이상은 말하지 않되, 필요한 건 빠짐없이 전달”하는 기술이죠.

## 🧩 출력 커스터마이징

서브에이전트가 반환하는 결과를 가공해,
감독이 이해하기 쉬운 형태로 변환할 수도 있습니다.

```python
from typing import Annotated
from langgraph.types import Command
from langchain.tools import InjectedToolCallId

@tool("math_solver", description="수학 계산 결과를 반환하는 친구")
def call_math_agent(
    query: str,
    tool_call_id: Annotated[str, InjectedToolCallId],
) -> Command:
    result = math_agent.invoke({
        "messages": [{"role": "user", "content": query}]
    })
    # 결과를 상태와 함께 병합해 전달
    return Command(update={
        "messages": [
            {
                "content": result["messages"][-1].content,
                "tool_call_id": tool_call_id
            }
        ]
    })
```

이런 식으로 `Command(update=...)`를 사용하면
단순 텍스트 이상의 데이터를 함께 전달할 수 있습니다. <br>
예를 들어, “이 답변은 어떤 서브에이전트가 한 것인지”를 추적할 수도 있습니다.

## ✨ 핵심 정리

| 항목 | 설명 |
|------|------|
| **Tool Calling** | 컨트롤러가 하위 에이전트를 도구로 호출하는 구조 |
|**Sub-agent** | 특정 작업(검색, 계산 등)에 특화된 독립 에이전트 |
| **Context Engineering** | 어떤 정보를 서브에이전트에게 전달할지 결정하는 기술 |
| **입출력 제어** | 입력은 ToolRuntime, 출력은 Command(update=...)로 제어 |
| **장점** | 확장성↑, 유지보수성↑, 에이전트의 역할 분리가 명확 |

✅ 이제 아기 에이전트는 더 이상 혼자가 아닙니다. <br>
검색 담당, 수학 담당, 메일 담당 친구들과 함께 일할 수 있게 되었죠. <br>
이 장에서 배운 Tool Calling 구조는 바로 **협업의 첫걸음**입니다. <br>
다음 장에서는 각 친구가 **자신만의 작은 세상(서브그래프)** 을 갖게 되는 과정을 다뤄보겠습니다.
