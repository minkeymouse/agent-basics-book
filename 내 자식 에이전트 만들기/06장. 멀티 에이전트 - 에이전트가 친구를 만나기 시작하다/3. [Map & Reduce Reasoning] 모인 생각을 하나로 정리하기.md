지난 장에서 우리 에이전트는 “팀을 꾸려서 역할을 분담”하는 법을 배웠습니다. <br>
이제 각 팀원이 자기 의견을 내기 시작하죠. <br>
그런데 문제는…

> “모두 말이 맞는 것 같긴 한데, 누구 의견으로 결론을 내리지?”

이럴 때 필요한 게 바로 **Map & Reduce Reasoning**,
즉 “모인 생각(Map)”을 “하나로 정리(Reduce)”하는 사고 방식입니다.

## 🧭 Map & Reduce란?

이 개념은 원래 데이터 처리(MapReduce)에서 온 것이지만,
에이전트 시스템에도 그대로 적용할 수 있습니다.

| 단계 | 설명 | 역할 |
|------|------|------|
| **Map 단계** | 여러 에이전트가 같은 문제를 각자 관점에서 사고 | 분산된 사고(Parallel Reasoning) |
| **Reduce 단계** | 그 결과를 하나의 결론으로 통합 | 집단적 판단(Consensus Building) |

LangGraph v1에서는 이를 `Fan-out` → `Fan-in` 패턴으로 구현할 수 있습니다.
즉, 여러 노드(에이전트)가 동시에 사고(Map)하고,
결과가 모이면 최종 통합 노드가 이를 정리(Reduce)합니다.

## 🌱 실습 시나리오: 회의에서 결론 내리기

**상황**을 생각해봅시다.
우리 Supervisor 에이전트가 세 명의 팀원에게 질문을 던집니다.

> “AI 모델의 성능을 올리는 가장 효과적인 방법은 뭐라고 생각해?”

세 팀원은 각각의 관점에서 답합니다:

* **모델 연구 담당**: 더 큰 모델로!
* **데이터 담당**: 양질의 데이터 확보!
* **시스템 담당**: 효율적인 파이프라인 구축!

Supervisor는 이들을 모두 듣고 “결론”을 내려야 합니다.

## ⚙️ Map 단계: 여러 에이전트의 의견 모으기

```python
from typing import Annotated, TypedDict
from operator import add
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 상태 정의
class TeamState(TypedDict):
    question: str
    opinions: Annotated[list[str], add]
    summary: str
```

각 팀원이 자신의 역할에 맞게 답변합니다.

```python
def model_team(state: TeamState):
    return {"opinions": [f"모델 크기를 키우는 것이 가장 큰 효과를 냅니다."]}

def data_team(state: TeamState):
    return {"opinions": [f"데이터 품질을 높이고 레이블을 정제해야 합니다."]}

def system_team(state: TeamState):
    return {"opinions": [f"효율적인 MLOps 파이프라인 구축이 중요합니다."]}
```

## 🧩 Reduce 단계: 의견 통합하기

이제 모든 의견이 모였을 때 LLM이 이를 요약하게 합니다.

```python
def reduce_opinions(state: TeamState):
    joined = "\n".join(state["opinions"])
    result = llm.invoke([{
        "role": "user",
        "content": f"다음 팀원들의 의견을 하나로 요약해줘:\n{joined}"
    }])
    return {"summary": result.content}
```

## 🧠 그래프 구성

이제 Fan-out(Fork)과 Fan-in(Join)을 설정해줍니다. 5장에서 살펴본 리듀서와 결합하면, 여러 노드에서 동시에 같은 상태 키를 갱신해도 `Annotated[..., add]` 규칙에 따라 안전하게 병합되기 때문에, 병렬 처리와 상태 일관성을 함께 확보할 수 있습니다.

```python
builder = StateGraph(TeamState)

builder.add_node("model_team", model_team)
builder.add_node("data_team", data_team)
builder.add_node("system_team", system_team)
builder.add_node("reduce_opinions", reduce_opinions)

# Fan-out: 세 팀이 병렬로 실행됨
builder.add_edge(START, "model_team")
builder.add_edge(START, "data_team")
builder.add_edge(START, "system_team")

# Fan-in: 모두 완료된 후 reduce 실행
builder.add_edge(["model_team", "data_team", "system_team"], "reduce_opinions")
builder.add_edge("reduce_opinions", END)

graph = builder.compile()
```

## ▶️ 실행 예시

```python
result = graph.invoke({
    "question": "AI 모델 성능을 올리는 방법은?",
    "opinions": [],
    "summary": ""
})

print("요약 결과:\n", result["summary"])
```

**출력 예시:**
```
요약 결과:
모델 크기 확장, 데이터 품질 개선, 그리고 효율적인 MLOps 구축이 모두 중요하며,
세 요소가 균형을 이루어야 최적의 성능 향상이 가능하다.
```

## 🔍 핵심 원리

| 개념 | 설명 | LangGraph에서의 구현 |
|------|------|------|
| Map (분산 사고) | 여러 에이전트가 동시에 사고함 | 여러 노드를 START로 연결 |
| Reduce (통합 사고) | 모든 결과를 모아 결론 생성 | 하나의 노드로 Fan-in |
| Reducer (Annotated[list, add]) | 중복된 상태 필드 병합 | 자동 통합 (add 연산) |
| 동기화 (Barrier) | 모든 병렬 노드가 끝날 때까지 대기 | add_edge([...], node) 구문 |

## 🧩 실전 확장: Map & Reduce + LLM Reasoning

이 패턴은 단순 요약뿐 아니라
**복수 모델의 Reasoning 결과 통합**,
**Multi-view 분석**,
**에이전트 협의 시스템**에도 활용할 수 있습니다. LangGraph Studio의 스트리밍 뷰나 `updates` 스트림을 켜 두고 실행해 보면, 각 팀 노드의 결과가 어떤 순서로 `opinions`에 쌓이고, 언제 `reduce_opinions` 노드가 실행되는지 한눈에 볼 수 있어, 병렬 실행·동기화 타이밍을 이해하는 데 큰 도움이 됩니다.

예를 들어, 같은 질문을 여러 모델에게 던지고
결과를 LLM으로 재요약하는 것도 이 구조와 동일합니다.

```python
def model_a_reasoning(state: TeamState):
    return {"opinions": [f"GPT-4: {llm.invoke('Use transfer learning.').content}"]}

def model_b_reasoning(state: TeamState):
    return {"opinions": [f"Claude: {llm.invoke('Add more pretraining data.').content}"]}
```

## ⚖️ Map & Reduce 패턴의 장점

| 항목 | 설명 |
|------|------|
| 집단지성 구현 | 여러 에이전트의 다양한 관점 반영 |
| 자동 병렬화 | Fan-out 구조로 시간 절약 |
| 의견 통합 자동화 | Reducer가 모든 결과를 하나로 합침 |
| 확장성 | 팀원 수를 자유롭게 늘릴 수 있음 |
| LLM Reasoning 최적화 | 복수 Reasoner → 단일 정리자의 구조 |

이제 우리 에이전트 팀은 단순히 “역할을 나누는 수준”을 넘어
**“의견을 모으고 합의점을 찾는 조직”**으로 성장했습니다. <br>
각자의 생각(Map)이 모여, 하나의 결론(Reduce)이 됩니다.
