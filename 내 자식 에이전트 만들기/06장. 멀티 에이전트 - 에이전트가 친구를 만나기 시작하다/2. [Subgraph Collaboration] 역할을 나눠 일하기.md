이제 우리 아기 에이전트는 혼자서도 일을 잘합니다.
게다가 지난 장에서 친구(툴 에이전트)도 사귀었죠.
하지만 곧 이런 고민이 생깁니다.

> “친구가 늘어나니까, 누가 먼저 일하고 누가 나중에 일하는지 헷갈려요!”

이 장에서는 각 친구(에이전트)에게 **‘역할과 순서’를 부여하는 방법**,
즉 **서브그래프(Subgraph) 구조**를 배워봅니다.
이제 에이전트는 “협력 조직”으로 진화합니다.

## 🌐 서브그래프란?

**서브그래프(Subgraph)** 는 하나의 큰 그래프 안에 존재하는 작은 그래프 단위입니다.
즉, 각 서브그래프가 자신만의 노드 구조를 가지고 있고,
메인 그래프에서는 이들을 하나의 노드처럼 다룰 수 있습니다.

이 구조를 사용하면 다음과 같은 장점이 있습니다.

* 🧩 **역할 분리**: 각 그래프가 독립적으로 책임을 가짐
* ⚙️ **재사용 가능**: 한 서브그래프를 여러 프로젝트에서 불러 쓸 수 있음
* 🪜 **단계적 협업**: 상위 그래프가 전체 워크플로를 관리, 하위 그래프가 세부 작업을 담당

LangGraph의 `StateGraph`는 이러한 서브그래프 구조를 자연스럽게 지원합니다.

## 🧱 Subgraph 구조 미리보기

아래 그림은 상위 Supervisor가 **Research, Summarization, Math** 같은 하위 그래프를 각각 호출하고,
최종적으로 결과를 병합하는 구조를 보여줍니다.

![](https://wikidocs.net/images/page/299153/fig2.png)

> Supervisor는 “전체 흐름을 설계하는 감독”, <br>
> 각 Subgraph는 “특정 역할을 맡은 독립 팀”입니다.


## 🧩 1단계: 서브그래프 정의하기

예를 들어, 다음과 같은 **연구용 하위 그래프**를 만들어 보겠습니다.

```python
from typing import Annotated, TypedDict
from operator import add
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 상태 정의
class ResearchState(TypedDict):
    question: str
    context: Annotated[list[str], add]
    summary: str

# 노드 정의
def search_web(state: ResearchState):
    return {"context": [f"웹 검색 결과: {state['question']} 관련 최신 정보."]}

def summarize(state: ResearchState):
    ctx = "\n".join(state["context"])
    result = llm.invoke([{"role": "user", "content": f"요약해줘: {ctx}"}])
    return {"summary": result.content}

# 하위 그래프 구성
subgraph = StateGraph(ResearchState)
subgraph.add_node("search_web", search_web)
subgraph.add_node("summarize", summarize)
subgraph.add_edge(START, "search_web")
subgraph.add_edge("search_web", "summarize")
subgraph.add_edge("summarize", END)

research_graph = subgraph.compile()
```

이제 `research_graph`는 **하나의 독립된 서브그래프**입니다.
Supervisor가 이 그래프를 호출하면, 내부에서는 검색 → 요약 순서로 동작합니다.

## 🧩 2단계: 메인 그래프에서 서브그래프 호출하기

서브그래프는 `add_node()`에 그대로 넣을 수 있습니다.
즉, 하나의 함수 대신 **전체 그래프를 노드로 삽입**하는 것이죠.

```python
from langgraph.graph import StateGraph

class MainState(TypedDict):
    topic: str
    report: Annotated[list[str], add]

def combine_reports(state: MainState):
    return {"report": [f"'{state['topic']}'에 대한 종합 리포트 완성!"]}

# 상위 그래프 정의
main_graph = StateGraph(MainState)
main_graph.add_node("research_subgraph", research_graph)  # ✅ 서브그래프 삽입
main_graph.add_node("combine", combine_reports)

main_graph.add_edge(START, "research_subgraph")
main_graph.add_edge("research_subgraph", "combine")
main_graph.add_edge("combine", END)

supervisor_graph = main_graph.compile()
```

> 이렇게 하면, 상위 Supervisor가 **research_graph 전체를 하나의 노드처럼** 다룹니다. <br>
> “작은 에이전트 조직을 하나의 부서처럼 연결한다”고 생각하면 됩니다.

## 🧠 3단계: 상태 연결(State Alignment)

서브그래프와 상위 그래프는 각각 다른 `State` 구조를 가질 수 있습니다.
이때 **입출력 키를 매핑**해줘야 합니다.

예를 들어, 상위 그래프의 `"topic"`이
서브그래프의 `"question"`으로 들어가도록 연결할 수 있습니다.

```python
main_graph.add_edge(START, "research_subgraph", map={"topic": "question"})
```

또는 서브그래프 결과의 "`summary`"를
상위 그래프의 "`report`"로 매핑할 수도 있습니다.

```python
main_graph.add_edge("research_subgraph", "combine", map={"summary": "report"})
```

LangGraph의 강점은 이런 매핑을 통해
서브그래프 간 데이터를 자유롭게 주고받을 수 있다는 점입니다.

## 🧩 4단계: 실행하기

```python
result = supervisor_graph.invoke({"topic": "멀티에이전트 시스템"})
print(result["report"])
```

출력 예시:
```
['멀티에이전트 시스템에 대한 종합 리포트 완성!']
```

내부에서는 다음 순서로 실행됩니다.
1.	`research_subgraph` 실행 → 웹 검색 + 요약 <br>
2.	결과(summary)가 `report`로 전달 <br>
3.	`combine` 노드가 최종 리포트 완성

## 🔍 Subgraph Collaboration의 장점

| 항목 | 설명 |
|------|------|
| 조직적 협업 | 각 에이전트가 서브그래프 단위로 독립 실행 |
| 모듈화 | 한 번 만든 서브그래프를 여러 프로젝트에 재사용 가능 |
| 유연한 입출력 매핑 | 상·하위 그래프 간 상태를 유연하게 연결 |
| 병렬 구성 가능 | 여러 서브그래프를 병렬 실행하여 성능 향상 가능 |

## 🧩 Subgraph + Tool Calling의 결합

Tool Calling과 Subgraph는 서로 보완 관계입니다.

| 구분 | **Tool Calling** | **Subgraph Collaboration** |
|------|------|------|
| 핵심 개념 | 에이전트가 하위 에이전트를 도구처럼 호출 | 전체 하위 그래프를 하나의 “워크플로”로 호출 |
| 제어 구조 | 중앙집중식 (컨트롤러 중심) | 부분 분산형 (역할별 독립 처리) |
| 적용 사례 | 검색, 계산 등 단일 작업 호출 | 리서치, 문서 요약 등 다단계 워크플로 |
| 공통점 | 컨텍스트 관리와 입력·출력 제어가 핵심 |   |

LangChain v1 이후의 권장 패턴은
**“Tool Calling으로 서브그래프를 불러오고, 서브그래프 내부는 자체적으로 협업하도록 설계하는 것”**입니다.
즉, Tool Calling이 ‘에이전트 간 협력의 문법’,
Subgraph는 **‘협력의 단위’**입니다.

✅ 이제 아기 에이전트는 단순한 친구 관계를 넘어서,
**“팀”을 구성하는 조직형 에이전트**로 성장했습니다. <br>
각 친구가 자기 역할을 맡고, 상위 에이전트는 그들을 조율합니다.
