외부 세계와 연결된 아기 에이전트는 궁금한 것들이 많아요. 아기들이 뭐든지 입에 넣으려고 할 때 부모로서 제지하는 것 처럼, 우리도 에이전트와 다양한 상호작용을 하며 제어할 수 있습니다!

### 🧠 왜 상호작용이 중요할까요?

AI 에이전트는 간혹 우리의 의도와 다르게 행동할 때가 있습니다. 말도 없이 파일을 지워버리거나, 쓸데없는 파일을 너무 많이 만들어 버리면 큰일이겠죠! 앞서 배운 **상태와 메모리의 이력을 추적하고 에이전트의 행동을 적절하게 제어하며, 결과값을 의도에 맞게 강제**함으로써 우리는 안전하고 효율적인 시스템을 만들 수 있습니다.

## 학습목표

이번 장의 학습 내용은 크게 다섯가지 입니다.  
2장에서 “툴·메모리·체크포인트”로 외부 세계와 연결하는 법을 배웠다면, 3장에서는 이 위에 **스트리밍·미들웨어·HITL**를 얹어 “에이전트의 머릿속을 들여다보고, 필요할 때 개입하는 법”을 다룹니다. 이렇게 쌓은 개념은 4장 자료조사 에이전트 실습에서 한 번에 연결됩니다.

* **스트리밍(streaming)**: 에이전트의 상태와 이력을 실시간으로 출력하고 추적할 수 있습니다.
* **미들웨어(middleware)**: 에이전트의 행동을 제어할 수 있습니다.
* **결과값 강제**: 스키마(schema)에 맞추어 결과값을 생성하도록 합니다.
* **런타임(runtime)**: 에이전트의 실행과 관련된 실시간 정보에 엑세스 할 수 있습니다.
* **컨텍스트 엔지니어링**: 효율적이고 정확한 실행을 위해 컨텍스트를 제어합니다.

## 실습 환경 설정

이번 장에서는 실습을 위해 *아기 에이전트*를 정의해 보겠습니다. *아기 에이전트*는 '기쁨', '배고픔', '응가', '졸림'의 네가지 기분 중 하나가 랜덤으로 주어집니다. 사용자에게 의성어로만 대답해야 하며, '울음', '응가', '맘마'의 세가지 중 하나의 행동을 취할 수 있습니다. 실습을 위해 필요한 모듈 및 환경변수를 불러오기 위한 코드는 다음과 같습니다.

```python
import os
import random
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langchain.agents import create_agent
from langgraph.store.memory import InMemoryStore
from dotenv import load_dotenv, find_dotenv
from pydantic import BaseModel, Field
from typing import Literal, Optional

load_dotenv(find_dotenv())
```

이제 앞서 배운 내용을 바탕으로 도구를 정의해 보겠습니다. 코드상으로는 상태를 먼저 정의해야 하지만, 이해를 돕기 위해 도구를 먼저 살펴보겠습니다.

```python
@tool("cry", description="아기처럼 웁니다. 디렉토리에 cry.txt 파일에 기록을 추가합니다.", args_schema=CryInput)
def cry(cry_count: Optional[int] = None) -> str:
    n = cry_count if isinstance(cry_count, int) and cry_count > 0 else random.randint(1, 10)
    with open("cry.txt", "a") as f:
        f.write("응애" * n + "\n")
    return "울음 성공적으로 생성!"

@tool("poo", description="응가를 봅니다. 디렉토리에 poo.txt 파일에 기록을 추가합니다.", args_schema=PooInput)
def poo(poo_shape: Literal["큰응가", "작은응가"] = "큰응가", poo_count: Optional[int] = None) -> str:
    c = poo_count if isinstance(poo_count, int) and poo_count > 0 else random.randint(1, 10)
    writer = get_stream_writer()
    writer("응가를 봅니다. 디렉토리에 poo.txt 파일에 기록을 추가합니다.")
    with open("poo.txt", "a") as f:
        f.write(poo_shape * c + "\n")
    writer("응가 성공적으로 생성!")
    return f"{poo_shape} {c}개 응가 성공적으로 생성!"

@tool("eat", description="맘마를 먹습니다. 디렉토리에 있는 food.txt 파일을 읽고 내용을 지웁니다. 없으면 배고픔 상태를 기록합니다.")
def eat() -> str:
    if os.path.exists("food.txt"):
        with open("food.txt", "r+") as f:
            content = f.read()
            f.seek(0)
            f.truncate()
            if content == "":
                return f"맘마 없어"
            return f"맘마를 먹었어요."
    else:
        return f"맘마 없어"
```

정의된 도구는 총 세가지로, `cry`를 호출할 시, 현재 디렉토리에 `cry.txt` 파일을 생성하고 에이전트가 지정한 횟수만큼 "응애"를 추가로 적어 놓습니다. `poo` 도구도 비슷하게 작동하며, 에이전트가 지정한 응가의 종류를 생성한 `poo.txt`파일에 추가로 적어 놓습니다. `eat`도구의 경우 디렉토리에 있는 `food.txt`파일을 읽고, 내용을 지운 뒤, "맘마를 먹었어요"를 적어 놓습니다. 만약 파일이 없거나, 파일에 아무것도 적혀있지 않다면 "맘마 없어"를 출력합니다.

이제 도구를 정의했으니, 도구에 들어가는 인풋을 정의하겠습니다. `pydantic`을 활용하여 다음과 같이 정의할 수 있습니다.

```python
class CryInput(BaseModel):
    how_many_times: Optional[int] = Field(
        default=None, description="울음 횟수(없으면 랜덤)", ge=1, le=10
    )

class PooInput(BaseModel):
    poo_shape: Literal["큰응가", "작은응가"] = Field(
        default="큰응가", description="응가 형태"
    )
    poo_count: Optional[int] = Field(
        default=None, description="응가 개수(없으면 랜덤)", ge=1, le=10
    )
```

`CryInput`과 `PooInput` 스키마를 별도로 정의하여 에이전트 도구 호출 시 스키마 교차로 인해 발생하는 오류를 사전에 방지했습니다.

아기 에이전트가 활용할 수 있는 도구와 인풋 스키마를 정의했으니, 챕터를 학습하면서 본격적으로 아기 에이전트와 상호작용을 해보겠습니다!
